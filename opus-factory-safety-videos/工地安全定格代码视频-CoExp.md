# 《定格》代码视频复盘

> 项目：工地安全警示横屏短片《定格》（B 站 16:9）
> 成品：1920×1080 · 24fps · 87.0 秒 · 2088 帧 · 22 个镜头 · 定格动画节拍（on twos）
> 技术栈：TypeScript + Three.js r186 + Vite 8，Playwright 无头 Chromium 逐帧截取，ffmpeg 6.1 合成
> 运行环境：云端容器，2 核 CPU，7GB 内存，**没有 GPU**（WebGL 走 SwiftShader 软件渲染）
> 本文只写这次真实发生的事：用了哪些参数、踩了哪些坑、最后怎么解决的。

---

## 一、创作思路

### 1. 需求如何拆成叙事结构

**第一步：先做调研，只挑一个点往深里挖。** 需求里有“工地安全警示”，但没说讲哪个风险。我先查了数据：住建部《关于 2020 年房屋市政工程生产安全事故情况的通报》里，689 起事故有 407 起是高处坠落，占 **59.07%**。于是整片只讲高处坠落这一件事，不做“十条安全规定”那种清单。

**第二步：找一个能把“为什么会出事”讲透的模型。** 我选了瑞士奶酪模型（Reason）：每一层防护都有漏洞，事故发生在几个漏洞恰好对齐的那一刻。落到剧情里就是三个“省事”：

| 洞 | 剧情里的动作 | 类别 |
|---|---|---|
| ① | 小李拆掉一段临边护栏，想着“一会儿再装” | 环境 |
| ② | 老周嫌勒，不系安全帽下颏带 | 个人防护 |
| ③ | 老周往后退时觉得挂绳碍事，解开安全带挂钩，“省 3 秒” | 行为 |

**第三步：让片名、手法和主题是同一个词。** “定格”既是定格动画，也是把事故停在最后一帧的剪辑手法。结构定为：

**倒叙钩子 → 建置 → 三个洞依次打开 → 定格 → 分析 → 倒带 → 三个洞依次关上 → 同样的意外，不同的结局 → 收尾**

**情绪/节奏曲线和镜头时间的对应**（时间码按最终时间线）：

| 时间 | 段落 | 镜头 | 情绪 | 镜头长度的规律 |
|---|---|---|---|---|
| 0–7s | 钩子 + 片名 | S01–S02 | 悬念、压迫 | 4s 环绕定格帧 + 3s 片名 |
| 7–24s | 建置 | S03–S06 | 平稳、日常 | 3–6s，给观众时间认识空间 |
| 24–35.5s | 事故链 | S07–S10 | 逐步紧张 | 3 → 3 → 3.5 → 2s，越来越短 |
| 35.5–38s | 高潮 | S11 | 冲击后突然静止 | 1.4s 慢动作坠落，36.9s 定格 |
| 38–50s | 分析 | S12–S13 | 冷静、读图 | 放慢到 7s、5s，让观众看清 MG |
| 50–54s | 转折 | S14 | “重来” | 1.3s 停住，接 2.7s 倒带 |
| 54–75s | 正确做法 | S15–S20 | 释然 | 回到 3–5s 的平稳节奏 |
| 75–87s | 收尾 | S21–S22 | 回到全局 | 7s 拉远 + 5s 结尾卡 |

### 2. 每个段落的设计意图

- **开场 S01（4s）**：一上来就给结果。老周正向后翻出楼边，安全帽飞在半空，画面完全静止，相机绕着这一帧转 40°（bullet time）。前 0.5s 从黑场淡入，字幕“如果时间能定格在这一帧——”。B 站观众前 3 秒决定划不划走，所以把最有冲击力的画面放在第一帧，但静止、不血腥。
- **片名 S02（3s）**：警示黄黑条纹从两侧“拍”进来，“定格”两个字逐字落下，“格”字用警示黄。这张卡片就是全片 MG 视觉系统的第一次亮相。
- **建置 S03–S04**：航拍从 (66,46,74) 推到 (34,28.5,38)，交代楼、塔吊、6F 作业面三者的位置关系。S04 用人物卡定格介绍老周：“钢筋工 · 干了 22 年”。“老手”这个设定就是伏笔：熟练导致随意。
- **三个洞 S05–S08**：每个洞用一个镜头、一个带编号的标注圈（①②③）打开。S07（吊物降下来）不讲洞，负责给出动机：他为什么要往楼边退。
- **高潮 S09–S11**：S09 全景交代他正退向缺口，S10 特写脚踩钢筋头打滑（on ones 慢动作），S11 回到楼外机位，坠出后定格。S11 的机位与 S01 相同，闭合开场的悬念。
- **分析 S12–S13**：定格画面去色，只保留红色（keepRed 0.75），叠三个标注圈和瑞士奶酪示意图，再接全屏数据卡 59.07%。
- **转折 S14**：先停在定格帧上打字幕“现实没有暂停键。”，然后整段戏在 on ones 下倒放 2.7 秒，护栏自己回到原位。倒带是这个结构里最自然的转场，因为定格动画本来就是一张一张的照片。
- **正确做法 S15–S20**：机位与前面一一对应（S05↔S15、S06↔S16、S08↔S17、S09↔S18、S11↔S19），观众一眼就能对照出区别。调色略偏暖（warmth 0.035，饱和度 1.1）。S19 是同样的一滑，这次背撞上护栏、挂绳绷直。
- **收尾 S21–S22**：从老周身边升起拉到航拍，打字幕“定格，只存在于视频里。/ 现实里，没有倒带。”，最后是可以截图带走的结尾卡：下颏带系紧 · 安全带高挂 · 临边不拆除。

### 3. 用到的剪辑和音画技巧，以及为什么有效

- **Murch 六法则**，优先级是 情绪 51% > 故事 23% > 节奏 10% > 视线 7% > 轴线 5% > 空间 4%。定格那一刻所有声音同帧切断，这就是“情绪优先”。
- **轴线统一**：6F 上的所有机位都放在东侧，老周后退的方向在画面上始终朝左。这样安排还有一个原因：上午的太阳在东南（方位 128°），东侧机位是顺光，人脸不会背光发黑。
- **匹配剪辑**：S01 与 S11 是同一帧；S08 解扣与 S17 检查挂钩是同机位同景别。
- **动作剪辑（cut on action）**：S09 在脚落地时切到 S10；S16 在下颏带“咔”那一帧切走。
- **J-cut / L-cut**：S07 的塔吊哨声写成 `{ t: -0.5, id: 'whistle' }`，比画面早 0.5 秒进来；S11 定格后的心跳一直延续进 S12 的分析段。
- **重叠时间覆盖（coverage）**：同一段连续表演用不同机位重复拍，镜头之间允许时间有重叠（例如 S10 取 11.15–11.75s，S11 从 11.6s 开始）。剪辑点因此自然连贯。
- **快动作用 on ones**：全片默认每秒 12 张（on twos），滑倒、坠出、撞栏杆这些冲击动作改成每秒 24 张，否则会显得跳帧。
- **音乐只放在建置和收尾**，事故段不用音乐；重来段落的“咔”（下颏带）和挂绳拉紧的“嗒”是全片最清晰的两个音效。

## 二、具体的创作方式

### 1. 技术栈与完整工作流

| 环节 | 工具 / 版本 | 备注 |
|---|---|---|
| 调研 | WebSearch / WebFetch | 标准原文、事故数据、剪辑理论；每个出现在字幕里的数字都要能追溯 |
| 语言 / 构建 | TypeScript 7.0、Vite 8.3、vite-plugin-singlefile | `tsc --noEmit` 只做类型检查 |
| 3D | three 0.186 | 附加模块：Sky、GTAOPass、BokehPass、UnrealBloomPass、FXAAPass、OutputPass、RoundedBoxGeometry、BufferGeometryUtils、OrbitControls |
| 贴图 | Canvas2D 程序化生成 | 不依赖任何外部图片，渲染结果完全可复现 |
| 声音 | Web Audio `OfflineAudioContext` | 在浏览器页面里合成后导出 WAV |
| 逐帧渲染 | Playwright 1.56 + 预装的 Chromium | 启动参数：`--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist` |
| 合成 | ffmpeg 6.1.1 | libx264 + AAC |
| 交付沙盒 | 单文件 HTML，发布为 Artifact | 约 780KB |

**完整步骤**

1. 调研 → 写 `docs/DIRECTOR.md`（调研依据、文稿、导演阐述、分镜表、速度与防穿模规范）
2. `world/layout.ts` 定下所有尺寸 → 搭建场景 → 看效果截图（look-dev）
3. 木偶骨架与姿势库 → 两条连续表演（Take）：事故版 `bad` 和正确版 `good`
4. 把分镜表转成 `shots.ts` 数据 → 时间线负责量化、boil 和 MG
5. `render.mjs --stills` 每个镜头出一张审片图 → 修 → `--check` 做穿模检查 → 修
6. 性能剖析 → 优化
7. 全片渲染：帧序列 + WAV → ffmpeg 输出 MP4 → 再压一版用于分享

### 2. 项目结构与关键代码

```
src/core        math.ts（种子随机、缓动、关键帧采样、可平铺噪声）· engine.ts（渲染器与后期链）
src/materials   textures.ts（程序化 PBR 贴图）· library.ts（材质库，uvScale = 每张贴图对应多少米）
src/world       layout.ts（所有尺寸的唯一来源）· geo.ts（静态几何按材质合批）
                building / crane / props / city / sky / site
src/characters  rig.ts（木偶骨架 + PPE）· poses.ts（姿势库 + 步态）· actor.ts（表演 + 安全绳）
src/film        stage.ts（Take）· shots.ts（22 个镜头）· timeline.ts（Film）· mg.ts（MG 图层）
src/audio       sfx.ts（音效库）· score.ts（配乐、混音、WAV 导出）
src/app         main.ts（三种模式）· ui.ts（右侧浮动 dock）
scripts         render.mjs（渲染/审片/检查/音频）· shot.mjs · profile.mjs
```

**核心设计：场地 / 表演 / 镜头 三层分离。** Take 是一段连续的表演；镜头本身不做任何动画，只选“看哪一段 Take 时间”和“机位”。

```ts
// shots.ts —— 一个镜头就是一段数据
{ id: 'S11', dur: 2.5, take: 'bad',
  tk: [k(0, 11.6), k(1.4, T_FREEZE, 'linear')],     // 镜头内时间 → Take 时间；之后保持 = 定格
  step: t => (t < 1.4 ? 1 : 2),                      // 坠落用 on ones，定格后回到 on twos
  cam: still(CAM_EDGE_OUT.p, CAM_EDGE_OUT.q, 30),
  dof: { focus: [k(0, 5.0)], aperture: 0.0012 },
  grade: t => ({ keepRed: t > 1.4 ? 0.55 : 0, flash: t > 1.4 && t < 1.5 ? 0.6 : 0 }),
  mg: (g, t) => M.freezeUI(g, t, 1.4, '09:41:52:07'),
  sfx: [{ t: 1.4, id: 'freeze' }, { t: 1.45, id: 'heart' }], amb: 0 }
```

**定格量化（timeline.ts）**

```ts
frameKey(frame) {
  const { index, shot, lt } = this.locate(frame);
  const step = this.stepOf(shot, lt);
  const lq = Math.floor(Math.round(lt * FPS) / step) * step / FPS;   // 同一 key 的帧画面必然相同
  return { shot: index, lq, key: `${index}:${lq.toFixed(4)}` };
}
// boil 只在“木偶真的动过”的帧上加：Take 时间变了才抖；定格帧和环绕机位不抖
const moving = Math.abs(T - Tprev) > 1e-5;
stage.apply(take, T, seed, moving ? 0.35 : 0);
sun.intensity = base * (moving ? 1 + (hash2(seed, 7) - 0.5) * 0.03 : 1);
```

**静态几何合批（geo.ts）**：所有静态零件（钢管、钢筋、面板）都转到世界空间，按“主轴投影”写世界坐标 UV，再用 `mergeGeometries` 按材质合并。最后场景只有 **122 个 mesh、约 22 万三角面**，真 GPU 上可以跑到 60fps。

```ts
b.tube('railRW', [x, y, z], [x, y + 1.25, z], 0.024, 6, 'railPost');   // 最后一个参数 = 同时登记为碰撞体
```

**地面吸附（actor.ts）**：每帧先摆姿势，再算脚底最低点，把整个人抬高或压低到楼面标高，脚永远不会陷进楼板或悬空。

```ts
P.applyRot(rot); if (snap > 0.5) P.footFlat();
P.root.updateMatrixWorld(true);
P.root.position.y += (floorY - P.soleMinY()) * snap;
```

**步态**：相位按“走过的距离 ÷ 一个步态周期的长度”计算（正走 1.3m/周期，后退 0.9m/周期），所以脚不会在地上滑。

**接触求解（stage.ts）**：S19 老周背靠护栏的倾角不是手调的，而是二分搜索算出来的：

```ts
let lo = 0, hi = -40 * DEG;
for (let i = 0; i < 24; i++) {
  const mid = (lo + hi) / 2;
  if (test(mid) < railZ - 0.029) lo = mid; else hi = mid;   // 背部采样点刚好碰到上杆
}
```

**摆放位置也用求解代替手摆**：绊倒他的钢筋头，位置取的是事故版里 T=11.38s 时他右脚跟的世界坐标；滚动距离再限制在挡脚板以内。

### 3. 各种视觉风格怎么用代码实现

| 效果 | 实现方式 |
|---|---|
| 写实材质 | Canvas 逐像素生成颜色、高度、粗糙度，再用 Sobel 算子从高度图算法线贴图。混凝土有气孔和模板缝，覆膜板有磨损和钉眼，泥地有碎石和车辙，钢筋是锈色 |
| 日光 | Preetham Sky（浊度 5.5，rayleigh 1.35），太阳高度 38°、方位 128°；DirectionalLight 强度 3.4；HemisphereLight 1.05；FogExp2 0.0019 |
| 阴影 | 每个镜头指定阴影焦点中心和半径（特写 4–6m，楼面 12–14m，航拍 60–65m），小半径时阴影更清晰 |
| 定格质感 | on twos 量化 + 关节 ±0.35° boil + 主光 ±1.5% 闪烁 + 不加运动模糊 + Bokeh 浅景深 |
| 调色 | 自写 GradeShader：饱和度、对比度、色温、keepRed（HSV 取红色掩码，其余去色）、暗角、按帧变化的颗粒、闪白、淡黑 |
| 后期顺序 | RenderPass（HalfFloat）→ GTAO → Bloom（阈值 3.0，强度 0.12）→ Bokeh → OutputPass（ACES，曝光 0.92）→ FXAA → Grade |
| MG | Canvas2D 1920×1080 叠在 3D 上面。安全色 5 个：黄 #FFC400 / 红 #E53935 / 绿 #2EAD5B / 墨 #111418 / 纸白 #F4F1EA；字体 Noto Sans CJK；入场用 easeOutBack，退场用 easeInCubic |
| 跟着镜头走的标注 | 用 `Vector3.project(camera)` 把关节或构件的世界坐标投影到屏幕，标注圈始终钉在对应部位 |
| 木偶 | 19 个关节，Lathe 胶囊做肢体，RoundedBox 做躯干；脸是画在球面 UV 上的贴图，加几何眼球和能眨的眼皮；安全帽用物理材质加清漆；五点式安全带带背部 D 形环；安全绳用每帧重建的 TubeGeometry（松时下垂，紧时拉直） |

### 4. 音频处理

- 全部是程序合成，放在 `sfx.ts` 里。每个音效是一个函数 `(ctx, out, t, gain)`，实时的 AudioContext 和离线的 OfflineAudioContext 都能用。例如：金属管敲击 = 比例 1 / 2.76 / 5.4 / 8.93 的非谐波正弦叠加加一小段噪声；心跳 = 62→38Hz 的“lub-dub”两下；倒带 = 锯齿波加变速 LFO；安全帽卡扣 = 两个 0.5ms 的高频噪声脉冲。
- **卡点是结构性的**：音效时间写在每个镜头里（相对镜头起点），渲染时加上镜头起始时间换算成绝对时间。镜头改长改短，声音自动跟着走，不需要手动对齐。
- **环境声**：棕噪声低通 220Hz 模拟车流，带通 700Hz 加 0.13Hz LFO 模拟风，再加随机的远处敲击。每个镜头有一个 `amb` 电平，用 `setTargetAtTime(lvl, t, 0.15)` 平滑过渡；`amb: 0` 时用 `setValueAtTime(0, t)` 同帧硬切，定格那一刻就是这样静下来的。
- **配乐**：92 BPM。A 主题 Am-F-C-G（克制），B 主题 C-G-Am-F（明亮）；每个主题由锯齿波 pad、三角波低音、方波琶音和软底鼓组成。连续标了同一主题的镜头合成一段，淡入 0.6s、淡出 0.8s。
- **总线**：DynamicsCompressor（阈值 -14，比例 3）→ 增益 0.95。
- **导出**：页面里 48kHz 双声道渲染 → 转成 16bit WAV 字节 → 每 32KB 一块转 base64（避免 `String.fromCharCode(...arr)` 参数过多导致栈溢出）→ Node 端写入 `audio.wav`。

### 5. 渲染与导出命令

```bash
# 逐帧：Playwright 调用 window.__film.renderFrame(i)，返回 JPEG（质量 0.94）的 dataURL
node scripts/render.mjs            # on twos 的重复帧直接 fs.linkSync 硬链接，不重复渲染

# 合成母版（这次实际使用的参数）
ffmpeg -y -framerate 24 -i out/frames/%05d.jpg -i out/audio.wav \
  -c:v libx264 -preset slow -crf 17 -pix_fmt yuv420p -profile:v high -movflags +faststart \
  -c:a aac -b:a 256k -shortest out/dingge_1080p.mp4          # 87s → 256MB

# 分享版：crf 22 → 81MB（约 7.4Mbps），B 站上传体积合适
ffmpeg -i dingge_1080p.mp4 -c:v libx264 -preset slow -crf 22 -pix_fmt yuv420p \
  -movflags +faststart -c:a aac -b:a 192k 定格_工地安全警示_1080p.mp4
```

- 分辨率 1920×1080，帧率 24，时长用 `ffprobe -show_entries format=duration` 确认为 87.000000。
- 母版体积大，主要是因为每帧的颗粒都不一样，x264 很难压缩。分享版直接调高 CRF；如果还要更小，可以把颗粒强度从 0.035 降到 0.02。

### 6. 时间分配与提速

| 环节 | 大约耗时 | 说明 |
|---|---|---|
| 调研 + 导演稿 | 约 10% | 值得花，避免把过时标准写进字幕 |
| 场景搭建（建筑、塔吊、城市、贴图） | 约 25% | |
| 木偶 + 两条 Take | 约 20% | |
| 镜头数据 + MG + 声音 | 约 15% | |
| 看效果、剖析性能、修 bug | 约 20% | 性能剖析走了弯路（见第三部分坑 5） |
| 全片渲染 | 墙钟约 2.5–3 小时 | 约 1000 张独立画面 × 平均 9.2 秒；ffmpeg slow 编码约 6 分钟 |

**最耗时的是软件渲染。** 提速办法：

- 有 GPU 就用 GPU（同样的场景可以实时跑）。
- 用 on twos 和 3D 画面复用减少独立帧数。
- 降低像素级开销：半分辨率只要约 1/4 的时间，说明瓶颈在片元着色。
- 天空烘焙成 CubeMap；IBL 只给金属和清漆材质。
- 审片用单帧 `--stills`，不要反复渲整片。

## 三、注意事项与踩过的坑

### 1. 检查清单

**开工前**

- [ ] 确认有没有 GPU：用 `WEBGL_debug_renderer_info` 查渲染器名，出现 “SwiftShader” 就说明是软件渲染，要按每帧 5–15 秒来估工期
- [ ] 确认 TTS 能不能用；不能用就提前把片子设计成“字幕 + MG”承担全部信息
- [ ] 用 `fc-list :lang=zh` 确认容器里有中文字体（这次有 Noto Sans CJK）
- [ ] 确认 ffmpeg、Playwright 的版本和已装的 Chromium 版本匹配（1.56 ↔ chromium-1194），不要重新下载浏览器
- [ ] 字幕里出现的每个数字、每条标准都查到原文，并留意新标准有没有替代旧说法
- [ ] 先定总时长和镜头数，导演稿和代码只认同一份数据

**制作中**

- [ ] 所有尺寸只写在 `layout.ts` 一个地方
- [ ] 所有随机都用种子（`mulberry32` / `hash2`），不要用 `Math.random`
- [ ] 每改一轮就 `--stills` 出审片图，拼成接触表（contact sheet）一次看完
- [ ] 每改一次表演就跑 `--check`，要求 0 处穿透
- [ ] 计时一定先做 GPU 同步（1 像素 `readPixels`）再读时间
- [ ] 标注类 MG 检查：会不会出画、会不会互相压住、会不会挡住主体

**导出前**

- [ ] 渲染用冻结的生产构建（`vite build` + `vite preview`），不要用开发服务器
- [ ] 渲染进程用 `setsid nohup … & disown` 完全脱离当前会话；支持断点续渲
- [ ] 渲染期间不要改源码
- [ ] 抽几个镜头边界的帧，确认 MG 是当前镜头的，不是上一个镜头残留的

**交付前**

- [ ] 用 ffprobe 确认时长、帧率、音轨都在
- [ ] 按平台准备分享版体积
- [ ] 导演稿里的时长和剧情描述与最终成片一致
- [ ] 源码打包时排除 node_modules 和 out

### 2. 踩过的坑

**坑 1：TTS 连不上，片子没有配音**
- 现象：edge-tts 先报证书错误，按代理说明指定 CA 后又返回 403。
- 根因：出口策略不允许访问这个服务。403 属于策略拒绝，不应该绕过。
- 解决：全片用字幕和 MG 承载信息；导演稿里的文稿可以直接拿去后期配音。
- 下次：开工第一步就测 TTS，别等剧本写完才发现。

**坑 2：画面发白、雾蒙蒙**
- 现象：第一张效果图整体泛白，像起了浓雾。
- 根因：UnrealBloom 阈值 0.92 是在 HDR 线性空间里判断的，阳光强度 3.4 下几乎所有表面都超过阈值，整张图都在泛光。
- 解决：把后期 pass 逐个关掉排查，定位到 Bloom 后改成阈值 3.0、强度 0.12。
- 下次：画面异常时先逐个 pass 关掉看；HDR 管线里的 Bloom 阈值要比 1 大。

**坑 3：没有影子，画面发平**
- 现象：卡车下面、塔吊身后都看不到阴影。
- 根因：用 Preetham 天空做的 PMREM 环境光非常亮（强度 0.55），把阴影区域全部填亮了。
- 解决：先降到 0.16；后来改成只有金属和清漆材质挂 envMap（强度 0.35），其余材质用 HemisphereLight 1.05 补光。
- 下次：临时关掉环境光看一次纯日光效果，确认阴影本身是正常的。

**坑 4：钢筋网严重摩尔纹**
- 现象：6F 楼面的钢筋网在中远景出现一圈圈波纹。
- 根因：Ø10 钢筋在画面里不到 1 像素宽，几何体产生混叠。
- 解决：整层楼面换成“覆膜板 + 钢筋网”的程序化贴图（有 mipmap，远处自然变成平均色）；真实钢筋几何只保留在事故区域，而且只有相机距离小于 36m 时才显示。
- 下次：细密的重复结构，默认用“贴图 + 近处 LOD 几何”的组合。

**坑 5：性能剖析被假数据误导，走了弯路**
- 现象：探针测出 39ms/帧，实际渲一帧要 15–30 秒。之后又出现一次 0.3 秒/帧的数字，一度以为瓶颈在阴影。
- 根因：`gl.finish()` 在 SwiftShader 下并不会阻塞等待，真正的开销被推迟到了截图时。0.3 秒那次是因为阴影贴图还没创建，渲染路径本身就不一样。
- 解决：每次计时前后都用 1 像素 `readPixels` 强制同步。最后查清楚是片元着色瓶颈（半分辨率快约 4 倍，关掉环境光快约 40%）。优化措施：天空和云烘焙进 1024 的 CubeMap 当背景；IBL 只给反光材质；GTAO 采样 16→10；阴影贴图 4096→2048；泥地、道路等纯接收面关掉投射阴影。最终从约 20 秒/帧降到约 9 秒/帧。
- 下次：先写一个带同步的剖析脚本，按“关一项测一次”逐项量化，再动手优化。

**坑 6：MG 串到后面的镜头里（最隐蔽的一个）**
- 现象：S19 和 S20 本来没有 MG，审片图上却出现了 S15、S17 的字幕和尺寸标注，而且已经按当前机位投影好了。
- 根因：SwiftShader 下 GPU 加速的 2D Canvas 被 `drawImage` 读取时，拿到的是旧快照，延迟了两次渲染。用 `getImageData` 检查时反而正常，因为它会强制刷新。
- 解决：叠加层和合成用的画布都用 `getContext('2d', { willReadFrequently: true })` 创建，强制走 CPU；合成画布复用同一个，每次先清空。
- 下次：离线渲染里凡是要被读回的 Canvas 一律加 `willReadFrequently`；审片时专门按“有 MG 的镜头 → 没 MG 的镜头”这个顺序连续渲几帧来验证。

**坑 7：渲染到一半崩了：“Execution context was destroyed”**
- 现象：全片渲到第 66 帧左右报错退出。
- 根因：渲染时我顺手改了 main.ts 并执行了打包，Vite 开发服务器检测到变化后整页刷新，渲染上下文被销毁。
- 解决：`render.mjs` 改成先 `build()` 到 `out/render-build`，再用 `preview()` 起服务，渲染的是一份冻结的构建。
- 下次：离线渲染永远不要依赖开发服务器。

**坑 8：后台渲染进程悄悄死掉**
- 现象：会话恢复后日志不再更新，帧数一直停在 66。
- 根因：nohup 启动的子进程随原会话一起被回收。
- 解决：改用 `setsid nohup node scripts/render.mjs >> out/render.log 2>&1 < /dev/null & disown`；脚本本身会跳过已存在的帧，重复帧用硬链接补齐，所以可以断点续渲。
- 下次：长任务一开始就完全脱离会话，并定期看日志里的“已渲染数”有没有增长。

**坑 9：穿模**
- 现象：`--check` 报 12 帧小李左手插进柱筋笼；修完后又报 2 帧老周脚跟碰到挡脚板（1cm）。
- 根因：小李沿着 z≈6.2 往西走，左手在楼边一侧，正好擦过位于 (3, 6.75) 的柱筋笼。老周正确版滑倒时脚跟滑到了 z 6.83–6.84，挡脚板在 6.888。
- 解决：给小李的路径加一个 (3.7, 5.8) 的途经点，让他绕开柱子；正确版滑倒终点从 z 6.6 改到 6.57，护栏接触角由求解器重新算。钢筋头滚动距离限制为 `min(0.16, 挡脚板z - 0.035 - 起点z)`。最终 0 帧穿透。
- 下次：碰撞体在建模时就登记（`b.tube(..., 'railPost')`），角色身上放 14–16 个采样点，每改一次表演就跑一遍检查。

**坑 10：头发盖住眼睛、安全帽太低**
- 现象：人物像蒙了一条黑布，看不到脸；正面看安全帽帽檐压住眼睛。
- 根因：头发用了 `SphereGeometry` 的 theta 分段，结果是一整圈环带，正好在眼睛高度；安全帽位置太低。另外球体默认 UV 的正面在 u=0.25，脸部贴图需要先 `rotateY(-π/2)` 才会朝前。
- 解决：头发改成 phi 取 1.08π 起、跨 0.84π（只覆盖后脑），theta 取 0–0.64π，前额另加一个小发际帽；安全帽位置 y 0.17→0.19，缩放 0.93。
- 下次：角色做完先在正面、侧面、背面各出一张特写检查。

**坑 11：写法取巧导致零件没加上**
- 现象：肩部三角肌和下巴没有显示出来。
- 根因：写了 `chest.add(place(mesh).scale.set(...).parent as never || new Object3D())` 这种一行链式写法。`scale.set` 返回的是 Vector3，于是真正被 add 进去的是一个空的 Object3D。
- 解决：改回老老实实的多行写法。
- 下次：不要为了少写几行用 `as never` 硬压类型检查。

**坑 12：坠落姿势看不懂**
- 现象：第一版定格帧里，人几乎是横躺在楼面上，看不出是“掉出楼外”。
- 根因：倾角只有 -58°，身体大部分还在楼面上方；机位偏高，背景是楼面。
- 解决：倾角改为 -74°，坠落时根节点向外漂移 +0.26m、抬升 0.12m；楼外机位从 y 16.55 降到 15.75，让人物的剪影衬在天空和城市前。
- 下次：高潮帧必须在最终机位下单独审，不要只在调试机位看。

**坑 13：MG 排版冲突**
- 现象：S12 的标签出了画面左侧，还压住了奶酪图面板；S15 顶部的字幕压住了“立杆间距”标注。
- 解决：`callout()` 增加 `labelY` 参数，可以直接指定标签的纵向位置，并缩短引线；奶酪面板从 X=1180 移到 1300、宽度 640→560；`caption()` 增加右上角位置 `'tr'`。
- 下次：MG 布局要在真实机位的审片图上逐镜检查，并在标注较多的镜头里预留安全区。

**坑 14：交付物和导演稿对不上**
- 现象：导演稿写“约 95 秒”，成片实际 87 秒；文稿写“安全带挂在身后柱筋上”，实现里是挂在头顶生命线上。
- 根因：写代码时改了设计，没有回写到文档。
- 解决：交付前把文档逐项核对一遍并改正。
- 下次：时长、镜头表以 `shots.ts` 为准，用脚本自动生成文档里的对应表格。

**坑 15：连续渲染的页面截不了图**
- 现象：沙盒模式下 `locator.screenshot` 一直报 “waiting for element to be stable”，直到超时。
- 根因：软件渲染下 requestAnimationFrame 循环让画面一直在变化，元素永远达不到“稳定”状态。
- 解决：用低画质参数 `q=low`，等待几秒后改用 `page.screenshot`。

**坑 16：Artifact 页面的格式要求**
- 现象：vite-plugin-singlefile 输出的是完整 HTML，而 Artifact 发布时会自动套一层外壳，不能自带 doctype、head、body。
- 解决：用 Python 正则取出 `<style>` 和 module `<script>`，重新拼成“title + style + 舞台 div + script”，并把脚本里的 `</script` 转义成 `<\/script`。

**坑 17：成片体积过大**
- 现象：crf 17 的母版 87 秒就有 256MB。
- 根因：每帧颗粒都不同，压缩效率很低。
- 解决：分享版用 crf 22，得到 81MB。

**坑 18（没修好，照实记录）：路牌上的 emoji**
- 现象风险：施工大门的“必须戴安全帽”标牌里写了 ⛑ 字符，而 Noto Sans CJK 不包含这个 emoji，可能显示成方框。
- 原因：这个牌子在成片镜头里基本看不清，所以没有处理。
- 下次：Canvas 里只写字体确定包含的字符，图标用路径自己画（结尾卡的三个图标就是这样画的）。

**其他小问题**
- r186 已移除 `PCFSoftShadowMap`，控制台会给出警告并自动回退为 PCF。
- 噪声音源的起始偏移用了 `Math.random`，导致每次导出的音频不完全一致；下次改用种子随机。

## 四、可复用的模板

### 模板 A：代码视频制作流程

```
0. 环境探测（10 分钟）
   GPU / 字体 / TTS / ffmpeg / Playwright 版本；用 1 帧测出真实的秒/帧 → 算出渲染工期
1. 调研（一个核心点）
   数据 + 标准原文 + 叙事模型（如瑞士奶酪）；每个字幕数字都要能追溯
2. 导演稿 docs/DIRECTOR.md
   主旨一句话 → 文稿 → 导演阐述（结构 / 风格 / 色彩 / 声音 / 节奏 / 表演）
   → 分镜表（镜号 / 时长 / 景别机位 / 画面 / MG / 声音 / 帧步 / 剪辑点 / 存在理由）
3. 场地 world/
   layout.ts 定尺寸 → Builder 合批 → 程序化材质 → 天光
   → look-dev：一张航拍 + 一张作业面特写
4. 角色 characters/
   骨架 → 姿势库 → 步态（按距离驱动）→ 地面吸附 → 碰撞采样点
5. Take film/stage.ts
   连续表演（对照版各一条）→ 接触和摆放位置用求解器 → 背景人物循环
6. 镜头 film/shots.ts
   纯数据：tk 映射、step、机位、景深、调色、MG、音效、环境电平、音乐
7. 审片循环
   --stills 拼接触表 → 修 → --check 穿模为 0 → 核对镜头边界帧的 MG
8. 性能
   带 readPixels 同步的剖析，逐项开关 → 优化到可接受的秒/帧
9. 渲染
   vite build + preview → setsid nohup 断点续渲 → 渲染期间不改源码
10. 合成
   母版 crf 17 + 分享版 crf 22 → ffprobe 核对时长
11. 交付
   MP4 + 导演稿（与成片核对）+ 源码 tgz + 可交互沙盒（Artifact）
```

### 模板 B：给 AI 的开工提示词

```
你要用 TypeScript + Three.js 做一支【主题】的横屏短视频（1920×1080，24fps，目标时长【X】秒，平台【B站】）。

硬性要求：
1. 开工前先做环境探测：GPU 还是 SwiftShader、中文字体、TTS 是否可用、ffmpeg/Playwright 版本；
   实测 1 帧的真实耗时（计时前后必须用 1 像素 readPixels 同步），据此报渲染工期。
2. 先调研再写稿：只挖一个核心问题；字幕里的数字和标准都给出处，并确认没有被新标准替代。
3. 产出 docs/DIRECTOR.md：文稿、导演阐述、分镜表（含帧步、剪辑点、每镜存在理由），
   时长与镜头数只认 shots.ts 一个来源。
4. 架构三层分离：world（尺寸唯一来源 layout.ts，静态几何按材质合批）/
   Take（连续表演，接触用求解器）/ Shot（纯数据：tk 时间映射、step、机位、景深、调色、MG、音效）。
5. 定格规则：on twos 量化；boil 只在木偶真的动过的帧上加；冲击动作 on ones；不加运动模糊。
6. 防穿模：地面吸附 + 碰撞体登记 + 全片逐帧检查，交付要求 0 帧穿透。
7. 离线渲染：用 vite build + preview 的冻结构建；Canvas 一律 willReadFrequently:true；
   重复帧硬链接；setsid nohup 脱离会话并支持断点续渲；渲染期间不改源码。
8. 声音：音效时间写在镜头里（相对镜头起点）；环境声按镜头设电平，定格时同帧硬切；
   事故段不用音乐；OfflineAudioContext 导出 WAV，所有随机用种子。
9. 每一轮改动都出 --stills 接触表给我看；重点检查高潮帧、MG 遮挡、镜头边界的 MG 残留。
10. 导出：母版 crf 17 + 分享版 crf 22（或按平台体积要求调整），用 ffprobe 核对时长。
11. 交付：MP4、导演稿（与成片逐项核对）、源码包、可交互沙盒页面。

风格：【写实材质 + 定格木偶 / 其它】；视觉系统：【5 个颜色 + 1 套字体】；成本敏感程度：【高/中/低】。
```
