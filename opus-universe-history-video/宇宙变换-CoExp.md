# 代码定格卡点视频 · 方法、模板经验与踩坑复盘

> 对应成品：`code_cosmos_stopmotion.mp4`（68 秒 · 1920×1080 · 24fps · 28 个镜头 · 27 种代码风格 · 原创合成配乐）
> 对应源码：`code_cosmos_source.zip`（`web/` 场景与合成器 · `render.mjs` 逐帧渲染 · `music.py` 配乐）

---

## 0. 项目档案

| 项 | 数值 |
|---|---|
| 时长 | 68.0 s = 136 拍 |
| 速度 | 120 BPM（1 拍 = 0.5 s） |
| 独立画面帧率 | 12 fps（定格动画"一拍二"的质感） |
| 输出帧率 | 24 fps（每张画面重复 2 次，胶片颗粒每帧都变） |
| 每拍帧数 | **6 帧（整数，这是整套卡点的地基）** |
| 镜头 | 28 个；每个 4 拍（2 s）或 6 拍（3 s） |
| 渲染 | 816 张独立帧，平均约 425 ms/帧，约 6 分钟 |
| 技术栈 | Chromium 无头浏览器 + Canvas2D + Three.js r170 + GLSL；Playwright 逐帧截取；numpy/scipy 合成音乐；ffmpeg 合成 |
| 最终文件 | 26 MB（两遍编码，3 Mbps） |

## 1. 核心方法

### 1.1 总架构：一张分镜表驱动所有东西

```
                ┌──────────────── shots.js（唯一真相源）────────────────┐
                │ id · 拍数 · 维度 · 风格名 · 事件 · 宇宙时间 · 代码一行 │
                └───────┬───────────────────────────────┬───────────────┘
                        │                               │
          ┌─────────────▼─────────────┐     ┌───────────▼────────────┐
          │ engine.js  renderFrame(F) │     │ music.py  按同一张表    │
          │  帧号 → 镜头 → 局部时间     │     │ 生成切点音效/快门/段落  │
          │  → scene.draw(t)          │     └───────────┬────────────┘
          │  → 定格/抖动/冲击/HUD 合成  │                 │ music.wav
          └─────────────┬─────────────┘                 │
                        │ Playwright 逐帧 toDataURL      │
                        ▼                               │
                  f00000.jpg … f00815.jpg               │
                        └──────────────┬────────────────┘
                                       ▼
                     ffmpeg：12→24fps · 胶片颗粒 · H.264 + AAC
```

关键点：**画面和音乐从同一张分镜表推导**。音乐不是先做好再去对画面，也不是画面做好再配乐；两边都以"第几拍"为坐标，所以天然对齐，不需要事后手工卡点。

### 1.2 时间基准：三个数必须整除

```
BPM = 120  →  1 拍 = 0.5 s
FPS = 12   →  1 拍 = 6 帧（整数）
帧 F  →  全局拍 = F / 6  →  所在镜头 → 局部帧 lf = F − start×6
```

选 120 BPM + 12 fps 不是随手的：**每拍帧数必须是整数**，否则每个拍点会落在两帧之间，误差累积，几十秒后画面就"拖拍"。可用组合举例：

| BPM | 每拍秒数 | 12 fps | 24 fps | 30 fps |
|---|---|---|---|---|
| 120 | 0.5 | 6 ✅ | 12 ✅ | 15 ✅ |
| 128 | 0.46875 | 5.625 ❌ | 11.25 ❌ | 14.06 ❌ |
| 140 | 0.4286 | 5.14 ❌ | 10.29 ❌ | 12.86 ❌ |
| 150 | 0.4 | 4.8 ❌ | 9.6 ❌ | 12 ✅ |
| 90 | 0.667 | 8 ✅ | 16 ✅ | 20 ✅ |

想用 128/140 这类电音常见速度，就得接受非整数帧，把切点四舍五入到最近帧，同时让音乐的切点音效也对齐到同一个四舍五入后的时间。

### 1.3 分镜表（shots.js）

每个镜头一行，字段固定：

```js
{ id:'ide', b:6, dim:'2D', style:'IDE SYNTAX', zh:'编辑器语法高亮',
  ev:'太初核合成', t:'t = 3 min', code:'fuse(p, n) → D → He' }
```

- `b`：拍数，决定时长；`start` 由累加自动算出，**不手写起始时间**（手写一定会错位）。
- `dim / style / zh / ev / t / code`：全部被 HUD 直接读取，画面上的文字和分镜表永远一致。
- 改节奏只改 `b`，其余全部自动跟随（HUD 进度条、音乐切点、定格位置）。

### 1.4 场景接口：纯函数

```js
SCENES.ide = {
  init(env) { /* 一次性：建几何体、预计算数据 */ },
  draw(ctx, env) { /* 只依赖 env.t / env.p / env.f / env.beat 画一帧 */ }
}
env = { t: 局部秒, f: 局部帧, p: 0→1 进度, beat: 局部拍, live: 有效时长, GL, acc: 维度主题色 }
```

**`draw` 必须是时间的纯函数**：给同一个 t，永远画出同一张图。原因见第 4 节，这条是整套方法的根。

有"演化"的场景（元胞自动机、粒子聚集）怎么办？
- 元胞自动机：在 `init` 里把 64 步模拟一次跑完，给每个格子记下"被点亮的步数"，`draw` 只做 `当前步 ≥ 点亮步 ? 亮 : 暗`。
- 点云/体素聚集：存"初始位置 I"和"目标位置 T"，`draw` 里 `pos = lerp(I, T, ease(p))`。
- 粒子爆炸：每个粒子的方向、速度、出生时间都由固定种子随机数生成，位置 = f(t − 出生时间)。

### 1.5 合成器：每一帧的固定流程

```
renderFrame(F)
 ├─ 定位镜头 i、局部帧 lf
 ├─ 有效帧数 live = (b − 1) × 6        ← 最后一拍留给定格
 ├─ freeze = lf ≥ live
 ├─ 场景帧 sf = freeze ? live − 1 : lf  ← 定格时重画"最后一个有效瞬间"
 ├─ scene.draw → sceneCanvas
 ├─ 若 有效：
 │    抖动（±3.5px 平移、±0.17° 旋转，种子 = 帧号）
 │    拍点冲击：拍内第 0..5 帧缩放 +5% / 2.8% / 1.3% / 0.5% / 0 / 0
 │    镜头首帧：+8.5% 缩放 + 60% 白闪
 │    每拍首帧：12% 白闪
 │    曝光闪烁（0–7% 黑）→ 暗角 → HUD
 └─ 若 定格（最后一拍 6 帧）：
      背景 = 同一画面 模糊 + 压暗
      卡片 = 画面缩到 0.8、旋转 ±2.3°（奇偶镜头左右交替）、米白边框 + 投影
      白闪 85% → 35% → 10%
      第 1 帧起盖"风格印章"（回弹缩放 1.7 → 1）
      HUD 照常
```

这就是"**定格卡点**"的语法：前 N−1 拍画面在动、每拍一次冲击；最后一拍"咔嚓"一声定成照片，下一拍硬切到新镜头。观众会形成预期：**听到快门 = 这个风格结束，下一种要来了**。

### 1.6 三种渲染后端

| 后端 | 用在哪 | 要点 |
|---|---|---|
| **Canvas2D** | 所有 2D，以及线框类 3D/4D（超立方体、光锥） | 自写 `camera(yaw,pitch,dist,fov)` 投影函数，十几行就够；霓虹线 = 宽半透明 + 窄实线叠 3 次，不用 `shadowBlur`（软件渲染下很慢） |
| **Three.js** | 低多边形、点云、粒子、时空网格、体素、透视卡片 | 一个共享 `WebGLRenderer`（`preserveDrawingBuffer:true`），每个场景自建 Scene/Camera；渲染完 `drawImage` 回 2D 画布，统一走合成器 |
| **全屏着色器** | 光线步进奇点、等离子体、红巨星体积渲染 | Three.js 的 `ShaderMaterial` 铺一个 2×2 平面 + 正交相机；**半分辨率渲染再放大**（0.5 倍），软件 GL 下速度可接受，画面反而更柔 |

统一出口：所有后端最终都画到同一张 `sceneCanvas`，再由合成器加定格/抖动/HUD。这样风格再多，"外壳"也只有一套。

### 1.7 逐帧渲染（render.mjs）

- Node 起一个极简 HTTP 静态服务（ES Module 不能从 `file://` 加载）。
- Playwright 启动 Chromium：`--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist`（无 GPU 的服务器也能跑 WebGL2）。
- 等 `window.READY` 和 `document.fonts.ready`。
- 循环：`page.evaluate(f => { renderFrame(f); return canvas.toDataURL('image/jpeg', .93) })` → 写文件。
- 支持只渲染指定帧 `node render.mjs outDir 15,29,100-120`，用来抽样检查和局部返工。

### 1.8 配乐（music.py）

完全用 numpy 合成，没有采样包，没有版权问题：

| 乐器 | 做法 |
|---|---|
| 底鼓 | 正弦波，频率 150→45 Hz 指数下滑 + 起音噪声 + tanh 饱和 |
| 拍手/军鼓 | 带通白噪声 + 3 个 11 ms 间隔的小尖峰（拍手的"多人感"） |
| 踩镲 | 7 kHz 高通噪声，15 ms 衰减 |
| 贝斯 | 反拍 16 分音符锯齿波 + 正弦 sub，600 Hz 低通 |
| 和弦 | 5 条失谐锯齿（supersaw），低通截止频率按段落变化 |
| 琶音 | 16 分音符拨弦，左右声像交替，送混响 |
| 上升音效 | 白噪声过"截止频率 300→12000 Hz 指数上升"的一阶低通 + 上滑正弦 |
| 冲击 | 60→28 Hz 下滑的 sub + 低通噪声 |
| 快门 | 两个间隔 55 ms 的高通噪声脉冲 |
| 键盘声 | 12 ms 高通噪声，按终端打字的字符时间逐个放 |

编排规则全部从分镜表读：每个镜头起点前 0.12 s 放"嗖"声，每个定格拍放"快门 + 轻底鼓 + 高音 blip"；打字镜头按字符时间放键盘声；超新星镜头做 1/16 拍的音频重复（stutter）；热寂处做"磁带停转"（播放速度 1→0 的重采样）。

混音：旁链压缩（每个底鼓把音乐压低 75%，70 ms 恢复）→ 指数衰减噪声卷积混响 → 25 Hz 高通 → tanh 软限幅 → 归一化到 −0.6 dBFS。

### 1.9 合成导出（ffmpeg）

```bash
# 两遍编码，控制在 30 MB 以内
ffmpeg -framerate 12 -i f%05d.jpg -i music.wav \
  -vf "fps=24,noise=alls=2:allf=t,format=yuv420p" \
  -c:v libx264 -preset slow -b:v 3000k -maxrate 4500k -bufsize 9000k -pass 1 -an -f mp4 /dev/null
ffmpeg -framerate 12 -i f%05d.jpg -i music.wav \
  -vf "fps=24,noise=alls=2:allf=t,format=yuv420p" \
  -c:v libx264 -preset slow -b:v 3000k -maxrate 4500k -bufsize 9000k -pass 2 \
  -c:a aac -b:a 192k -shortest -movflags +faststart out.mp4
```

- `-framerate 12` + `fps=24`：12 张独立画面每张重复两次 → 画面有"一拍二"的定格感。
- `noise=...:allf=t`：颗粒按**输出帧**变化，画面停住时颗粒还在动，这正是真实定格动画（胶片）的样子。

## 2. 以这个视频为模板整理的经验

### 2.1 叙事 × 风格：让"风格本身"也在讲故事

最有效的匹配方式不是随机分配，而是**风格的视觉隐喻 = 这个阶段的物理本质**：

| # | 阶段 | 风格 | 为什么匹配 |
|---|---|---|---|
| 01 | 宇宙之前 | 终端打字机 | 程序还没运行，`time is not defined` |
| 02 | 量子涨落 | 十六进制内存 | 全是 00 的内存里偶尔蹦出非零字节 = 虚空不空 |
| 03 | 奇点 | 光线步进 SDF | 用"距离场"表示一个半径 → 0 的东西 |
| 04 | 大爆炸 | 动态文字 | 最需要"冲击力"的一刻交给最直接的文字 |
| 05 | 暴胀 | 四维超立方投影 | 0D→1D→2D→3D→4D 逐拍展开 = 空间本身被撑开 |
| 06 | 夸克-胶子等离子体 | 片元着色器 | 连续、翻滚、没有结构的"汤" |
| 07 | 强子形成 | 力导向图 | 节点被弹簧拉成三元组 = 胶子把夸克拴住 |
| 08 | 太初核合成 | 编辑器语法高亮 | `fuse(p, n)` 像写代码一样"合成"元素，旁边柱状图同步长出丰度 |
| 09 | 宇宙微波背景 | 像素画 | CMB 图本来就是一格一格的温度像素 |
| 10 | 黑暗时代 | 字符画 | 没有光，只有密度；字符的"浓淡"就是密度 |
| 11 | 第一代恒星 | 低多边形 | 灰色云团塌缩后突然点亮，棱角带出"原始感" |
| 12 | 再电离 | 元胞自动机 | 电离泡按邻居规则扩散，本身就是 CA |
| 13 | 宇宙网 | 点云 | 7 万个点从均匀分布聚成丝状骨架 |
| 14 | 星系诞生 | 粒子系统 | 较差自转把弥散的盘卷成旋臂 |
| 15 | 超大质量黑洞 | 时空曲率网格（4D） | 网格下陷 = 引力就是时空弯曲 |
| 16 | 超新星 | 故障艺术 | 爆炸 = 画面本身"坏掉"，碎片是元素符号 |
| 17 | 太阳系形成 | 多层视差（2.5D） | 尘埃盘、行星、岩石分层 = 有了"前后关系" |
| 18 | 地球 | 体素 | 一块块方块从下往上堆出地球 = 定格动画式的"搭建" |
| 19 | 生命 | 代码雨 | 字符只有 A/T/C/G，雨里凝出双螺旋 |
| 20 | 今天 | 透视卡片（2.5D） | 人类写的代码卡片环绕"你在这里" |
| 21 | 暗能量 | 数据可视化 | 真实 ΛCDM 公式画出的 a(t) 曲线 + 甜甜圈图 |
| 22 | 星系逃离视界 | 时空光锥（3+1） | 世界线越过视界圆柱变红 = 永远看不见 |
| 23 | 红巨星 | 体积渲染 | 蓬松的火球吞掉水星、金星 |
| 24 | 恒星时代终结 | 等距视角（2.5D） | 柱子高度 = 亮度，大质量先塌，红矮星最后熄灭 |
| 25 | 质子衰变 | 公式动画（Manim 风） | 这一段只存在于理论里，所以只用公式讲 |
| 26 | 黑洞蒸发 | 示波器 | 视界圆越缩越小、辐射越来越密，最后一闪 |
| 27 | 热寂 | 终端仪表盘（htop） | 所有进程 defunct，熵条满格，画面褪成均匀的灰 |
| 28 | 回到之前 | 终端（闭环） | `universe.exit(0)` → `clear` → `$ ▌`，与第一帧相同 |

经验：
- **首尾用同一种风格**（终端），闭环一眼就能看出来；最后一帧 = 第一帧，视频可以无缝循环播放。
- **最需要爆发的点用最朴素的风格**（大爆炸 = 纯大字），复杂技术放在"解释型"镜头里。
- **维度的分布要有节奏**：4D 放在暴胀（开头）、黑洞（中段）、视界（后段），而不是扎堆。
- 每个镜头里都放一行"生成它的代码"和一行"硬数据"（温度、步数、占比），观众觉得"这是真的在算"，而不是贴图。

### 2.2 统一骨架（每个镜头都一样的东西）

| 位置 | 内容 | 作用 |
|---|---|---|
| 左上 | `CODE × COSMOS` + `SHOT 07/28 · STYLE #07` | 进度感 |
| 右上 | `2D / 2.5D / 3D / 4D` 四个标签，当前维度填色 | 维度的记忆锚点 |
| 左下 | 事件（66px 粗体中文）+ 宇宙时间（主题色等宽） | 叙事主线 |
| 右下 | 风格英文名 + 中文名·维度 + 代码一行（描边小标签） | 风格清单本身 |
| 底部 | 28 段时间轴，按拍数等比，已过镜头上色，当前镜头加粗 | "走到宇宙哪儿了" |
| 定格拍 | 照片卡片 + 风格印章 | 卡点的"标点符号" |

每种维度一个主题色，全片只用这四个颜色做强调：2D `#00E5FF` · 2.5D `#FFD600` · 3D `#FF3D7F` · 4D `#B388FF`。高饱和、互相区分度大，在黑底上都清楚。

HUD 不跟着画面抖，画面抖、HUD 稳 → 前景信息始终可读，背景有手作感。

### 2.3 一个镜头内部的节拍语法

以 4 拍镜头为例（6 拍镜头就是中间多两拍"有效"）：

```
拍 1  ████ 硬切进入：+8.5% 冲击 + 60% 白闪 + 嗖声
拍 2  ███  内容推进，+5% 冲击
拍 3  ███  内容推进到高潮
拍 4  ▣    定格：白闪 → 照片卡片 → 印章 → 快门声
```

场景动画的时间设计要配合这个语法：**内容的"完成态"要在定格前一帧出现**（p = 1 的那一帧就是被拍成照片的那一帧）。比如超立方体在第 5 拍刚好展开成 4D，编辑器在最后一帧刚好把 `};` 打完。

### 2.4 音乐的能量曲线

实测的每半秒 RMS（×100）大致是：

```
0–8s   宇宙之前→奇点     15→35   安静 → 上升音效 + 军鼓连击加速
8s     大爆炸           67      全片最高点：冲击 + 大底鼓
8–22s  第一段律动        40–50
22–25s 黑暗时代         20      抽掉鼓，只剩铺底 → 上升音效
25–45s 第二段律动（加主旋律） 45–50
45–48s 你在这里          24–30   停一拍，只剩心跳底鼓
48–62s 第三段（和声转暗 Am-F-Dm-E） 45–52
62s    热寂             ↓7      磁带停转，只剩时钟滴答
65–68s 回到之前          10–17   键盘声 + 与开头相同的铺底
```

原则：**两次"掉下去"（黑暗时代、你在这里）是为了让下一次"起来"更有力**；结尾的音乐和开头用同一个铺底音色，循环播放时声音也能接上。

### 2.5 每种风格的实现要点速查

| 风格 | 关键技巧（一句话） |
|---|---|
| 终端打字机 | `slice(0, (t−t0)×26)` 控制打字；光标 `floor(f/3)%2` 闪；画扫描线 |
| 十六进制内存 | 每个格子用（行,列）做种子生成事件列表，概率随 p 增加 |
| 光线步进 | 球 SDF + 三重 sin 位移，累积 `0.012/(0.02+d²·6)` 做辉光；背景星空按撞击参数偏折 |
| 动态文字 | 三拍三个词，`back` 缓动 2.4→1 倍；第二拍黑白反色 |
| 超立方体 | 16 个顶点逐维乘缩放系数 s₀..s₃；XW 旋转角 × s_w，避免 4D 出现前就扭曲 |
| 着色器等离子 | 两层 domain warp fbm，调色板 紫→品红→橙→白 |
| 力导向图 | 位置 = lerp(噪声漫游, 簇中心+轨道, smooth((p−延迟)/0.4)) |
| 编辑器 | 预先分好词的代码行，按字符预算逐 token 显示 |
| 像素画 | 4×4 Bayer 矩阵阈值 < 进度才显示 = 抖动式出现 |
| 字符画 | **一行一次 fillText**，按亮度分三层字符串叠画（比逐字画快约 100 倍） |
| 低多边形 | Icosahedron(1.6, 1) 按顶点位置哈希做抖动，flatShading；点亮时自发光 + 尖刺 + 点光源 |
| 元胞自动机 | 初始化时模拟完，记录每格点亮步数 |
| 点云 | 在最近 3 邻居连成的"丝"上撒点 + 节点团 + 少量均匀噪声 |
| 粒子星系 | θ = 臂相位 + k·log(r) − t·ω(r)，扩散度随 p 收紧 |
| 时空网格 | CPU 每帧算 LineSegments 顶点 y = −M/√(r²+ε)；吸积盘按开普勒角速度转 |
| 故障艺术 | 复制到临时画布 → RGB 三通道分别 multiply 着色后错位叠加 → 随机水平条带位移 → 块状复制 |
| 多层视差 | 每层 `x −= cam × 深度`，深度标注在画面上 |
| 体素 | InstancedMesh；飞行中坐标取 0.5 的整数倍 = 一格格"跳"过去的定格感 |
| 代码雨 | 70 列，每列独立速度，头部白色；中间半透明黑底上画双螺旋 |
| 透视卡片 | CanvasTexture 做代码卡；中心大卡用 `back` 缓动弹出 |
| 数据可视化 | 用真实 ΛCDM 公式 a(t) = (Ωm/ΩΛ)^(1/3)·sinh^(2/3)(1.5√ΩΛ·H₀t) |
| 光锥 | 纯线条 + 自写投影；世界线越出视界圆柱就变红 |
| 体积渲染 | 球相交求区间，40 步累积密度与透射率 |
| 等距视角 | 按 x+y 排序画三面立方体（顶 100%、左 70%、右 45% 亮度） |
| 公式动画 | 矩形裁剪从左到右"写出"；`setLineDash([L, 9999])` 让框"画出来" |
| 示波器 | M ∝ (1−t)^(1/3)（霍金蒸发的真实标度）；3 个历史时刻半透明叠画 = 余辉 |
| 终端仪表盘 | 结尾所有颜色与灰色插值，最后盖一层灰 = 热寂的"均匀" |

### 2.6 性能数据

| 类型 | 大致耗时/帧（软件 GL，2 核） |
|---|---|
| 纯 2D 文字类 | 150–300 ms |
| Three.js 点/粒子（7–8 万点，CPU 更新坐标） | 400–600 ms |
| 全屏着色器（半分辨率） | 500–900 ms |
| `toDataURL('image/jpeg')` 1080p | 约 80 ms |

全片 816 帧约 6 分钟。**渲染时在后台跑，同时去写音乐**，两边并行。

### 2.7 用这个模板做新视频的流程

1. 定主题的"时间线"或"逻辑链"，拆成 20–30 个节点。
2. 给每个节点挑一个风格，检查"视觉隐喻是否等于内容本质"（2.1 的标准）。
3. 写 `shots.js`：只填拍数和文字，起点自动算。
4. 每个场景先写一个最简 `draw`（哪怕只是一个字），跑一遍全片确认结构和时长。
5. 逐个场景填内容；每次改完只渲染"中间帧 + 最后有效帧 + 定格帧"做联系表检查。
6. `music.py` 改段落边界（按拍号），切点/快门自动跟随分镜表。
7. 全量渲染（后台）→ 合成 → 在切点前后抽帧核对。

## 3. 踩过的坑（系统整理）

### 3.1 环境与工具链

| 现象 | 原因 | 解决 | 以后怎么避免 |
|---|---|---|---|
| `Cannot find package 'playwright'` | Playwright 是全局安装，ESM 的 `import` 不查全局目录 | 把全局包软链接进项目 `node_modules` | 新项目第一步就验证 `import` 能用，不要等写完渲染脚本才发现 |
| 页面里 ES Module 加载失败的风险 | `file://` 下 Chromium 拒绝跨源加载模块 | Node 起一个 20 行的静态 HTTP 服务 | 浏览器渲染管线默认就用 HTTP 服务 |
| 担心无 GPU 没有 WebGL | 服务器没有显卡 | `--use-angle=swiftshader --enable-unsafe-swiftshader`，**先写 10 行测试脚本确认拿到 WebGL2** | 动手写 3D 场景前先做环境探针（WebGL 版本 + 截图耗时） |
| 字体不确定 | 容器里字体因环境而异 | `fc-list` 查出 DejaVu Sans Mono、Noto Sans CJK SC、Latin Modern；等宽字体栈里加 `Noto Sans Mono CJK SC` 作中文回退 | 截帧前等 `document.fonts.ready`；字体栈写成常量统一引用 |

### 3.2 时间与确定性

| 坑 | 说明 | 做法 |
|---|---|---|
| BPM 与帧率不整除 | 拍点落在两帧之间，越往后越拖拍 | 选 120 BPM × 12 fps（6 帧/拍）；见 1.2 的表 |
| 定格帧要"重画"而不是"保存" | 如果定格靠缓存上一帧，单独重渲某一帧时就拿不到缓存 | 定格时用 `sf = live − 1` 重新调用 `draw`；前提是 `draw` 是纯函数 |
| 有状态的模拟 | 元胞自动机、粒子聚集如果在 `draw` 里一步步推，就不能跳帧 | 全部在 `init` 里预计算，或者写成 lerp(起点, 终点, p) |
| 随机数 | `Math.random()` 每次渲染结果都不同，返工一帧会和相邻帧对不上 | 全部用固定种子的 `rng(seed)`；抖动的种子 = 全局帧号 |
| 闭环镜头也定格 | 最后一个镜头如果也变成照片卡，结尾就不等于开头 | `loop` 镜头不定格，全部 6 拍有效；定格拍时时间轴重置为 0 |
| 闭环不是像素级相同 | 开头第 0 帧有"镜头首帧"白闪和冲击缩放，结尾没有 | 目前接受；想完全无缝可以对第 0 帧关掉首帧特效 |

### 3.3 画面

第一轮联系表检查一次性暴露了 8 个问题，**全部是"分层叠加"导致的，单看场景代码发现不了**：

| 镜头 | 问题 | 修复 |
|---|---|---|
| 像素画 | 像素标题压在椭圆顶部 | 椭圆下移、压扁（cy 500→560，半高 380→320），文字缩到 3 倍 |
| 示波器 | 顶部刻度文字钻进 HUD 区 | 网格范围 ±420 → ±350，标签跟着下移 |
| 终端仪表盘 | 百分比数字和进度条字符重叠 | 改成固定宽度 `[` + 56 空格 + `]`，再把竖线画进去，数值放括号外 |
| 数据可视化 | "开始加速"（7.7）和"今天"（13.8）两个标注挤在一起 | 第二个标注下移 40px |
| 光锥 | 整个结构太小、偏上 | 焦距 1250→1650，中心下移 |
| 体素 / 低多边形 | 主体过大、飞行中的体素跑出画面 | 相机拉远（46→56、8→10.5） |
| 字符画 | 整体太暗，看不出结构 | 三层字符颜色都提亮 |

由此得到的**安全区规则**（1920×1080）：
- 顶部 0–110 px：HUD（品牌、计数、维度标签）
- 底部 800–1080 px：HUD（事件、风格、时间轴），并且有渐变压暗
- 场景自带的说明文字统一放在 **x=120, y=190–260**
- 主体中心放在 y≈500，而不是几何中心 540

其他画面坑：
- **Canvas 状态泄漏**：某个场景改了 `globalAlpha`、`textAlign`、`lineDash`、`filter` 没改回来，会污染下一个场景。合成器在每次 `draw` 前后强制 `save / setTransform(1,0,0,1,0,0) / restore`，场景内部改了 `textAlign` 也要自己改回 `left`。
- **故障艺术不能从自己身上读写**：必须先拷贝到临时画布再做切片位移。
- **`shadowBlur` 在软件渲染下很贵**：辉光一律用"宽半透明线 + 窄实线"叠画，或径向渐变圆点。只在少量岩石剪影上用了 `shadowBlur`。
- **逐字画字符画会很慢**：1 万次 `fillText` → 改成每行一次、按亮度拆成三层字符串叠画。
- **着色器全分辨率太慢**：半分辨率渲染再放大；`GL.draw(ctx, scene, cam, 0.5)` 切换尺寸，其他场景自动恢复 1.0。
- **4D 旋转在 4D 出现前就生效**：w 分量为 0 时做 XW 旋转，1D 线段也会被"压扁"。解决：旋转角乘以 s_w。

### 3.4 音频

| 坑 | 说明 | 做法 |
|---|---|---|
| 音乐和画面各做各的 | 事后对齐一定有误差 | 两边都读分镜表的拍号 |
| 上升音效的时变滤波 | numpy 不能直接做"截止频率随时间变化"的滤波 | 一阶低通逐样本循环，4 秒约 17.6 万次，Python 可接受 |
| 磁带停转之后怎么处理 | 直接变速会把后面整段都拖下来 | 只对 0.9 秒区间重采样（速度 1→0），之后用"去掉鼓和贝斯"的轨道重建 |
| 旁链压缩在安静段也生效 | 安静段本来就没底鼓，但包络仍会压音乐 | 黑暗时代、你在这里两段显式跳过 |
| 结尾爆音/循环接缝 | 首尾不淡入淡出会有"咔"声 | 开头 20 ms 淡入，结尾 300 ms 淡出 |

### 3.5 编码与交付

| 现象 | 原因 | 解决 |
|---|---|---|
| **第一次导出 442 MB** | CRF 18 + 较强的逐帧颗粒（`alls=6`）：颗粒是随机噪声，编码器没法压缩 | 颗粒降到 `alls=2~3`，加 `-tune grain` |
| 第二次 46 MB，**超过 30 MB 发送上限** | 用 CRF 控质量不控体积 | 改成两遍编码固定码率 3 Mbps，最终 26 MB；复查了最难压的故障艺术镜头，画质没问题 |
| 规律 | 体积 ≈ 码率 × 时长：3 Mbps × 68 s ≈ 25.5 MB，加音频约 26 MB | 有体积上限时，**先用上限反推码率**，不要用 CRF |

### 3.6 流程

- **先搭骨架、后填内容**：所有场景先有占位 `TODO`（合成器会画红底"TODO id"），能先看到完整时长和 HUD。
- **联系表比逐帧看高效得多**：每个镜头取"中间帧、最后有效帧、定格帧"，9 格一张拼图，一次检查 9 个镜头。第一轮 84 帧就发现了全部布局问题。
- **只返工需要的帧**：渲染脚本支持帧号列表和区间，改一个镜头不用重渲全片。
- **重活放后台**：全量渲染约 6 分钟，后台运行的同时写音乐。
- **没有提前确认画幅**：我默认做了 16:9（B 站横屏）。如果要发抖音/视频号竖屏 9:16，HUD 和所有场景布局都要重排，**这是开工前就该确认的一件事**。

### 3.7 遗留问题（目前成品里还存在的）

- 定格印章和右下角 HUD 的风格名重复出现了一次。
- 暗角盖在照片卡片的米白边框上，边框看起来偏灰。
- 低多边形恒星在画面中仍偏大。
- 配乐是基础合成音色，没有做采样级的质感（例如真实鼓组、厚铺底），和专业电音比有差距。
- 部分天文时间点是简化后的"量级"（如"超新星 · 数十亿年""星系诞生 · 10 亿年"），做科普严谨版需要逐条核对。
- 首尾闭环不是像素级相同（见 3.2）。

## 4. 做类似视频最重要的思路

### 4.1 最核心的一条：让一切都成为"帧号的函数"

这条单独拿出来深挖，因为其他所有东西都建立在它上面。

**它是什么**：视频里的任何东西（画面上每个点的位置、颜色、字符、抖动量、音乐里每个音符）都只由"现在是第几帧"决定，不依赖"上一帧是什么样"。

**它为什么重要**——它同时解决了五个看起来无关的问题：

1. **卡点精确**。拍 = 帧 / 6，音乐也按拍排，两边都是同一个整数坐标系。不需要"听着音乐手动拖时间线"，也不会因为某帧渲染慢而错位（离线渲染，渲染快慢和播放时间完全无关）。
2. **定格可以任意重现**。定格 = "把时间钉在 live−1 帧"。因为 `draw(t)` 是纯函数，这一步只是换一个参数，不需要缓存、截图、状态回滚。
3. **可以跳着渲染、局部返工**。改了第 16 个镜头，只渲染 F=444–467 这 24 帧，其余 792 帧原封不动，拼回去也完全连续。有状态的实时动画做不到。
4. **可以并行**。第 0 帧和第 800 帧互不依赖，理论上可以开 N 个浏览器各渲染一段（这次机器只有 2 核没用上，但架构已经支持）。
5. **可以检查**。联系表能抽任意帧，而且每次抽出来都一样。bug 能稳定复现，就能修。

**它的代价**，也就是需要额外设计的地方：
- 真正"演化"的系统（CA、物理模拟）要**预计算**并把结果变成"查表"。
- 随机性必须**种子化**，种子来自帧号或对象编号。
- 动画要写成**"起点 + 终点 + 缓动(p)"**，而不是"每帧加一点速度"。

**判断标准**：写完一个场景，问自己"如果我直接调用 `renderFrame(500)`，不经过 0–499，画面对不对？"对，这个场景就合格。

这也是 Remotion 的核心设计（`useCurrentFrame()`）。这套管线本质上就是一个极简版的"Remotion + Three.js"：分镜表 ≈ `<Sequence>`，场景 ≈ 组件，合成器 ≈ 全局布局。把它抽成通用框架，下一步就是：
- **场景基座库**：场景 = 可复用的"舞台"。
- **组件库**：HUD、定格卡片、霓虹线、辉光点、投影相机。
- **风格预设**：每种风格 = 一个带参数的场景模板。

### 4.2 其他几条

- **统一外壳，多变内核**。27 种风格之所以不乱，是因为骨架只有一套：同样的 HUD 位置、同样的四色体系、同样的"N−1 拍有效 + 1 拍定格"。风格越多，外壳越要死板。
- **风格选择 = 视觉隐喻**。先问"这个阶段的本质是什么"，再找"哪种代码可视化形式天生长这样"。匹配对了，不需要旁白观众也能懂；匹配错了，再炫也只是轮播。
- **每个镜头只讲一件事，并让它在定格那一帧完成**。定格帧就是这个镜头的"结论"。
- **节奏靠落差**：全片最响的是大爆炸，最安静的是热寂；中间两次主动"掉下去"。一直满格的卡点视频会让人麻木。
- **放一点"真的在算"的证据**：一行代码、一个真实公式、一个跳动的数字。代码视频的说服力来自"这是算出来的"，不是"这是画出来的"。
- **早看全貌，晚抠细节**：占位跑通全片 → 联系表 → 逐镜头打磨 → 全量渲染。反过来做（先把一个镜头做到完美）会在后期发现时长、节奏、布局都要推倒。
- **交付约束倒推参数**：画幅（横/竖）、时长、文件体积上限、发布平台，都在开工前定，它们会反过来决定 BPM、分辨率、码率和 HUD 布局。

## 附录 C：合成器骨架（最小可复用版本）

```js
export function renderFrame(F) {
  const i = locate(F), s = SHOTS[i], lf = F - s.start * FPB;
  const live = s.id === 'loop' ? s.b * FPB : (s.b - 1) * FPB;
  const freeze = lf >= live, sf = freeze ? live - 1 : lf;
  drawScene(i, sf, live);                       // 纯函数：只看 sf
  const r = rng(F * 7919 + 17);                 // 抖动种子 = 帧号
  if (!freeze) {
    const k = lf % FPB, punch = lf === 0 ? .085 : [.05,.028,.013,.005,0,0][k];
    // 平移抖动 + 旋转抖动 + 缩放冲击 → 画场景 → 曝光闪烁 → 暗角 → HUD → 白闪
  } else {
    const k = lf - live;
    // 模糊压暗背景 → 缩放旋转的照片卡 → 暗角 → HUD → 印章 → 白闪 [.85,.35,.1]
  }
}
```
