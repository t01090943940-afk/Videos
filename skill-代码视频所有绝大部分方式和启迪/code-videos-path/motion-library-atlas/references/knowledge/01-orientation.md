# 先区分能力，再选择工具

这是一部发现能力的词典，不是新的视频标准，不要求所有工具改用同一套底层代码。最小研究单位保持在可用资源与能力的层级：知道它解决什么、怎样展示、需要什么条件，以及证据有多强。

## 这些名字不是同一种东西

视频框架负责合成、时间和渲染入口；动画库负责属性随时间变化；渲染器负责画出场景；几何和排版库负责计算；设计资产提供现成作品；声音和编码工具负责其他媒体层。Skills 则提供查阅与执行知识。用一个总评分排列这些不同角色，通常没有意义。

例如 Pretext 的定位是文本测量与排版，不是文字动效引擎；OpenTimelineIO 交换剪辑信息，不负责把它渲染成视频。把定位搞错，会制造虚假的“模型不会做”。[Pretext 作者资料](https://github.com/chenglou/pretext)；[OTIO 官方说明](https://opentimelineio.readthedocs.io/en/latest/)。

## 从一个镜头反查能力

把“做高级视频”换成可辨认的视觉需求：逐字揭示、稳定换行、图形形变、纹理位移、镜头推进、角色接触、音效落点。先找已经解决其中一项的资源，再决定组合。允许多个候选共存，不急于宣布唯一方案。

## 不把广度变成负担

目录可以广，当前上下文应小。先读分类，再读两三个候选词条，最后才查对应 API 和案例。一个镜头通常不需要同时安装十个动画库。边生产边记录，不为追求完整而停止创作。
