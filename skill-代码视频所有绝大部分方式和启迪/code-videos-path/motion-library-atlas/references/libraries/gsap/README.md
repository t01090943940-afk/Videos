# GSAP

> 类型：动画库 · 分类：时间与编排 · 研究快照：2026-09-24
> 证据：官方资料核对核心定位。本条不包含跨模型成绩；关联原理演示不视为该库实测。

## 它增加了什么能力

把对象属性、顺序与缓动放进可控制的时间线。

- 嵌套 timeline
- stagger
- seek
- 插件生态

## 值得尝试的表达

以下是原创实验建议，不是声称已找到或复刻的官方获奖作品。

- [实验方向 01](./examples/01.md)：用同一条曲线连接字幕、路径描边与相机推进。
- [实验方向 02](./examples/02.md)：用 Flip 让卡片网格变成全屏主视觉并保持对象连续性。

## 能力边界

时间线能力不包含自动设计；依赖布局的插件需要稳定 DOM 和字体。

## 使用建议（本词典编辑性判断）

- 暂停主时间线后显式定位时间；保留 labels；清理作用域与重复实例。
- 把入场、强调、停留与退出分开；静止可以是有意阅读，不等于故障。

## 时间线与输出

暂停内部自动播放，显式设置当前时间；必要时预采样。

DOM/SVG 截图或 Canvas 帧 → 编码。

## 组合候选

[splittext](../splittext/README.md), [flip](../flip/README.md), [morphsvg](../morphsvg/README.md), [motionpath](../motionpath/README.md)。组合关系仅是研究候选，不代表已验证兼容。

## 常见平庸与失败模式

- 缓动要符合物体与叙事功能，不是所有对象都弹簧。

## 进一步辨别

### 工程正确与艺术正确分开

时间线能减少延迟散落在代码中的问题，但不会自动决定哪个运动值得发生。为动作使用有意义的标签，例如 reveal-evidence、compare、resolve，而不仅是 step1。

### 显式时间与布局

暂停时间线并定位到目标时间，是接入视频的一条路线。依赖 DOM 测量的 Flip 或 SplitText 则先要求字体、容器与布局稳定。重复初始化还可能把结束态当开始态，应有清理和复位。

[官方 Timeline](https://gsap.com/docs/v3/GSAP/Timeline/) 与 [官方 Skills](https://github.com/greensock/gsap-skills) 是不同层级的资料。Skill 的开源许可不应误当作运行库的许可证。

## 通用镜头提示词

```text
你正在制作一个代码视频镜头，而不是普通网页。请围绕「GSAP」研究 嵌套 timeline, stagger, seek 的表达可能。

创作输入：主题=[填写]；目标观众=[填写]；时长=[填写]；画幅=[填写]；旁白/素材=[填写]；参考画面=[填写]。

先读取该库官方文档：https://gsap.com/docs/v3/。确认版本，必要时只加载相关 Skill，不要盲目复制过时 API。
提出 2 个不同的视觉解释方案，说明每个动作承担的意义。优先考虑：用同一条曲线连接字幕、路径描边与相机推进。
选择方案后写出明确的时间点、主体、焦点和前后状态。不要默认把全部对象设置成缓慢淡入；阅读停留需有目的，运动节奏服从信息理解。
技术边界：时间线能力不包含自动设计；依赖布局的插件需要稳定 DOM 和字体。
接入建议：暂停内部自动播放，显式设置当前时间；必要时预采样。组合候选：splittext, flip, morphsvg, motionpath，尚未验证，先小样确认。
先输出可运行的代表镜头，再渲染检查首帧、动作中间、转场两侧和尾帧。检测文字越界、非意图遮挡、资源缺失与不同步；3D 另检镜头及可见网格穿透。
交付源代码、运行方式、素材及版本清单、实际预览与已知限制。把“官方能力”“自己的设计建议”“实际测试结果”分开报告。不要虚构质量分、模型成功率或测试截图。
```
