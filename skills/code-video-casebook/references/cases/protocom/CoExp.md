## 一、创作思路

### 1. 需求怎么拆成叙事结构

#### 1.1 原始需求里的关键词

用户的要求（原话要点）：

- 30–90 秒，"价值 10000$"，达到顶尖 AE / MG 动画水平
- 有叙事感：普通同学一看就被吸引，投资人一看就觉得"这个社团牛"
- 高燃、有节奏
- **用视觉风格的变化来叙事**：前面是线条手绘立体风格，AI 时代到来后风格改变，最后和社团风格靠拢
- 结尾升华、升维
- 可以用镜像反转、拉片、深浅色反转、各大 AI Logo
- 成员混剪快速卡点

给到的素材：

- 《共建手册 v0.1》PDF（25 页，方法论 7 条、价值观 7 条、判据 21 条）
- 仓库里的落地页调研文档：`info.md`、`plan.md` 等（配色 `#FAF8F3` / `#E8633A` / `#4A7C6F`、华科背景、YC 数据、Karpathy 引语）
- 16 张 protocom 截图：成员列表、11 位成员档案、产品页、Tokens 排行榜、活动流

#### 1.2 拆解方法：先找母题，再定四幕

我先从素材里找能贯穿全片的"一个东西"，选定的是**"一个想法"**：

- 手册的核心是"从本质出发"，落地页的核心是"学生创造"，两边都落在"想法变成现实"上
- 一个灯泡既好画（手绘）又好认，还能在后面被"找回"

这个母题在片中出现了五次：

1. 冷开场："都始于一个想法"
2. 手绘灯泡
3. 被 AI 选框选中的山挡在灯泡前面
4. 拉片倒带停在灯泡上
5. 片尾"下一个故事，由你书写"

然后把用户要的"风格变化"直接对应到戏剧结构：

| 戏剧功能 | 对应风格 | 情绪 |
|---|---|---|
| 建立（有一个想法） | 黑底终端 → 纸 | 安静、好奇 |
| 冲突（想法和现实之间隔着一座山） | 铅笔手绘、等轴立体 | 温暖但受阻 |
| 转折（AI 来了） | 深色霓虹、故障、反相 | 爆炸、失重 |
| 反问（代码不再稀缺，什么才稀缺？） | 拉片倒带 → 回到纸 | 急停、思考 |
| 证据（我们是谁、做了什么） | 暖白纸 + 精确 UI（protocom 界面） | 自信、可信 |
| 升华（升维，收品牌） | 星空、线框、4D | 宏大、邀请 |

### 2. 每个段落的设计意图

#### 2.1 冷开场（0–4 秒）：用最少的东西立母题

- **为什么是终端？** 这是 AI 社团，终端是"写代码的人"最熟悉的界面；黑底白字也是后面所有亮画面的反差起点。
- **为什么打字？** 打字有天然节奏（配键盘声），不需要音乐就能撑起开头 4 秒。
- **转场：光标块放大成纸。** 这是全片第一个匹配剪辑：终端里的方块光标（`fillRect`）从光标位置放大到全屏，颜色就是纸色 `#F3EEE3`。观众会觉得"屏幕变成了一张纸"，从数字世界进入手绘世界。

#### 2.2 手绘时代（4–19.5 秒）：把"没有 AI 的创造"具象成一座山

- **为什么手绘？** 用户明确要求开头用线条手绘立体风格。更重要的是，手绘代表"人"和"慢"，和后面的 AI 形成反差。
- **为什么是山？** "从想法到现实的阻力"是抽象的，必须具象。六块积木上各写一个真实的门槛：学三年编程、写十万行代码、凑齐一个团队、找设计·找服务器、拉到第一笔钱、还得有人愿意用。三层叠成金字塔，就是一座"山"。
- **为什么要仰拍？** 14 秒时镜头快速绕到山脚、压低视角，山突然变高，配手写的"想法与现实之间，隔着一整座山。"这是整段情绪的最低点。灯泡同时开始闪烁、变暗（`noise1(t*14)` 控制亮度）。
- **为什么用"选框 + 提示框"引入 AI？** 这是整片最关键的一刻：一个干净的数字光标闯进铅笔世界，像设计软件一样框住整座山，弹出一个深色的 AI 输入框，打出"把它做出来。"。两种视觉语言第一次同屏碰撞，AI 的到来被表现成"一个动作"，而不是一段解说。

#### 2.3 静默（19.5–20 秒）：高潮前的吸气

画面全黑，只有一个小小的"2022"（ChatGPT 发布那一年），音乐也只剩一个低音。**没有这半秒，后面的 drop 就不响。**

#### 2.4 AI 爆发（20–38 秒）：先爆炸，再急停，再反问

- **20.0 秒反相闪白**：把 18.9 秒的线稿画面反相（纸变黑、铅笔线变白），只闪 0.14 秒。用户要的"深浅色反转"就用在这里，意思是"世界的默认值翻转了"。
- **山碎成 token**：把积木的每条边按 30 像素采样成粒子，每个粒子是一个代码字符（`{}[]<>=λ∑令牌想法做出来`），沿中心向外炸开。**阻挡你的东西，变成了 AI 的原料**，这是视觉上的隐喻。
- **Logo 点名**：OpenAI、Claude、Gemini、DeepSeek、Qwen、Kimi、Doubao、Cursor，一拍一个。背景有 36 条放射线，每拍转一个角度（`idx * 0.26`）。奇数拍在 0.25–0.31 秒闪一下镜像（`P.mirror = 1`），就是用户要的"镜像反转"，但只闪几帧，作为节奏点。
- **工具墙 → 冲入**：32 个 Logo 从中心螺旋填满 8×4 格子，配字幕"工具，一夜之间长满了整个世界。"然后镜头 `inExpo` 放大 15 倍冲进去。这和前面那座山是呼应：**过去挡路的是一堵墙，现在长出来的是一整墙的工具。**
- **95% 和 Karpathy**：给理性观众（投资人）真实数据和权威引语。数据来自仓库里的调研文档 `info.md`。
- **"当代码不再稀缺——"**：从"AI 很猛"转向"那我们有什么"，是整片的逻辑转折。
- **拉片（34–35.45 秒）**：用户要的"拉片"。胶片带上的 14 格缩略图都是**前面真实渲染过的画面**（灯泡、积木、Logo、95%……），带时间码和帧号，倒着飞回去，停在最早的灯泡上，然后推进成全屏。意思是：跑了一圈，回到人的那个想法。
- **答案（36–38 秒）**："注意力 / 判断力 / 品味"一拍一个，背景依次是黑、纸白、珊瑚橙，**深浅反转当作节拍来用**。三个词都能在手册里找到出处：M-01 注意力、插页"你只有不懂，才会认为它说的绝对是对的"、C-16"酷"。

#### 2.5 我们（38–62 秒）：风格收敛成社团本身

- **为什么是暖白纸加精确 UI？** 手绘的纸代表人，AI 段的精确代表机器，两者结合就是"人 × AI"。落地页主背景 `#FAF8F3`、珊瑚橙 `#E8633A` 直接取自 `info.md`；卡片、chip、头像的样式照着 protocom 截图重画，让观众"认出"这是真实在用的系统。这就是用户说的"风格和我们社团靠拢"。
- **成员混剪**：先 4 张大卡，每张 0.5 秒；再 7 张快切，每张 0.25 秒；最后停在一张 2.25 秒的全员目录上。明暗交替、左右交替（镜像构图）。**越切越快，然后急停**，比匀速快剪有力。
- **目录第 12 格"下一个是你"**：虚线框，打字光标在 `@________` 后面闪。给观众留一个位置。
- **76.0B Tokens**：来自 Tokens 排行榜截图的真实数字（4 位参与者：Mio 31.1B、Daniel 24.0B、Gazerrr 13.8B、羽升 7.1B）。柱状图的高度是**从截图里逐列采样出来的**，不是编的。
- **"不是 PPT 上的项目。是正在运行的系统。"**：呼应手册 V-01"吹出去的必须能兑现"。产品卡都带绿色脉冲的"运行中"，活动流滚动的是 tommy0103/obelisk 的真实 PR 标题。
- **手册六条**：每条 1 秒，上半屏从左滑入、下半屏从右滑入，中间一条珊瑚色细线切开，是"镜像"的另一种用法。明暗逐条交替。

#### 2.6 升维（62–80 秒）：从"我们"到"一个时代"

- **61–62 秒塌缩**：最后一条原则缩成一个光点，进入星空。星空呼应落地页首屏的星座背景。
- **星座**：11 个成员头像从光点炸开，连线成星座，配手册价值观总结句"靠交付赢得信任 · 靠信任换取速度 · 靠速度做出真东西"。
- **升维**：这是用户要的"升华升维"，我做成了**字面意义上的升维**：
  - 66.0 秒：星座的点收成一个正方形（z、w 都是 0），标 DIMENSION 2D
  - 67.2 秒：z 展开，变成旋转的立方体，标 3D
  - 68.5 秒：w 展开，变成在 XW、ZW 平面旋转的超立方体，标 4D；第 4 维的边用珊瑚色
  - 文案："当创造被 AI 升维——" → "一个学生，就是一支团队。" → "一群学生，就是一个时代。"
  - 超立方体有 16 个顶点，11 个是成员，**剩下 5 个是空着发光的"座位"**，又一次留位置。
- **Logo**：超立方体塌缩成一点，闪白，指纹图标的弧线一条条画出来（protocom 的图标是指纹，对应"身份与档案"），然后是 protocom 字标和标语，11 个头像绕着 Logo 转。
- **邀请**：`> join protocom --as @你`，光标闪烁，淡出。结尾落在观众身上，而不是落在自己身上。

### 3. 节奏、剪辑、音画配合的技巧

| 技巧 | 用在哪 | 为什么有效 |
|---|---|---|
| **先定 BPM 再写画面** | 全片 120 BPM | 画面和音乐共用一张时间表，天然卡点；120 BPM 一拍正好 0.5 秒，心算方便 |
| **高潮前的静默** | 19.5–20 秒纯黑；71.9–72 秒；35.45 秒音乐骤停 | 听觉上的"吸气"，让下一拍的冲击翻倍 |
| **加速快剪 + 急停** | 成员 0.5 秒 → 0.25 秒 → 停 2.25 秒 | 节奏的变化比节奏本身更抓人 |
| **匹配剪辑** | 光标变纸、山变 token、胶片停在灯泡、头像行第一个头像放大成大卡、超立方体收成点再长出 Logo | 转场不是"切"，而是"变"，观众的视线被连续引导 |
| **冲击点叠多层反馈** | Logo 每拍：缩放 1.55→1、径向模糊 0.14、色差 0.015、闪白 0.35（2 帧），再配冲击音效 | 单独一种都显得软，叠在一起才有"砸"的感觉 |
| **深浅反转当节拍** | 20 秒反相；答案段黑/白/橙；成员卡明暗交替；原则明暗交替 | 反转一次就是一次视觉重音 |
| **镜像当点缀** | Logo 反拍闪 0.06 秒；成员卡左右交替；原则上下对向滑入 | 一直开着是噪音，短暂出现才是节奏 |
| **逐字出现** | 几乎所有标题 | 上移 + 去模糊 + 淡入 + 错开 0.03–0.06 秒，普通文字立刻变成动效文字 |
| **每个画面动作都有声音** | 砖块落地（闷响）、打字（键声）、成员切换（快门）、工具墙填格（上行音阶）、95% 计数（加速滴答）、拉片（磁带倒带声） | 声音让动作有"重量" |
| **音乐分段换调** | 手绘段 Am-F-C-G 拨弦；我们段 C-G-Am-F 更明亮；升维段回到拨弦母题 | 和声的变化对应情绪的变化；升维段的拨弦是手绘段的回声 |
| **侧链"泵感"** | 贝斯、和弦被底鼓压低 | 电子乐的呼吸感，让鼓更突出 |

#### 2.2 核心思路：视频 = 时间的纯函数

```js
// main.js —— 整条片子只有这一个入口
const acts = [[0, 20, drawAct1], [20, 38, drawAct2], [38, 62, drawAct3], [62, 80, drawAct4]];

export function drawRaw(c, t, scale = 1) {
  const P = { time: t, grain: 0.04, vig: 0.3, ca: 0.0015 };  // 后期参数，各幕可以改
  c.save();
  c.setTransform(scale, 0, 0, scale, 0, 0);                    // scale 给缩略图用
  c.globalAlpha = 1; c.filter = 'none'; c.globalCompositeOperation = 'source-over';
  for (const [a, b, fn] of acts) if (t >= a && t < b) fn(c, t, P);
  c.restore();
  return P;
}
function renderFrame(t) { const P = drawRaw(ctx, t); post(src, P); }  // 2D 离屏 → WebGL 后期
window.renderFrame = renderFrame;
```

要点：

- **没有状态**：不存上一帧，不用 `requestAnimationFrame` 的时间，不用 `Math.random()`
- **所有随机来自哈希**：`hash(i, seed, boilFrame)`，同样的输入永远得到同样的输出
- 带来的好处：
  - 可以直接跳到任意一帧预览
  - 可以按时间段拆给 4 个进程并行渲染，拼起来是无缝的
  - 拉片时可以把"过去的画面"直接画成缩略图

```js
// core.js —— 确定性哈希（替代 Math.random）
export function hash(...n) {
  let h = 2166136261;
  for (const v of n) {
    h ^= Math.floor(v * 1000003) | 0;
    h = Math.imul(h, 16777619); h ^= h >>> 13;
    h = Math.imul(h, 0x5bd1e995); h ^= h >>> 15;
  }
  return ((h >>> 0) % 1000000) / 1000000;
}
```

#### 2.3 镜头写法：`prog` + 缓动

每个镜头都是"把绝对时间换成 0→1 的进度，再套缓动"：

```js
export const prog = (t, a, b) => clamp((t - a) / (b - a));   // t 在 [a,b] 内映射到 0→1

// 例：Logo 每拍砸入
const idx = Math.floor((t - 22) / 0.5), lt = (t - 22) - idx * 0.5;  // 第几拍、拍内时间
const e = ease.outExpo(clamp(lt / 0.3));
const sc = 1 + 0.55 * (1 - e);                                      // 1.55 → 1.0 回弹
P.zoomBlur = 0.14 * (1 - clamp(lt / 0.16));                          // 径向模糊快速衰减
P.ca = 0.003 + 0.012 * (1 - clamp(lt / 0.12));                       // 色差尖峰
P.flash = lt < 0.035 ? 0.35 : 0;                                    // 2 帧闪白
```

缓动几乎只用 `outExpo`（出现）和 `inExpo`（吸入 / 冲入），偶尔用 `outBack`（卡片弹出）和 `outBounce`（砖块落地）。

#### 2.4 逐字出现（全片最常用的一招）

```js
export function revealText(ctx, str, x, y, o, p, { stagger = 0.06, rise = 40, dur = 0.5, blur = true } = {}) {
  const chars = [...str], n = chars.length, total = dur + stagger * (n - 1);
  // …先量每个字宽，按 align 算起点…
  chars.forEach((c, i) => {
    const lp = clamp((p * total - i * stagger) / dur);   // 这个字自己的进度
    const e = ease.outExpo(lp);
    if (lp > 0) {
      ctx.save();
      if (blur && lp < 1) ctx.filter = `blur(${(1 - e) * 10}px)`;
      text(ctx, c, cx, y + (1 - e) * rise, { ...o, alpha: e });  // 上移 + 去模糊 + 淡入
      ctx.restore();
    }
    cx += widths[i];
  });
}
```

#### 2.5 后期参数由每一帧自己决定

每幕只改 `P` 对象，比如 `P.invert = 1`、`P.mirror = 1`、`P.dirBlur = [vx, 0]`，着色器统一处理。这样**特效是时间的函数**，和画面一起卡点。

  const swing = ease.inOutExpo(prog(t, 14, 14.7));
  const yaw   = lerp(-0.32 + (t - 6) * 0.01, 0.5, swing);                 // 缓慢环绕 → 14 秒猛甩

  const dist  = lerp(24, 17.5, ease.inOutCubic(prog(t, 14, 16)));         // 推近

}

#### 3.7 星空 + 4D 线框（升维）

- 星空：260 颗星，位置由哈希决定，亮度按 `sin(t × 随机频率 + i)` 闪烁，15% 是暖色
- 超立方体：16 个顶点 `(±1, ±1, ±1, ±1)`；32 条边 = 所有只差一个坐标的顶点对

```js
function tesseract(t, sz, sw, spin, scale) {
  return V4.map(([x, y, z, w]) => {
    z *= sz; w *= sw;                                              // sz、sw 从 0 到 1 → 2D→3D→4D
    [x, w] = [x * cos(a) - w * sin(a), x * sin(a) + w * cos(a)];   // XW 平面旋转
    [z, w] = [z * cos(.7a) - w * sin(.7a), …];                     // ZW 平面旋转
    const k4 = 1 / (3 - w); x *= k4 * 2; y *= k4 * 2; z *= k4 * 2; // 4D → 3D 透视
    // 再做 3D 偏航 + 俯仰，然后 3D → 2D 透视
  });
}
```

- 星座到超立方体的变形：每个成员分配一个顶点（`SLOT = [0,3,5,6,9,10,12,15,1,14,7]`），位置 `lerp(星座坐标, 超立方体顶点投影, morph)`
- 边的颜色：第 4 维（w 方向）的边珊瑚色，z 方向青色，其余奶白
- 旋转角 = `spinT*0.9 + spinT²*0.12`（越转越快）+ 塌缩时再加 3 弧度
- 指纹：8 段同心圆弧（半径 14–74，开口朝下，部分断成两段）+ 两条"茎"，按进度逐条画出

#### 3.8 WebGL 后期（所有风格共用）

一个片元着色器，全部由 uniform 控制，顺序如下：

1. **镜像**：`if (mirror > 0.5 && uv.x > 0.5) uv.x = 1.0 - uv.x;`（右半边是左半边的镜像；`mirror > 1.5` 时上下也镜像）
2. **故障**：画面分成 28 行，每行按 `hash(row, floor(time*24))` 决定是否水平错位；另有 9×6 的块偏移
3. **径向模糊 + 方向模糊 + 色差**：14 次采样，每次 R/G/B 按到中心的距离错开取样
4. **辉光**：8 个方向 × 2 个距离采样，取超过 0.55 亮度的部分叠加
5. **反相**：`col = mix(col, 1.0 - col, invert)`
6. **扫描线**：按 `gl_FragCoord.y` 的正弦调制亮度
7. **暗角**：`1 - vig * dot(q, q) * 1.35`
8. **暖色调**：`col * vec3(1.04, 1.0, 0.94)`
9. **颗粒**：按像素坐标和时间的哈希加 ±grain 的噪声
10. **闪白**：`mix(col, flashColor, flash)`，`flashColor` 可以是纯白或奶白

#### 4.2 乐器与音效（全部是函数）

| 名称 | 合成方法 |
|---|---|
| 底鼓 `kick` | 正弦频率 `45 + 120·e^(-t/0.035)` 下扫，振幅 `e^(-t/0.16)`，加 2kHz 以上的噪声"咔"（4ms），`tanh` 饱和 |
| 拍手 `clap` | 三次噪声脉冲（0、11、22ms），带通 900–5200Hz，最后一次长衰减 |
| 军鼓 `snare` | 带通噪声 1.5–8kHz + 185Hz 正弦 |

#### 4.4 混音与母带

- 混响：两条 2.6 秒的指数衰减噪声（6kHz 低通）作为左右声道冲激响应，`scipy.signal.fftconvolve` 卷积，湿声 0.9
- 28Hz 高通去掉次声
- 先归一化到峰值 1.6，再 `tanh` 软削波（相当于一个简单的饱和压缩）
- **淡入 0.05 秒**（防止开头"啪"一声），**淡出 1.6 秒**（`linspace(1, 0)^1.5`）
- 最后归一化到峰值 0.93（约 -0.6 dBFS），写 16-bit WAV

### 5. 渲染与导出命令、参数

#### 5.1 浏览器启动参数（最重要的一行）

```js
chromium.launch({ args: [
  '--enable-unsafe-swiftshader', '--use-angle=swiftshader', '--ignore-gpu-blocklist',   // 让 WebGL 在无 GPU 环境可用
  '--disable-accelerated-2d-canvas', '--disable-gpu-rasterization',                   // 2D 画布走 CPU，快 100 倍
]});
// 视口 1920×1080；加载后先 waitForFunction(() => window.__ready)，再 await 它
```

#### 5.2 帧导出

```js
const b64 = await page.evaluate((t) => {
  window.renderFrame(t);
  return document.getElementById('out').toDataURL('image/jpeg', 0.96).split(',')[1];
}, f / FPS);                                                   // 帧号 / 60 = 时间，不累加浮点
if (!ff.stdin.write(Buffer.from(b64, 'base64'))) await new Promise((r) => ff.stdin.once('drain', r));  // 背压
```

WebGL 上下文必须用 `preserveDrawingBuffer: true` 创建，否则 `toDataURL` 可能拿到空白。

#### 5.3 每个进程的 ffmpeg

```bash
ffmpeg -y -loglevel error -f image2pipe -framerate 60 -c:v mjpeg -i - \
       -c:v libx264 -preset slow -crf 21 -pix_fmt yuv420p -r 60 out/segments/seg0.mp4
```

- 4800 帧（80 秒 × 60fps）平均分给 4 个进程：`a = floor(TOTAL*w/4)`，`b = floor(TOTAL*(w+1)/4)`
- `-pix_fmt yuv420p` 保证所有播放器、微信、手机都能播

#### 5.4 拼接 + 混流

```bash
# list.txt 内容：file 'seg0.mp4' … file 'seg3.mp4'
ffmpeg -y -f concat -safe 0 -i out/segments/list.txt -i audio/music.wav \
       -c:v copy -c:a aac -b:a 256k -shortest -movflags +faststart out/protocom-promo.mp4
```

- 视频 `-c:v copy` 不重新编码（无损拼接，秒级完成）
- `-movflags +faststart` 把索引放到文件头，网页和手机能边下边播
- 音频时长刚好 80.0 秒，和视频一致

#### 5.5 分享版（压到上传限制以下）

```bash
ffmpeg -y -i out/protocom-promo.mp4 -c:v libx264 -preset slow -crf 24 -pix_fmt yuv420p \
       -c:a copy -movflags +faststart out/protocom-promo-share.mp4
```

#### 6.2 最耗时的环节和提速办法

1. **全片渲染（25 + 19 分钟）**

### 2. 踩坑逐条复盘

#### 【环境与依赖】

**坑 1：PDF 读不了**
- **现象**：用 Read 工具读 PDF 报错 `pdftoppm is not installed`；改用 pypdf，导入时崩溃 `ModuleNotFoundError: No module named '_cffi_backend'` → `pyo3_runtime.PanicException`
- **原因**：系统没装 poppler；pypdf 依赖的 cryptography 和系统里的 cffi 版本冲突
- **解决**：`pip install pymupdf`，用 `fitz.open(pdf)` 逐页 `get_text()`，同时 `get_pixmap(dpi=50)` 导出缩略图
- **下次**：读 PDF 直接用 PyMuPDF

**坑 2：没有 ffmpeg，也没有 numpy**
- **现象**：`which ffmpeg` 为空；`import numpy` 失败。Playwright 自带的 ffmpeg（`/opt/pw-browsers/ffmpeg-1011`）只能录 webm，不能编 H.264
- **解决**：`pip install numpy scipy imageio-ffmpeg`，用 `imageio_ffmpeg.get_ffmpeg_exe()` 拿到静态二进制路径（ffmpeg 7.0.2）
- **下次**：开工第一步就跑依赖检查

**坑 3：CDN 被拒**
- **现象**：`curl https://cdn.jsdelivr.net/...` 返回 `CONNECT tunnel failed, response 403`
- **原因**：环境的网络代理只放行部分域名
- **解决**：所有字体、图标都从 npm 安装到本地（npm registry 可访问），HTML 里用相对路径引用 `node_modules/`
- **下次**：代码视频的所有资源一律本地化，渲染过程不依赖网络（也保证每次渲染结果一致）

**坑 4：用户中途发的截图不在磁盘上**
- **现象**：第一批 5 张截图在 `images/` 目录里，后来补发的 10 张（羽升、司南、Elena、执炬人、Whosxws、why、王梓鑫、小ye、活动流、排行榜）没有文件
- **原因**：对话中途发的图片只进了模型上下文，没有落地成文件
- **解决**：头像全部从第一张成员列表截图里抠（每人约 38 像素）；新截图里的数据（真名、Token 数、PR 标题、76.0B）靠读图抄进 `data.js`
- **下次**：需要用到的图片，请用户以文件方式上传；或者一开始就确认 `ls` 能看到哪些文件

#### 【渲染性能】

**坑 5：截图一帧 41 秒（最严重的一个坑）**
- **现象**：`renderFrame` 本身只要 4–7ms，但 `page.screenshot()` 要 41 秒；预览脚本直接超时
- **原因**：无头 Chromium 默认把 2D 画布交给 GPU 光栅化，而这里没有 GPU，走的是 SwiftShader 软件模拟；`renderFrame` 只是录制绘图命令，真正的光栅化在截图时才发生，所以耗时全部落在截图上。纸张纹理那 90000 个 `fillRect` 在这条路径上极慢
- **解决**：启动参数加 `--disable-accelerated-2d-canvas --disable-gpu-rasterization`，2D 画布改走 CPU 的 Skia。之后截图 347ms，页面就绪从 61 秒降到 6 秒
- **下次**：在无 GPU 环境渲染 Canvas，一开始就加这两个参数；**测性能要测"绘制 + 导出"的总时间**，不要只测绘制函数

**坑 6：WebGL 在无头环境不可用**
- **原因**：Chromium 默认拒绝软件 GL
- **解决**：加 `--enable-unsafe-swiftshader --use-angle=swiftshader --ignore-gpu-blocklist`
- **下次**：这三个参数和上面两个一起，作为固定启动参数

**坑 7：页面还没准备好就开始渲染**
- **现象**：`TypeError: window.renderFrame is not a function`
- **原因**：`main.js` 用了顶层 `await import()`，`window.__ready` 要等所有 import 完才赋值；`page.evaluate(() => window.__ready)` 执行时它还是 `undefined`，立刻就返回了
- **解决**：先 `await page.waitForFunction(() => window.__ready, null, { timeout: 120000 })`，再 `await page.evaluate(() => window.__ready)`
- **下次**：就绪信号在模块最开始就挂一个 Promise，或者一律用 `waitForFunction`

#### 【中文字体与文字排版】

**坑 8：中文字会先显示成后备字体**
- **原因**：fontsource 的中文字体按 unicode-range 切成上百个 woff2 小文件。canvas 的 `fillText` 用到某个字时浏览器才开始下载那一片，第一次画的时候还没下完，就用后备字体画了。`document.fonts.ready` 只保证"当前已请求的"字体加载完，而 canvas 用到的字在绘制前根本没被请求
- **解决**：字体预热，把整条时间轴每 1/20 秒画一遍，记下所有用到的"字体串 + 文字"组合，逐个调用 `document.fonts.load(font, text)`，重复 3 遍
  ```js
  export function text(ctx, str, x, y, o) { const f = font(ctx, …); fontUses.add(f + '\u0000' + str); … }
  async function preloadFonts() {
    for (let pass = 0; pass < 3; pass++) {
      for (let t = 0; t < DURATION; t += 1 / 20) drawRaw(ctx, t);
      await Promise.all([...fontUses].map((k) => { const [f, s] = k.split('\u0000'); return document.fonts.load(f, s).catch(() => {}); }));
      await document.fonts.ready;
    }
  }
  ```
- **下次**：任何用网络 / 切片字体的 canvas 项目都要做这一步；并抽查几帧，确认字形是目标字体

**坑 9：缩略图里的字是后备字体**
- **原因**：拉片的缩略图按时间点缓存，而字体预热那三遍绘制时就已经生成并缓存了缩略图，那时字体还没下完
- **解决**：act2 导出 `clearThumbs()`，`main.js` 在 `preloadFonts()` 之后调用
- **下次**：任何缓存都要在"所有资源就绪"之后才开始生成

**坑 10：手写字体的破折号变成"一一"**
- **现象**："要把它变成现实——"里的破折号在 Long Cang 字体里像两个"一"
- **解决**：手写文案不用破折号，改成"要把它变成现实，"；衬线体（Noto Serif SC）里的"——"是正常的，照常使用
- **下次**：特殊字体里的标点（破折号、引号、省略号）要单独渲染检查

**坑 11：一行三句文案超出画面**
- **现象**："靠速度做出真东西"被截在画面右边
- **原因**：三句的 x 坐标写死成 `330 + k * 630`，没考虑实际字宽
- **解决**：先 `measure()` 每句宽度，加上间距 110 求总宽，再整体居中排布
- **下次**：多段文字横排，一律先量再排；不要写死坐标

**坑 12：西文字体里的中文**
- **做法**：`font()` 函数里，等宽字体和 Space Grotesk 后面都自动追加 `"Noto Sans SC"` 作为后备，避免混排的中文掉到系统字体

#### 【画布坐标与变换】

**坑 13：拉片的缩略图全是白的**
- **现象**：胶片带上每一格都是白的或者空的
- **原因**：缩略图的做法是在小 canvas 上 `scale(0.25)` 后调用 `drawRaw`，但 `drawRaw` 一开头就 `setTransform(1,0,0,1,0,0)`，`fillBg` 里也有同样的重置，缩放被清掉了，只画出了左上角四分之一
- **解决**：`drawRaw(c, t, scale)` 改成 `setTransform(scale, 0, 0, scale, 0, 0)`；`fillBg` 不再重置变换，改成在当前变换下填充 `(-2W, -2H, 5W, 5H)` 的大矩形
- **下次**：场景代码内部**禁止** `setTransform`，只用相对变换，这样同一段画面代码既能全屏画，也能画成缩略图、被放大、被推拉

**坑 14：砖块上的字不跟镜头动**
- **原因**：贴字用了 `ctx.setTransform(仿射矩阵)`，丢掉了外层的镜头漂移和推近
- **解决**：改成 `ctx.transform(…)`（在当前变换上叠加）
- **下次**：同坑 13

**坑 15：匹配剪辑差了一截**
- **现象**：头像行第一个头像放大到 (560, 540)、半径 250，但下一镜头的第 0 帧头像在 (680, 540)
- **原因**：下一镜头的头像带入场动画，第 0 帧有 `(1 - e) * 120` 的偏移，而 `e` 在第 0 帧是 0
- **解决**：放大终点改成 680，半径 265（第 0 帧还有 1.06 倍缩放）
- **下次**：匹配剪辑的终点，要对的是下一镜头**第 0 帧实际画出来的位置**，而不是它最终停下来的位置；两帧并排渲染检查

#### 【构图】

**坑 16：3D 场景太小、地面线太斜** → 焦距从 1650 改到 2150，偏航从 -0.42 改到 -0.32，灯泡和旗子从 ±7.6 收到 ±7.0

**坑 17：提示框压住被选中的山** → 仰拍段整体上移（`cyOff` 从 +70 过渡到 −75），提示框下移到 `H - 110`

**坑 18：星座节点贴着画面顶端** → 散开范围从 1500×1300 缩到 1380×1000，中心上移 90 像素

**坑 19：超立方体转出画面** → 尺寸从 250–290 缩到 230–250，中心上移

**坑 20：Logo 周围的头像环压住字标** → 圆轨道 1.25×0.95 改成扁椭圆 1.6×0.6，图标整体上移 40 像素

**坑 21：产品卡里的迷你柱状图压住描述文字** → 直接删掉。一张卡只讲一件事

**下次**：每幕写完立刻出 6–18 张静帧拼图，大部分构图问题一眼就能看出来。这次每个问题都是看拼图发现的。

#### 【后期与画质】

**坑 22：亮色头像被辉光吹成白色圆斑**
- **现象**：星座段 Mio、羽升、Gazerrr、Elena 的头像看起来是纯白光球，认不出是谁
- **原因**：辉光的阈值是亮度 0.55，浅色头像本身就超过阈值，被当成光源叠加；再加上头像背后的径向光晕
- **解决**：62–72 秒把 `P.bloom` 从 0.55 降到 0.1
- **下次**：辉光只给真正该发光的元素（线框、光点、文字），**有照片的段落要降低辉光或提高阈值**

**坑 23：低清头像放大后很糊**
- **原因**：原图只有约 38 像素，放大到半径 250–300 像素
- **缓解**：半径大于 110 时叠一层 8×8 的网点图案（黑点半径 1.6，透明度 0.1–0.2）加径向明暗，把"糊"变成"印刷质感"
- **根治**：要原图
- **下次**：开工前就要高清头像；抠图时优先从大图抠（这次 Mio、Daniel、Gazerrr 用的是档案页的大头像，明显更清楚）

**坑 24：反相闪白那几帧看不清**
- **现象**：20.0–20.14 秒的反相线稿在成片里比较暗，线条不清楚
- **原因**：同时开了 0.08 的径向模糊和 0.012 的色差
- **结论**：只有 8 帧，作为"闪"是成立的；如果要让观众看清反相后的线稿，应该延长到 0.3 秒并去掉模糊

#### 【帧率、时长与音画同步】

**坑 25（预防成功）：时间累加误差**
- **做法**：每一帧的时间用 `f / FPS` 计算，而不是 `t += 1/60` 累加，避免浮点误差让后面的帧慢慢漂移
- 音频用 `int(round(t * SR))` 定位采样点
- 两边的时间常数完全相同，所以同步是"设计出来的"；成片音视频时长都是 80.000 秒

**坑 26：音频数组长度差 1**
- **现象**：`ValueError: operands could not be broadcast together with shapes (1323,) (1322,)`
- **原因**：两段信号分别用 `int(SR * 0.03)` 和 `int(SR * 0.012) + int(SR * 0.018)` 计算长度，取整后差 1 个采样
- **解决**：相加前取 `min(len(x), len(y))` 截齐
- **下次**：音频拼接一律按最短长度截齐

**坑 27：侧链压缩的顺序**
- **原因**：`DUCK` 包络是 `kicks()` 写入的，`add(..., duck=True)` 读取时如果底鼓还没加，读到的是 1（不压）
- **做法**：每一段都先调用 `drums()` / `kicks()`，再加贝斯和和弦
- **遗留**：62–72 秒的铺底在 66 秒的底鼓之前添加，所以这一段没有泵感（不影响，因为这段本来就是抒情段）

**坑 28：我听不到声音**
- **现象**：只能用 RMS 曲线确认动态，无法判断音色、混音平衡、卡点的听感
- **下次**：音频合成完成后，**第一时间把单独的 music.wav 发给人试听**，而不是等整片渲染完

#### 【文件体积与交付】

**坑 29：第一次成片 775MB**
- **原因**：CRF 15 本身就高，加上后期每帧叠加的随机颗粒（`grain` 0.03–0.05）几乎无法帧间压缩，码率 77.5 Mbps
- **测试**：10 秒样本，CRF 20 + tune grain 23.5MB，CRF 21 4.68MB，CRF 23 2.45MB（tune grain 反而更大，因为它会刻意保留颗粒）
- **解决**：分段直接用 CRF 21 编码，成片 45MB，截图对比看不出差别
- **下次**：有颗粒的片子从 CRF 21 起步；先拿 10 秒样本测体积再全片渲染

**坑 30：超过 30MB 的上传限制**
- **现象**：45MB 的成片发送失败 `45.1 MiB exceeds the 30 MiB upload limit`
- **解决**：另压 CRF 24 分享版 27MB，母版进仓库
- **下次**：开工前就问清交付渠道的大小限制；目标体积大约 = 限制 × 0.9，按"码率 = 体积 ÷ 时长"反推 CRF

**坑 31：成片提交不上去**
- **现象**：`git add out/protocom-promo.mp4` 提示 `paths are ignored by one of your .gitignore files: promo/out`
- **原因**：仓库根目录的 `.gitignore` 里有 `out` 规则（不是我写的 `promo/.gitignore`）
- **解决**：`git add -f`
- **下次**：交付物直接放在不会被忽略的目录（比如 `promo/dist/`），或者提交后用 `git status` 确认

**坑 32：一次改动触发整片重渲染**
- **现象**：只改了 62–72 秒的辉光，重新渲染了整片 19 分钟
- **下次**：`render.mjs` 支持起止时间参数，只重渲染受影响的段落，再用 concat 拼接（前提：分段边界落在帧上，编码参数相同）

#### 【内容准确性】

**坑 33（预防）：不确定的事实不上屏**
- 本来想给每个 Logo 标发布年份，但各家的时间说不准，就改成统一的"2022 → 2026"
- 95% 的数据、Karpathy 引语来自仓库里已有的调研文档，没有自己编
- 柱状图高度是从截图逐列采样的：用 Pillow 数亮度小于 120 的像素，得到每根柱子的相对高度；羽升的截图不在磁盘上，只能按图目测填写

**坑 34：社团名不确定**
- 落地页标题是"此处应有名字"，而成员页有"加入了 protocom"，所以用了 protocom，并把它做成 `data.js` 里的一个常量 `BRAND`
- 注意：片尾打字的命令 `> join protocom --as @你` 在 `synth.py` 里也写了一遍（用来计算打字音的次数），改名时两处都要改

### 1. 代码视频制作流程模板

```
阶段 0：环境检查（5 分钟）
  □ ffmpeg？没有 → pip install imageio-ffmpeg
  □ Chromium / Playwright？位置？
  □ Python：numpy scipy pillow pymupdf
  □ 中文字体？没有 → npm i @fontsource/noto-sans-sc @fontsource/noto-serif-sc
  □ 网络：npm / Google Fonts / CDN 哪些可用
  □ 素材文件是否在磁盘上（ls）

阶段 1：理解与策划（15 分钟）
  □ 读全部素材，抽出：品牌名、配色、字体、可验证的数据、可引用的原话、真实界面截图
  □ 找母题（一个贯穿全片、会反复出现的物件或句子）
  □ 按"建立 → 冲突 → 转折 → 反问 → 证据 → 升华 → 邀请"排结构
  □ 每一段指定一种视觉风格，风格变化要对应叙事转折
  □ 定 BPM（120 最方便）和总时长（小节数 × 2 秒）
  □ 写时间表：每个镜头的起止秒数、关键动作、对应音效

阶段 2：搭引擎（20 分钟）——可以直接复制本项目的 core.js / post.js / main.js / preview.mjs / render.mjs
  □ core.js：prog / ease / hash / text / revealText / typeText / 风格专用画笔 / 3D 投影
  □ post.js：一个全屏着色器，所有特效参数化
  □ main.js：acts 表 + drawRaw(c, t, scale) + 素材加载 + 字体预热 + renderFrame
  □ data.js：所有事实数据
  □ preview.mjs：静帧导出；sheet.py：拼图

阶段 3：逐段开发（每段 10–20 分钟）
  循环：写镜头 → node preview.mjs out/pv t1 t2 … → python3 sheet.py → 看 → 改
  □ 每个镜头看开头 / 中间 / 结尾三帧
  □ 转场看前一帧 + 后一帧

阶段 4：音频（10 分钟）
  □ 乐器、音效函数
  □ 按时间表 add(音效, 时间)，时间照抄画面常量
  □ 检查分段 RMS 曲线
  □ 立刻把 music.wav 发给人试听 ←←← 这次没做，下次要做

阶段 5：草稿渲染（5–10 分钟）
  □ 30fps、960×540 渲染一版确认节奏和音画同步（这次没做，下次要做）

阶段 6：正式渲染（约 20 分钟 / 80 秒 60fps / 4 进程）
  □ 10 秒样本测体积 → 确定 CRF
  □ node render.mjs 4 60 out/xxx.mp4
  □ 后台运行 + 监控进度

阶段 7：复查与交付（10 分钟）
  □ ffmpeg -i 看参数
  □ 从成片抽所有转场点前后的帧拼图复查
  □ 有问题 → 改 → 只重渲染受影响的段落
  □ 压分享版（体积 < 渠道上限）
  □ git add -f 提交；发送文件
  □ 列出需要人来确认的事项（听感、真名、商标、品牌名）
```
