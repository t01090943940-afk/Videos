# 《碎月重圆》AE 级特效 CoExp（复盘）

> 这份复盘只讲 30 秒 MG 动画《碎月重圆》里的特效是怎么做出来的：3D 合成器、抠像拆层、碎裂、出框、魔方墙、隧道、粒子、后期和运动模糊，以及和画面卡点的音效。
> 3 分钟的《共此时》见 `../共此时代码视频复盘.md`，本文不再重复。
> 文中的参数、耗时、报错和改动都来自这次真实的日志和代码（`mid_autumn_film/mg/`）。

成片：`output/碎月重圆_MG动画.mp4`，1920×1080，30 fps，时长 30.000 s，H.264 加 AAC 256k，总码率 7.55 Mbps，文件 28.3 MB。

## 一、创作思路

### 1. 先回答"AE 级"到底指什么

我把"像顶尖 AE 设计师做的"拆成了几条可以检验的标准，每条都对应一种 AE 里的做法：

| AE 设计师的做法 | 观众感受到的 | 这次用代码怎么做 |
|---|---|---|
| 3D 图层 + 摄像机（Camera、Orbit、Dolly） | 画面有纵深，会绕着转 | 自己写透视摄像机和 3D 卡片（`eng.py`） |
| Roto Brush 把人抠出来 | 人能从照片里"站出来" | MediaPipe 交互式分割 + 导向滤波修边（`cutout.py`） |
| 2.5D 拆层（Projection / 等比缩放补偿） | 第一眼是平面照片，一动才发现是立体的 | 各层按深度 z/D0 等比放大 |
| Shatter / Voronoi 碎裂 | 月亮被打碎 | 环状 Voronoi 裂纹 + 双面碎片卡片 |
| C4D MoGraph 克隆 + Effector | 一整面方块按波形翻转 | 336 个立方体、按延迟场驱动 |
| Trapcode Form / Particular | 照片散成粒子又聚成别的形状 | 23 万颗解析轨迹粒子 |
| Optical Flares、Glow、Motion Blur、CA、Shake | 质感、速度感、"贵" | 自写后期链 + 子帧运动模糊 |

结论：**素材不能摆在时间线上"拼"，而要进到 3D 空间里重新"拍"。** 所以这次第一步写的是合成器，而不是剪辑表。

### 2. 主题：月亮碎了，碎片是我们

这次主题延续上一部片子的"月亮"母题，并把它做成一个闭环：月亮碎了，碎片是我们；碎片一路被拆开、翻转、穿过，最后我们聚齐，月亮又圆了。片名取「碎月重圆」（化用"破镜重圆"）。这个结构让首尾两个最炫的镜头（碎裂、粒子重组）刚好是一对互逆的动作，中间三个镜头负责"在碎片之间穿行"。

五个镜头，每个只炫一种主技术，避免 30 秒里技术互相抢：

| 时间 | 镜头 | 主技术 | 情绪 |
|---|---|---|---|
| 0–6 s | 碎月 | Voronoi 碎裂 + 双面卡片 + 距离场转场 | 悬念 → 爆发 |
| 6–9 s | 拆层 | Roto 抠像 + 2.5D 拆层 + HUD | 惊奇（"原来是立体的"） |
| 9–12 s | 出框 | 框内 / 框外双纹理出框 | 俏皮 |
| 12–18 s | 魔方墙 | 336 立方体波形翻转 + 亮度浮雕 + 爆散 | 节奏感、力量 |
| 18–24 s | 时光隧道 | 螺旋照片隧道 + 变速 + 立体字 583 | 速度 → 慢动作 → 冲出 |
| 24–30 s | 粒子归月 | 23 万粒子 → 星盘 → 满月 + 立体标题 | 收束、温暖 |

### 3. 衔接原则：每个转场都是一个动作，不是一次切换

AE 片子"高级"的一大来源是转场有物理逻辑。本片的转场都绑在动作上：

- **碎月 → 拆层**：碎片中有一块（hero shard）转过来，背面照片沿距离场从碎片形状长成整幅矩形。它的最后一帧和下一镜头的第一帧**逐像素相同**。
- **拆层 → 出框**：甩镜（whip pan）。两个镜头被当成一条左右相连的长条整体左移，中间做水平方向模糊。
- **出框 → 魔方墙**：推进 + 缩放模糊 + 闪白，落在第 12.0 秒的重拍上。
- **魔方墙 → 隧道**：立方体炸向镜头的同时，隧道已经在后面渲染并淡入（从 16.2 s 到 17.3 s）。镜头穿过碎方块，直接就在隧道里。
- **隧道 → 粒子**：隧道尽头的光越来越大，最后白场（24.0 s），白场褪去时合照已经在那里。
- 所有转场点都来自同一张节拍表 `cues.py`（120 BPM），音效也从这张表取时间。

## 二、具体的创作方式

### 1. 自写 3D 合成器（`eng.py`）：AE 3D 图层的最小实现

**坐标系**：世界坐标 x 向右、y 向下、z 朝屏幕里，和图像坐标一致，写布局时不用反复翻转符号。

**摄像机**：用 look-at 构造，焦距由 fov 推出：

```python
f = normalize(target - pos); r = normalize(cross((0,1,0), f)); d = cross(f, r)
self.f = (W/2) / tan(radians(fov)/2)          # fov=40 → f≈2637 px
u = W/2 + f*x/z ; v = H/2 + f*y/z
```

`fill_width(z) = 2·z·tan(fov/2)` 用来算"在深度 z 处刚好铺满画面的宽度"，拆层和 hero shard 转场都靠它。

**纹理 `Tex`**：
- 预乘 alpha 的 RGBA float32。
- 四周留 3 px 透明边，这样透视变换后卡片边缘自动抗锯齿。
- 用 `cv2.pyrDown` 建 mipmap。大照片缩得很小时（隧道远处、魔方墙每格 72 px）选对应层级，不会闪烁。

**画一张 3D 卡片 `card()`**：
1. 投影四个角；有角的 z 小于 0.08 就不画（近裁剪）。
2. 求屏幕包围盒，**只在包围盒里做 warpPerspective**，所以耗时和卡片在屏幕上的面积成正比。
3. 按投影后的边长选 mip 层级：`lv = floor(log2(tex_w / 投影边长))`。
4. 可选：景深高斯模糊（包围盒先外扩 3σ）、光照增益、高光加色、透明度。
5. 以预乘 over 的方式合成：`reg *= 1 - a; reg += patch`；另外支持 add 和 screen 两种模式。

**画家算法 `Painter`**：收集（深度、绘制函数），从远到近画。立方体内部的几个面再单独按深度排序一次。

**光照 `shade()`**：Lambert 漫反射 + Blinn 高光，返回（增益、高光、是否正面朝向）。卡片翻到背面时，自动换背面纹理并镜像 ex，保证背面图不左右反。碎片翻转时一闪一闪的"反光"就是这里的高光项。

**景深 `coc()`**：`sigma = k·|1 - z_focus/z|`，并设上限。

### 2. 抠像与拆层（`cutout.py`、`subjects.py`、`sc2_layers.py`）

**模型选择**（下载前先实测过网络）：
- `storage.googleapis.com` 返回 200。
- HuggingFace、download.pytorch.org、dl.fbaipublicfiles.com、kaggle 全部连不上（000）。
- tfhub-lite 上的 MiDaS 深度模型返回 403。
- 所以**没有深度模型**，只能用 MediaPipe 的三个分割模型：deeplab_v3（2.7 MB）、selfie_multiclass_256x256（16 MB）、magic_touch（6.2 MB）。

**三个模型在教室合照 P019 上的实测**：
- deeplab_v3 的 person 类只是一团糊，不可用。
- selfie_multiclass 在多人合照上太粗。
- **magic_touch（给一个关键点，分出点下面的那个物体）效果最好**：单人边缘干净，头发、比耶的手、cos 服都能分出来。
- Haar 人脸检测给出的关键点有漏检也有误检（门框被当成人），所以最后改成**手选关键点**。这一步相当于 AE 里手动 roto 的描点。

**做法**：
- **局部裁切**：每个关键点带一个裁切比例（例如 `(0.39, 0.52, 0.45)`），模型只在点周围那一块上跑，每个人分到的像素多得多。
- **多点并集**：一个人给 2–5 个点（脸、躯干、手、腿），把各点的掩膜取并集。
- **修边**：用导向滤波（He et al.，灰度引导图）把边缘贴到照片的真实边缘上。模型的高置信核心保留，只在边缘带里采用滤波结果。
- **排他归属**：从近到远，每个像素只归离镜头最近、且覆盖它的那一层：`excl_i = m_i · Π(近层)(1 - m_j)`。这样重叠处不会出现双影。
- **补背景 `plate()`**：把人的区域膨胀 1.2%，用多尺度 push-pull 平滑填充，再和 600 px 小图上的 Telea 修补结果 5:5 混合，最后加一点噪声让补出的区域有纹理。
- 10 层抠像加补背景总共耗时 9.4 s，结果缓存成 16 位 PNG。

**2.5D 拆层的关键：等比缩放补偿**

```python
def plane(z, rect):            # 深度 z 处，与原照片子矩形 rect 投影重合的卡片
    hw, hh = z*TAN, z*TAN*9/16
    c = (((u0+u1)-1)*hw, ((v0+v1)-1)*hh, z)
    return c, ((u1-u0)*hw,0,0), (0,(v1-v0)*hh,0)
```

每一层离墙越远，就被等比放大多少。所以从起始机位看，11 层叠出来**和原照片逐像素一致**；镜头一动，视差才把深度暴露出来。这就是"拉片、分层"那种"原来是立体的"惊喜的来源。

**层次细节**：
- **分离节奏**：分三次拉开，落在 6.5 / 7.0 / 7.5 s，每次用弹簧曲线 `spring(t, 1.6, 6.0)`；最大间距 5.2。
- **纸片厚度**：每个人物层后面叠 3 片压暗到 30% 的切片。
- **投影**：人物 alpha 模糊 14 px，投到背景墙上，偏移量和该层的 z 成正比。
- **扫描线**：第 6.0–6.5 s 一道青色竖线扫过，扫过的地方人物描边亮起（描边 = 膨胀减腐蚀后的 alpha 边带）。
- **HUD**：每层的全画幅矩形画成线框，首尾两层对应的角用连线连成视锥；每个人头顶一个 `L07 / Z-0.72` 标签，带引线和圆点。

**出框**：
- 一张抠像拆成两张纹理："框内"（alpha × 在相框窗口内）和"框外"（alpha × 在窗口外）。
- 相框窗口故意裁得比人小（例如 P064 用 `(0.14, 0.30, 0.72, 0.85)`），头、比耶的手、挥舞的胳膊自然就在框外。
- 出框时人物层沿卡片法线抬起 `0.18·p`、放大 `1 + 0.05·p`，框外部分随 `p` 显现；投影只画在相纸窗口内。
- 拍立得本体绕 X 轴从 -85° 翻进来，用弹簧曲线 `spring(u, 1.3, 5.5)`，落在 9.0 / 9.5 / 10.0 / 10.5 s 的拍子上。

### 3. 碎裂、魔方墙、隧道（`sc1_shatter.py`、`sc3_cubes.py`、`sc4_tunnel.py`）

**碎月**：
- **种子分布像玻璃碎裂**：以撞击点 `(0.22, -0.16)` 为圆心排 10 圈，第 k 圈 `6+3k` 个点，半径每圈 ×1.42，角度带抖动。越靠近撞击点碎片越小。
- **Voronoi**：用 cKDTree 在 2048² 的月面上求最近种子，查询坐标加一点正弦扰动，让裂缝不那么直。一共 175 块碎片。另外用随机游走折线画了 26 条发丝裂纹。
- **裂纹逐拍推进**：裂纹前沿半径在 7 个拍点（1.0 → 3.5 s）依次扩到 0.16 / 0.34 / … / 1.6；每拍的推进用 `eout((t-tc)/0.22)` 缓动，并带一次亮度脉冲。
- **裂纹发光**：内核 + 3 px 和 14 px 两层模糊光晕，叠加到月面上。
- **爆开**：位移 `f(u) = (1-e^{-3u})/3·2 + 0.35u`，先爆后飘；每块碎片沿随机轴旋转。前 1.3 s 同时有 2.6 万颗月尘粒子飞出。
- **hero shard 转场**：
  - 位置、朝向、尺寸在 5.0–6.0 s 之间插值到"下一镜头机位前 3.0 处、铺满画面、背面朝镜头"。
  - 蒙版用 `distanceTransform` 算出的距离场，阈值 `u²·1150` 让碎片形状长成矩形，生长边缘带一圈金光。

**魔方墙**：
- 24×14 个立方体，每格贴图 72 px；棱长让整面墙正好铺满 z=10 处的画面。
- 每个立方体 4 个照片面加 2 个深灰侧面，背面剔除。
- 第 k 个面的朝向是 `R·Rx(-k·90°)`：立方体转到 `k·90°` 时，第 k 张照片正好正立地朝向镜头。
- 三种延迟场分别对应三次翻转（13 / 14 / 15 s）：中心涟漪 `dist·0.035`、对角扫 `(x+y)·0.02`、随机 0–0.5 s。
- 翻转曲线带阻尼回弹 `1 - e^{-5.5u}cos(2π·1.1u)`；翻转过程中立方体向镜头凸出 `sin(πu)·0.35`，避免和邻居穿插。
- **浮雕**（15.5 s 起）：每格的高度取当前那张照片在该格的亮度 × 2.2。
- **爆散**（16.0 s）：每个方块带随机速度和旋转轴，延迟随离中心的距离递增。

**时光隧道**：
- 120 张卡片排成螺旋：每张转 47°，前进 0.42，半径 1.7–2.9；每张向中轴倾斜 15–35°，看起来就是一条隧道。
- 每 9 张里有 1 张是视频卡。6 段视频先用 ffmpeg 转成 480×270、15 fps，存成 `.npy`，渲染时用 mmap 按帧读取。
- 镜头 z 是速度曲线的积分（600 Hz 采样）：
  - 基础速度 7，每拍额外加一次 `9·e^{-Δt/0.12}` 的冲刺；
  - 20.5–21.5 s 速度降到 10%（慢动作）；
  - 最后 1 秒再加 22 冲出去。
- 立体字"583"：14 层切片从后往前叠，越靠后越暗（增益 0.55 + 0.03k）；字面用渐变金色，加一圈腐蚀得到的倒角高光。
- 光速线：160 条线段，长度跟随当前车速，在半分辨率画布上用 `cv2.line`（shift=4 做亚像素）画，再叠一层高斯光晕。

### 4. 粒子归月（`sc5_moon.py`）：Trapcode Form 的解析版

**核心设计：每颗粒子的位置都是时间的解析函数，不做逐帧仿真。** 这样任意一帧都能独立渲染，4 个进程可以乱序并行，也不用存几百 MB 的轨迹。

- **粒子数**：合照 P032 缩到 640×360，一个像素一颗，共 230,400 颗，各自保留原色。
- **脱离时间**：`td = 24.5 + 1.5·clamp(0.8u + 0.35(fbm-0.5) + 0.1)`，从左往右烧，边缘被噪声撕得不规则。
- **还没脱离的部分**：照片仍然画成一张卡片，alpha = `td > t`，保证清晰；烧边宽 0.022 s，平方后更细。
- **三段轨迹，逐颗混合**：
  1. 吹散：`p0 + 漂移·τ^1.6 + 正弦湍流·(1-e^{-τ/0.5})`，一开始慢，像沙子。
  2. 星盘：双旋臂，`ρ ∈ [1.55, 3.45]`，初始角 `θ0 = arm·π + (ρ-1.55)·2.4`；差速旋转 `θ = θ0 + 2.6t/ρ^1.3`，内圈快、外圈慢；整个盘面倾斜 `Rx(-1.15)`。
  3. 收拢：每颗粒子带 0–0.55 s 的随机延迟，从 26.5 s 起沿 smoother 曲线收到球面前半球；颜色同时渐变成月面贴图上对应位置的颜色。
- **渲染**：
  - 双线性 splat，用 `np.bincount` 往 4 个邻近像素累加，比 `np.add.at` 快得多。
  - 叠一层 2 px 模糊作为光晕；刚脱离的粒子带一点橙色"余热"。
  - 27.5–28.3 s 把清晰的月亮卡片淡入到粒子下面，粒子同步减弱，完成"粒子 → 实体"的交接。
- **标题**：
  - 「碎月重圆」用思源宋体 Black，16 层切片挤出；落位用弹簧曲线 `spring(u/0.9, 1.0, 5.0)`，从 2.5 单位外飞入。
  - 28.5–29.3 s 一道斜向光带扫过字面。
  - 两行副标题依次上浮淡入。
  - 布局先在屏幕像素上定好（月心 y=380 px、半径 300 px、标题 y=770、副标题 890 / 950），再用 `y_w = (y_px-540)·z/f` 换算成世界坐标。

### 5. 后期、运动模糊与转场（`film.py`）

**运动模糊**：180° 快门（0.5 帧），在快门时间内等间隔采样若干个子帧再平均。采样数按镜头分配：

| 区间 | 采样数 |
|---|---|
| 碎裂后（4.0–6.0 s） | 4 |
| 拆层、出框、魔方墙翻转 | 2 |
| 爆散和隧道（16–24 s） | 4 |
| 粒子 | 3 |
| 甩镜 | 1（甩镜自己带方向模糊） |

**后期链**（顺序固定）：
1. 震屏：撞击点 16 / 8 / 18 / 12 / 6 / 5 px 并指数衰减；每次翻转 4 px、每次出框 3 px；隧道里每拍 3.5 px。
2. 缩放模糊：只在转场前的窗口里起作用。
3. 多尺度辉光：阈值 0.92，强度 0.4。
4. 变形镜头拉丝光：阈值 1.0，只让叠加光（亮度超过 1 的部分）起光。
5. 径向色差：常驻 2 px，撞击时最多 +14 px，隧道里随车速增加。
6. 闪白。
7. 高光肩部压缩：拐点 0.82。
8. 暗角 0.32，颗粒 0.012。
9. 分离色调：暗部偏青、亮部偏暖。

**甩镜**：把 A、B 两个镜头当成左右相连的长条，偏移量先 ease-in 再 ease-out，水平模糊核 `sin(πu)·260 px`。

**输出**：
- 分块渲染时以 x264 crf 10、yuv444p 存中间文件，写入前加 ±0.5/255 的随机抖动，防止光晕和渐变出现色带。
- 最终压制：2-pass，视频 7000k，音频 AAC 256k，`+faststart`。

### 6. 特效音与卡点（`sound.py`）

- 画面和声音共用 `cues.py`，每个视觉事件都有对应的声音：

  | 画面 | 声音 |
  |---|---|
  | 7 次裂纹 | 7 声冰裂（尖锐瞬态 + 7 个非谐 tink + 低频闷响），逐次加重 |
  | 碎裂 | 玻璃碎裂（90 个随机落点碎片音）+ 低频冲击 + 太鼓 + 镲 |
  | 扫描线 | 600→3200 Hz 扫频 |
  | 三次分层 | 三记通鼓 + whoosh |
  | HUD 标签 | 1800–2400 Hz 提示音，每 1/8 拍一个 |
  | 出框 | "啵"声 + 古筝 B–D–F#–A |
  | 立方体翻转 | 每 3 个立方体取一个，按它真实的翻转延迟排一声咔嗒，所以咔嗒声的波形和画面上翻转波的传播一致 |
  | 慢动作 | 音乐床低通到 500 Hz 并压低，底鼓停，心跳 + 钟声 |
  | 粒子吹散 | 流沙声 |
  | 星盘旋转 | 五声音阶星屑 |
  | 满月 | D 大调解决 + 古筝刮奏 + 钢琴 |

- **碎裂前的真空**：吸气声在 3.78 s 结束，3.78–3.988 s 整体静音（实测峰值 0.0），然后在 4.0 s 砸下来。
- **混音**：sidechain 只作用于 12 s 之后；先把峰值归一到 0.8 再做 tanh 饱和，然后做 LUFS 归一 + 5 ms 前视限幅。
- **结果**：整体 −12.49 LUFS，峰值 0.93。分段响度：

  | 区间 | LUFS |
  |---|---|
  | 0–4 s | −16.5 |
  | 4–6 s | −10.9 |
  | 6–12 s | −12.3 |
  | 12–16 s | −12.6 |
  | 16–18 s | −12.9 |
  | 18–24 s | −12.1 |
  | 24–28 s | −16.3 |
  | 28–30 s | −14.6 |

- **卡点验证**：用 librosa onset 检测对照 cue 表：
  - 裂纹、翻转、出框、撞击的 18 个点落在 8–22 ms 以内；
  - 6.0 s、24.0 s 两处是"riser / 反向镲接重击"，检测器没有报出 onset（偏差 474 / 223 ms），属于检测方法的局限，不是错位；
  - 9.0 s 偏 149 ms 是设计如此：出框声本来就在拍点后 0.12 s。

### 踩过的坑

**A. 运行环境与依赖**

1. **装 MediaPipe 后 OpenCV 版本被偷换**
   - 现象：`cv2.__version__` 显示 5.0.0，`putText` 报 `img.depth() == CV_8U` 断言失败。
   - 根本原因：mediapipe 1.0.1 依赖 opencv-contrib-python，于是装了 5.0.0.93，和原来的 opencv-python-headless 4.14 共用同一个 `cv2/` 目录，互相覆盖。
   - 解决：两个都卸载，只装 `opencv-contrib-python<5`（4.14，自带 CascadeClassifier 和 ximgproc）。
   - 预防：装任何带 cv2 依赖的包之后，立刻跑 `pip list | grep opencv`。

2. **`libEGL.so.1: cannot open shared object file`**
   - 现象：MediaPipe 一创建分割器就报这个错。
   - 根本原因：容器里没有 GL/EGL 运行库。
   - 解决：`apt-get install libegl1 libgles2 libgl1`。
   - 预防：写进 README 的环境步骤。

3. **MediaPipe 1.0 的 API 变了**
   - 现象：`InteractiveSegmenter.segment` 需要 strokes 参数，旧示例跑不通；返回的掩膜形状是 (h, w, 1)，布尔索引报维度错。
   - 根本原因：新版本的接口换了，关键点用法移到了 Legacy 类。
   - 解决：改用 `InteractiveSegmenterLegacy` + `RegionOfInterest(KEYPOINT)`，掩膜统一取 `[..., 0]`。
   - 预防：先 `inspect.signature` 看清接口再写代码。另外进程退出时打印的 `TypeError: 'NoneType' object is not callable` 是析构噪声，不影响结果。

4. **拿不到深度模型**
   - 现象：MiDaS 在 tfhub 上返回 403，HuggingFace、PyTorch Hub 都连不上。
   - 根本原因：网络策略限制。
   - 解决：放弃单目深度估计，改为"逐人抠像 + 人工指定每层深度"。这也正是 AE 设计师手工拆层的做法。
   - 预防：开工前先列出可用的模型源，按可用模型来设计特效。

**B. 抠像**

5. **自动分割在合照上不可用**
   - 现象：deeplab 输出一团糊；selfie 模型太粗；Haar 自动取点漏人，还把门框当成人。
   - 根本原因：这些模型的输入都是 256 左右的整图，合照里每个人只占几十个像素。
   - 解决：magic_touch + 手选点 + 局部裁切 + 多点并集 + 导向滤波修边。
   - 预防：主角照片的抠像一律人工给点，把"描点"当成 roto 工作的一部分。

6. **拆层后背景墙露出发糊的补色**
   - 现象：人物层拉开后，墙上原来站人的地方出现灰褐色糊团，右侧最明显（那里原来是深色裤腿）。
   - 根本原因：大面积洞口靠扩散类算法只能补出平均色，补不出结构。
   - 解决：减小绕转角度（-40° → -27°，俯仰 12° → 8°）；背景墙随分离程度压暗 30%、额外模糊 2.5 px；人物投影盖在洞口上。
   - 预防：选拆层照片时优先选人物背后是简单墙面的；拆层镜头的绕转角度不要超过 30°。这个瑕疵在成片里仍能看出来。

**C. 渲染与画面**

7. **碎裂前月面出现细黑缝**
   - 现象：完整的月亮上布满细网格线。
   - 根本原因：碎裂前也在画 175 块碎片，每块的抗锯齿边在交界处是半透明的，背景从缝里透出来。
   - 解决：碎裂前只画一整张月亮卡片，裂纹作为叠加层；从 4.0 s 起才换成碎片。
   - 预防：能用一张卡片表达的就不要拆成多张拼。拼接的地方要么重叠 1%（魔方墙起始时用 1.012 倍），要么用发光线盖住。

8. **碎裂后画面变空**
   - 现象：4.9 s、5.4 s 两帧几乎全黑，碎片早就飞出画面。
   - 根本原因：横向速度 1.2–3.2、纵向速度最大 9，再加上镜头推进 5.0，碎片不到 1 秒就全部离场。
   - 解决：横向速度改为 0.25–1.1，纵向速度改为 1.0–4.5 并按离撞击点的距离加权；位移曲线改成 `(1-e^{-3u})/3·2 + 0.35u`；镜头推进改为 2.6。
   - 预防：爆炸类镜头要算好"碎片在画面里停留多久"，并在爆后 0.5 s、1 s、1.5 s 各抽一帧检查。

9. **hero shard 太早变成矩形**
   - 现象：5.5 s 时碎片已经是整块矩形照片，失去了"碎片长成照片"的过程。
   - 根本原因：蒙版生长阈值 `u·900` 是线性的，而碎片轮廓放大到全画幅后本身已经很大。
   - 解决：阈值改成 `u²·1150`，前段慢、后段快。
   - 预防：用距离场做蒙版动画时，阈值一律用非线性曲线，并在 20%、50%、80% 进度处各看一帧。

10. **`round()` 报 `numpy.ndarray doesn't define __round__`**
    - 现象：hero 镜头渲染到 5.4 s 时崩溃。
    - 根本原因：缓动函数返回的是 0 维 ndarray，拿它当 lru_cache 的键前调用了 `round()`。
    - 解决：先 `float(...)`。
    - 预防：缓动函数的返回值只要当键用、当条件用或拿去 round，就先转成 float。

11. **缩放模糊在转场后一直不关**
    - 现象：成片级抽帧中，13.5 s 的魔方墙和整条隧道都被径向糊掉。
    - 根本原因：`smooth(seg(t, 11.6, 12.0))` 过了 12.0 s 之后仍然等于 1，不会回落。
    - 解决：乘上 `(t < 切点)`。
    - 预防：所有"转场前起作用"的窗口都写成"上升 × 截止"，并在窗口之后 1 秒抽帧确认。

12. **辉光把白墙点亮、拉丝光乱飞**
    - 现象：教室白墙整片发光，白衬衫拖出横向光条。
    - 根本原因：辉光阈值 0.78、拉丝光阈值 0.92，都低于照片里白墙的亮度。
    - 解决：辉光阈值改 0.92、强度改 0.4；拉丝光阈值改 1.0，只有叠加光（亮度超过 1 的部分）才会起光。
    - 预防：后期的阈值要按照片里最亮的"正常"区域来定，发光元素刻意做成亮度超过 1。

13. **碎裂瞬间曝光成一块白椭圆**
    - 现象：4.03 s 画面中间是一个过曝的白色椭圆。
    - 根本原因：场景内闪光（2.2 倍光晕 + 整体加 0.5）又叠上了后期的辉光和拉丝光。
    - 解决：场景内闪光降到 0.6 倍光晕 + 整体加 0.12，由后期负责剩下的亮度。
    - 预防：闪光只在一处定义强度，场景和后期不要各加一次。

14. **隧道卡片的白边像棉花一样发虚**
    - 现象：卡片的白色边框很软，像一圈光晕。
    - 根本原因：边框用的是 8×8 纯色纹理，3 px 透明边相对于 8 px 太宽，放大后边缘被拉成大片渐变。
    - 解决：纯色纹理改成 96 px。
    - 预防：透明边的宽度要远小于纹理尺寸，纯色卡片也不要用太小的纹理。

15. **魔方墙起始帧有网格缝，爆散后画面变空**
    - 现象：12.0 s 本该像一张平面照片，却有横竖细线；17.6 s 画面空无一物。
    - 根本原因：一是相邻格子的抗锯齿边重叠处透底；二是爆散速度太快（纵向 3–9），镜头又推进了 9。
    - 解决：棱长从 1.012 倍（互相重叠）到 0.94 倍（出现间隙）做动画；爆散速度改为 1.5–5.5、推进改为 4.5；16.2 s 起把隧道渲染在墙后面并淡入。
    - 预防：大转场的"空档"用下一个镜头来填，不要用黑场。

16. **出框镜头构图失衡、露出时间戳**
    - 现象：竖图 P085 的卡片大得出画；相纸右下角露出"2024/04/30 12:41"。
    - 根本原因：卡片宽度固定为 2.0，没有考虑宽高比；裁切框包含了相机时间水印。
    - 解决：卡片宽度按 `PW/√aspect` 缩放，保持面积接近；裁切框改为 x1=0.72、y1=0.85/0.84；魔方墙的 P032 用 cover 焦点 (0.5, 0.4) 把水印挤出画面。
    - 预防：选图时就标出时间戳水印的位置，所有裁切都避开。

17. **粒子只是一层雾，看不出漩涡**
    - 现象：26–27 s 粒子均匀铺满全屏，看不出形状。
    - 根本原因：第一版只是整体绕 y 轴旋转加湍流，没有形状目标。
    - 解决：改为双旋臂、差速旋转、倾斜 66° 的星盘，每颗粒子在脱离后 0.35 s 起被"捕获"进盘面；中心加一团原月光晕；亮度系数 0.55 → 1.15。
    - 预防：粒子每个阶段都要有明确的形状目标（平面 → 盘 → 球），不要只靠噪声。

18. **标题和副标题跑出画面、压在月亮上**
    - 现象：第一版的标题压着月亮下半部，金字落在浅色月面上看不清，副标题直接出了画面。
    - 根本原因：直接用世界坐标凭感觉摆放。
    - 解决：先在屏幕像素上定好版式（月心 380 px、半径 300 px、标题 770 px、副标题 890 / 950 px），再用 `y_w = (y_px-540)·z/f` 换算。
    - 预防：凡是需要"版式感"的元素（字、居中构图），一律先在屏幕空间设计。

19. **HUD 标签挤成一团**
    - 现象：绕转后所有层的左上角汇到一处，标签互相重叠，也太小。
    - 根本原因：标签挂在每层全画幅矩形的角上，而这些角在透视下会收敛到一起。
    - 解决：标签改挂在每个人自己的包围框上，加引线和圆点，字号从 0.45 调到 0.7。
    - 预防：HUD 元素要挂在"内容"上，不要挂在"画布"上。

**D. 音画同步与音效**

20. **碎裂前的"静音"其实没有静下来**
    - 现象：3.85–4.0 s 的最小 RMS 仍有 0.064。
    - 根本原因：静音门写成了以 3.93 s 为中心、宽 0.1 s 的 V 形，而且 V 形还被 max 运算盖掉了大部分。
    - 解决：改成硬窗口：3.78 s 用 30 ms 淡出，3.988 s 用 12 ms 淡入；吸气声提前到 3.78 s 结束。实测 3.8–3.98 s 峰值 0.0。
    - 预防：静音这种"效果"一定要实测峰值，不能只看公式。

21. **第一版母带峰值只有 0.507**
    - 现象：响度到了 −12.5 LUFS，峰值却只有 0.507，说明被压得太扁。
    - 根本原因：tanh 饱和作用在未归一化的大信号上，等于重度削波。
    - 解决：先把峰值归一到 0.8，再做 `tanh(1.25x)/1.25`。复测峰值 0.93。
    - 预防：任何非线性处理之前先把电平定好。

22. **笛子主旋律节奏错位**
    - 现象：代码审阅时发现旋律音长不对。
    - 根本原因：hook 的起点和时值都以"拍"为单位，传给 `dizi_line` 时只把起点换算成了秒，时值没换。
    - 解决：统一写成 `(o*0.5, d*0.5, m)`。
    - 预防：cue 表里注明单位；跨函数传时间一律用秒。

23. **onset 检测报"偏差 474 ms"**
    - 现象：6.0 s 和 24.0 s 两个重击点检测不到对应的 onset。
    - 根本原因：这两处是"riser / 反向镲 → 重击"，能量是连续上升的，onset 检测器不会报出这种点。
    - 解决：确认波形上重击存在后，判定为检测方法的局限，不是错位。
    - 预防：验证卡点时，把"渐强接重击"类的点单独用 RMS 阶跃来检查。

**E. 工具与流程**

24. **预览图读到旧缓存**
    - 现象：同名预览图重写后，看到的仍是旧画面。
    - 根本原因：图片读取工具会缓存同名文件。
    - 解决：每轮都用新文件名（s1_a / s1_b / film_a / film_b…）。
    - 预防：预览文件名带上轮次。

25. **长时间等待被拦截**
    - 现象：`sleep 240` 被拒绝执行；前台命令超过 10 分钟被自动转到后台。
    - 根本原因：运行环境禁止前台 sleep，单条命令也有时长上限。
    - 解决：渲染用 `nohup` 后台运行，用 `until ! pgrep -f render.py; do sleep 15; done` 这类循环等待完成。
    - 预防：超过 10 分钟的任务一开始就放后台跑。

26. **每个 worker 首帧都很慢**
    - 现象：首帧耗时隧道 47 s、魔方墙 22 s、碎月 14 s。
    - 根本原因：进程内的 lru_cache 不跨进程共享，每个 worker 都要重建贴图、解码视频。
    - 解决：月面、碎裂结果、粒子、视频帧都落盘成 `.npy` / `.pkl` / `.npz`，视频用 mmap 读取。
    - 预防：凡是超过 1 秒的预计算都落盘；分块时让每个 worker 拿到连续的帧段，同一镜头的缓存只建一次。

**F. 文件体积**

27. **颗粒、粒子和运动模糊都很费码率**
    - 现象：高频细节多，压缩后容易出现块状噪点。
    - 解决：颗粒只用 0.012；中间文件用 crf 10、yuv444p 并加抖动；最终 2-pass 7000k。成片 28.3 MB，低于 30 MB 的发送上限。
    - 预防：先定交付体积，再定颗粒强度，不要反过来。

**G. 验证方法本身**

28. **场景检测找不到任何剪切点**
    - 现象：`select='gt(scene,0.3)'` 在全片上没有输出。
    - 根本原因：这部片子没有硬切，转场全是连续的镜头运动、甩镜或闪白。
    - 解决：改为按 cue 时间点抽帧，逐一核对画面。
    - 预防：MG 片不用场景检测验证卡点，改用"cue 抽帧 + 音频 onset"两条线。

### 1. 代码 MG 动画制作流程模板

### 2. 给 AI 的开工提示词模板

```
请用代码（Python + numpy/OpenCV + ffmpeg，不用 AE、不用模板）为我做一段【时长】秒的 MG 动画，
素材是【路径】里的照片和视频。目标：看起来像顶尖 AE/C4D 设计师做的，而不是素材拼接。

创作要求
1. 自定主题，首尾两个镜头要是一对互逆动作；共【3–6】个镜头，每个镜头只炫一种主技术，
   从这些里选：3D 摄像机拆层（2.5D，起始帧必须与原照片逐像素一致）、人物出框、
   Voronoi 碎裂、MoGraph 式立方体墙、照片隧道、粒子重组、立体挤出文字。
2. 每个转场绑一个物理动作（碎片长成下一镜头、甩镜、穿过、白场），不能硬切了事。
3. 画面和原创配乐共用一张 cue 表（BPM 固定），每个视觉事件都要有对应音效。

技术要求
- 自写 3D 合成器：look-at 透视摄像机；预乘 RGBA 纹理 + mipmap + 透明边抗锯齿；
  只在包围盒内做单应性贴图；画家算法；景深；Lambert+Blinn；180° 快门子帧运动模糊。
- 每个镜头写成 render(t) 纯函数（粒子用解析轨迹），支持分块并行渲染和断点续渲。
- 抠像：先探测网络确认可用模型；主角照片用手选关键点 + 局部裁切 + 多点并集 + 导向滤波，
  多层之间做排他归属；补背景时拆层绕转角不超过 30°。
- 后期：辉光阈值按画面里最亮的正常区域来定，只让叠加光（亮度超过 1）起拉丝光；
  所有"转场前的窗口效果"都要写成"上升 × 截止"。

流程要求
- 每个镜头至少迭代 2 轮：抽 9 帧联系表 → 指出问题 → 改参数；
  转场两侧、爆炸后 0.5/1/1.5 秒、窗口效果结束后 1 秒都要抽帧。
- 版式元素（标题、副标题）先在屏幕像素上定位，再换算成世界坐标。
- 裁掉照片里的时间戳和黑边；大于 1 秒的预计算落盘缓存。
- 声音：静音窗口实测峰值为 0；非线性处理前先把电平定好；
  报告分段 LUFS 和 onset 对 cue 的偏差。
- 交付：【分辨率/帧率】，文件小于【体积】MB，按目标体积反推码率做 2-pass；
  从最终 MP4 抽帧核对；提交代码和 README（数字要和代码一致）。
- 老实说明做不到的地方（例如补背景的瑕疵、我无法试听音频）。
```
