# 华中大读书会《慢下来》代码视频 · 复盘经验总结（CoExp）

> 成片：竖屏 1080×1920 · 30fps · 37.0 秒 · H.264 + AAC · 20.8 MB
> 交付物：`华中大读书会_慢下来.mp4`、`华中大读书会_慢下来_代码版.html`（1.12 MB，自包含，可交互播放）、`华中大读书会_慢下来_源码.zip`
> 核心特点：**画面和音乐全部由同一个 HTML 文件里的代码生成**，没有任何图片、音频素材；浏览器预览和 MP4 导出用的是同一套代码、同一条时间轴。

## 一、创作思路

### 1. 需求如何拆成叙事结构

用户需求里有三组关键词，我把它们翻译成一条「能量曲线」：

| 用户原话 | 翻译成的设计约束 |
|---|---|
| 前期悠扬、优美、温馨，手绘/SVG，可爱；但 BGM 要生动、节奏快 | 画面「慢而暖」，音乐「快而轻」：120BPM，16 分音符音乐盒琶音，保证不拖沓 |
| 后期逐渐变快、爆燃、卡点、深度剪辑/拉片 | 换调换速：150BPM，重底鼓 + 侧链泵感，每拍一切；加入「拉片」段落 |
| 在快节奏中让大家慢下来；时代很快、短视频、AI | 在最高潮处**骤停**，然后用 10 秒做真正的「慢」，这是全片的主题句 |
| 空间变化、时间变化、书海气息、万物归一 | 空间：横向手卷移镜；时间：秋冬春夏刻度 + 季节背景；书海：B 段书单堆叠；万物归一：漩涡收成一个光点，结尾小图标落回书里 |
| 看完就想加入 | 片尾给出明确的行动号召：「来，慢下来读书。」+ 时间地点 |

最终的时间轴（数字全部是代码里的常量）：

```
0 ──── 2 ──── 4 ─ 6 ─ 8 ─ 10 ─ 12 ─ 14 ── 15 ── 16 ════════════ 25.6 ─ 26.4 ─────────── 37
│ 书被画出│ 标题 │邮寄│百团│分享│游园│童心│义卖│21天推镜│  B 段 爆燃（6 小节）  │骤停 │ C 段 慢下来 → 片尾
│ 音乐盒独奏  │ ← A 段 F 大调 120BPM，每 2 秒（1 小节）一个场景 →   │军鼓加花│ D 小调 150BPM │磁带停│ 钢琴放慢同一旋律
```

- **A 段 0–16s（8 小节 × 2s）**：一小节一个场景，转场卡在小节第一拍。
- **过渡 15–16s**：「21 天习惯养成」数字越跳越快，同时镜头推进、画面变暗，用来引出爆燃段。
- **B 段 16.0–25.6s（6 小节 × 1.6s，一拍 0.4s）**：每小节一种剪辑手法。
- **骤停 25.6–26.4s**：磁带停转音效后几乎无声，画面只剩一个光点。
- **C 段 26.4–37s**：一次只出现一句字幕，给观众留出阅读和情绪的空间。

> 时长说明：用户要求「30 秒左右，可弹性」，最终做了 37 秒。多出来的时间基本都给了 C 段，因为主题靠这里的留白来成立。如果要压到 30 秒，可以删掉 C 段的「世界很快」一屏，并把片尾缩到 2.5 秒。

### 2. 各段落/场景的设计意图

**开场（0–4s）**
- 0–1.5s：墨线把一本打开的书画出来（线条逐步显现）。一开场就定下「手绘、纸张、温暖」的基调。
- 0.55–1.9s：书里垂下一根**红色书签丝带**，落地后向左右延伸，变成全片的地平线。这是整片唯一的视觉主线（「一根线」），同时也是「万物归一」的伏笔。
- 2.0s（第一个强拍）：毛笔字「以书为媒 / 让思想在喻园生长」从左到右写出来，书页随节拍翻动，书脊长出一株嫩芽（呼应「生长」），盖一枚「喻园」印章，一个小人从书后探头挥手。

**A 段各场景（4–16s）**：场景按「一个学年」排序，而不是按原文顺序，这样才能表现时间在流动：

| 时间 | 场景 | 时间感/空间感 | 画面上的卡点 |
|---|---|---|---|
| 4–6 | 时光邮寄 | 开学季 · 韵苑/紫菘；日历 2026→2027（时间向前） | 第 3 拍盖火漆印，第 4 拍信封飞走、日历翻页 |
| 6–8 | 百团大战 | 十月中旬 · 东西操场 | 三个对话泡泡分别落在第 2/3/4 拍 |
| 8–10 | Sunlight 分享会 | 季节换成冬（冷色背景、雪点） | 太阳升起，三张金句卡依次落在拍点上 |
| 10–12 | 游园会 | 春（绿色背景、花瓣） | 四个印章按 8 分音符连续盖下，最后盖「通关」 |
| 12–14 | 童心拾忆 | 夏；蜡笔画风（时间回到童年） | 纸飞机绕圈，风筝的线就是红色主线的颜色 |
| 14–15 | 图书义卖 | 夏 | 书沿抛物线从书架飞到人手里，冒出爱心 |
| 15–16 | 21 天习惯养成 | 一学年结束 | 天数跳动加速，镜头推进放大 8 倍，画面变暗 |

- 固定 HUD：顶部品牌条，底部「秋·冬·春·夏」刻度（红点随镜头移动）。
- 背景色随镜头位置在 7 个季节色之间插值；飘落粒子（落叶/雪/花瓣/光点）按季节权重混合。这样即使画面持续横移，也能感到时间在变。

**B 段爆燃（16–25.6s）**，一个小节一种剪辑语言，避免一招用到底：

| 小节 | 时间 | 内容 | 手法 |
|---|---|---|---|
| 1 | 16.0–17.6 | 巨大的「读」字砸下 → 13+ 年 → 600+ 场 → 20000+ 人次 | 冲击波圆环、放射速度线、RGB 分离、数字 0.22 秒内快速滚到目标值 |
| 2 | 17.6–19.2 | **拉片**：A 段场景变成竖向胶片帧 | 每拍前半拍定格并出分析框（红色角标、三分线、TIME/SPACE 标签），后半拍甩切到下一帧，带残影 |
| 3 | 19.2–20.8 | 共读书单 8 本 | 每半拍（0.2s）砸下一本书封，前面的书缩小散落成「书海」 |
| 4 | 20.8–22.4 | 物理系的逻辑 × 哲学院的思辨；医学生的严谨 × 文学院的浪漫 | 上下两句对撞，在拍点上爆出火花、闪白、屏幕震动 |
| 5 | 22.4–24.0 | 四个部门逐拍点亮 | 2×2 网格，放大弹出 |
| 6 | 24.0–25.6 | 「倍速 ×2…×128」「AI 一键总结」「下一条」刷屏 → 所有文字卷入漩涡收成一个点 | 16 分音符刷词，漩涡转速按 e^t 加速，中心光晕放大 |

- 第 6 小节是叙事转折：前 5 小节展示读书会的能量，第 6 小节把能量推成「时代太快」的压迫感，给后面的骤停提供理由。

**骤停 + 结尾（25.6–37s）**
- 25.6s 闪白 → 黑屏上一个呼吸的光点，音频做「磁带停转」，然后近乎静音 0.8 秒。**反差越大，「慢」越有力。**
- 26.4s 响起一个钢琴单音，光点变成一滴水，纸张以涟漪形式从中心铺开（圆形 clip 半径 0→1300）。
- 字幕一次只出现一句：「世界很快。」+「短视频十五秒，AI 一秒给出总结。」→ 巨大的毛笔字「慢」（从上往下扫出）+「在最快的时代 / 做一件最慢的事」→ 红线重新画出书，活动小图标（信封、帐篷、太阳、爱心、纸飞机、风筝、星星）旋转着落进书里（万物归一），配「读前人走过的路，写自己的下一页。」（对应用户说的「学习前辈经验并升华」）→ 片尾品牌 + 「来，慢下来读书。」+ 印章 + 招新时间地点。
- **音乐上的点题**：C 段钢琴弹的就是 A 段钟琴的主旋律，只是速度放慢（8 分音符从 0.25s 变成 0.4s）。同一段旋律，快的时候是热闹，慢的时候是回味。

### 3. 节奏、剪辑与音画配合的技巧

1. **转场落在强拍上**：横移镜头从小节线前 0.3 秒开始，用 `easeInOutQuart` 在小节线后 0.08 秒落定，whoosh 音效从前 0.34 秒开始。观众感觉「画面被节拍推进去」。
2. **动作卡在拍点，而不是只卡在小节**：印章、泡泡、卡片都落在第 2/3/4 拍或 8 分音符上；这些时刻都配了 `thump` 或 `tick`。A 段虽然画面温柔，但全程有「咔哒」感，满足了「前期节奏也要快」的要求。
3. **同一个时间常数驱动画面和声音**：例如 21 天计数，画面上天数的切换时刻和音频里的 tick 时刻都来自同一个函数 `dayTimes()`，因此能做到逐帧对齐。
4. **能量阶梯**：音乐盒独奏 → 加底鼓/拍手/拨弦 → 第 5 小节加铃鼓 → 军鼓从 8 分加到 16 分再到 32 分 + 噪声 riser → 爆点冲击音 → 150BPM 重底鼓 + 侧链 → 最后一小节再加军鼓滚奏和 riser → 骤停。每 2–4 秒都会多一层，不会停在同一个能量平台上。
5. **每拍的冲击感（punch）**：B 段每拍画面缩放 `1+0.07·e^(-Δt/0.06)`，小节第一拍额外震屏 26px 并闪白 0.85。底鼓经过 tanh 失真，和画面的冲击同时出现。
6. **侧链泵感**：B 段的超级锯齿和弦每拍把增益压到 0.22，0.3 秒内回到 1，形成 EDM 式「呼吸」，听起来就是爆燃。
7. **反差骤停**：高潮顶点直接切进磁带停转（所有频率在 0.62 秒内滑落到 7%）+ 静音。这是全片最重要的剪辑点。
8. **慢段的节奏也是设计过的**：逐字出现（每字 0.06–0.13s），一屏一句；关键动作仍然卡在钢琴和弦上（例如 34.0s 终止和弦同时盖章、出现片尾标语）。

## 二、具体的创作方式

### 1. 技术栈与整体工作流

| 环节 | 工具 |
|---|---|
| 资料 | WebSearch / WebFetch + 用户提供的 `华科读书会5.0.html`（Python 正则去掉标签后提取纯文本） |
| 画面 | 原生 **Canvas 2D**（1080×1920），不用任何框架；SVG path 字符串 → `Path2D` 绘制，同时用隐藏的 `<svg><path>` 获取 `getTotalLength / getPointAtLength` |
| 音乐 | 原生 **Web Audio API** 合成器（振荡器、噪声、滤波器、卷积混响、压缩器）；实时预览用 `AudioContext`，导出用 `OfflineAudioContext` |
| 字体 | npm `@fontsource/*`（马善政、站酷快乐体、站酷庆科黄油体、龙藏体、思源宋体 400/700/900）+ Python `fontTools`（+`brotli`）裁字 |
| 渲染 | Python **Playwright**（容器预装 Chromium），逐帧调用 `window.__frame(t)` 拿 JPEG |
| 编码 | **ffmpeg**：`image2pipe` 从标准输入读帧，libx264 + AAC |
| 检查 | 抽帧脚本 + PIL 拼成缩略图总览（contact sheet），一次查看 10–27 帧；numpy 按段落统计音量 |

完整步骤：

1. 读用户 HTML，提取纯文本（活动、部门、书单、数据、口号）。
2. 网络搜索（8 次左右），确认外部公开资料很少，因此内容以用户 HTML 为准。
3. 写分镜：时间轴 + 每段的画面/音乐/卡点（本文第一部分的表格就是当时的分镜）。
4. 查环境：`fc-list :lang=zh`（只有 Noto Sans CJK）、`which ffmpeg`、Playwright 是否可用、Google Fonts 是否能访问（403）。
5. 装字体：`npm install @fontsource/...`。
6. 一次性写出 `video.src.html`（约 1100 行，包含画面引擎 + 7 个场景 + B/C 段 + 合成器 + 乐谱 + 播放器）。
7. `build.py` 裁字、内嵌字体，生成 `video.html`。
8. `snap.py` 抽关键帧 → 拼成总览图查看 → 修改 → 重复（本次共 3 轮：A 段 11 帧、B+C 段 27 帧、修复后 6 帧）。
9. `render.py`：先离线渲染音频 → WAV，再逐帧渲染并通过管道送进 ffmpeg。
10. 用 numpy 检查音频分段 RMS/峰值/削波；用 ffprobe 检查时长和编码。
11. 超过上传限制时重新压缩 → 交付；最后打包源码。

**核心原则：确定性渲染，`render(t)` 是纯函数。**
画面只由时间 t 决定：不读 `Date.now()`，不用 `Math.random()`，不保存上一帧的状态。因此可以任意跳到某一秒、逐帧导出，预览和导出结果完全一致。

```js
function render(t){
  TIME=t; BOIL=Math.floor(t*8);          // 手绘线条「抖动」按 8fps 更新
  ctx.setTransform(1,0,0,1,0,0); ctx.globalAlpha=1;
  if(t<B0) partA(t); else if(t<B_END) partB(t); else partC(t);
}
// 所有「随机」都来自整数哈希，保证每次结果相同
function hash(n){n=(n|0)^0x9e3779b9;n=Math.imul(n^(n>>>16),0x85ebca6b);
  n=Math.imul(n^(n>>>13),0xc2b2ae35);n^=n>>>16;return (n>>>0)/4294967296}
// 工具：把时间映射到 0..1 的进度
const P=(t,a,b)=>clamp((t-a)/(b-a));
```

**动画写法统一为「时间窗 + 缓动」**：`eOB(P(lt, 0.5, 0.8))` 表示本场景第 0.5–0.8 秒回弹弹出。每个场景函数接收本地时间 `lt = t - SC_T[i]`。

**手绘线条的逐步显现 + 线条抖动（line boil）**：

```js

  const el=document.createElementNS(svgNS,'path');el.setAttribute('d',d);svgEl.appendChild(el);

  const Q=PATHS[name]; ctx.save(); ctx.lineCap=ctx.lineJoin='round';
  ctx.strokeStyle=o.color||INK; ctx.lineWidth=o.w||5;
  const s=BOIL*31+Q.id*7, j=1.3;
  if(o.fill){/* 填色：略微错位，模拟水彩 */}
  if(p<1) ctx.setLineDash([Q.len*p, Q.len+10]);           // 核心：用虚线长度控制画了多少
  ctx.save(); ctx.translate((hash(s+2)-.5)*j*2,(hash(s+3)-.5)*j*2); ctx.stroke(Q.p); ctx.restore();
  ctx.globalAlpha*=.33; ctx.lineWidth*=.55;                  // 第二笔：更淡更细、错位，形成手绘双线
  ctx.translate((hash(s+4)-.5)*j*5,(hash(s+5)-.5)*j*5); ctx.stroke(Q.p); ctx.restore();

```

**音乐调度：同一份乐谱，既能实时播放，也能离线渲染，还能从中途开始**：

```js
class Music{
  constructor(ac,dest,offset,t0){this.ac=ac;this.off=offset;this.t0=t0;/* 建总线/压缩器/混响/侧链 */}
  at(t){ if(t<this.off-.001) return null; return this.t0+(t-this.off); } // 乐谱时间 → AudioContext 时间
  kick(t,v,hard){const w=this.at(t); if(w==null) return; /* 创建节点并定时 start/stop */}
}
// 实时播放：t0=ac.currentTime+.08；画面时钟 = off + (ac.currentTime - t0)  ← 以音频时钟为准，永远同步
// 导出：new OfflineAudioContext(2, sr*DUR, 44100)，offset=0,t0=0 → startRendering()
```

**播放器**：浏览器必须有用户点击才能出声，所以加了一个「▶ 播放」遮罩；控制条支持暂停（关闭 AudioContext 并记录 off）、点击进度条跳转（按新的 offset 重建 Music，只调度 t ≥ offset 的事件）、空格键暂停。URL 参数 `?t=17.9` 可以直接停在某一秒，`?render=1` 进入渲染模式（隐藏 UI）。

### 3. 各种视觉风格的代码实现

| 风格 | 实现 |
|---|---|
| 手绘线稿 | `ink()`：`setLineDash([len*p, len])` 控制线条显现 + 按 8fps 的哈希错位双线（boil） |
| 水彩填色 | `ink(...,{fill})`：填充时随机偏移 ±2.6px，并且在描线画到一半以后才淡入 |
| 蜡笔画（童心拾忆） | `crayon()`：同一路径描 3 遍，每遍 alpha 0.5 并错位约 5px；`hatch()`：用路径 clip，再画斜线排线 |
| 毛笔字书写 | `brush()`：用 `rect` clip 从左往右扫出（宽度×进度）。「慢」字从上往下扫，边缘加一条半透明椭圆，模拟墨迹前沿 |
| 逐字出现 | `charsIn()`：先 `measureText` 算出每个字的宽度，再让每个字按错开的时间上浮并淡入 |
| 纸张质感 | 启动时预渲染一张 1080×1920 的离屏 canvas：14000 个杂点 + 500 条纤维曲线 + 暗角，每帧叠加一次 |
| 季节 | 背景 7 色按 `camX/W` 插值；落叶用 `leaf` 路径，雪/花瓣/光点用程序化粒子，位置 = `hash(i)`·范围 + t·速度，取模循环 |
| 可爱小人 | `buddy()`：圆头、圆角身体、腮红、眨眼/笑眼，按拍 `|sin|` 弹跳，四肢端点每帧轻微抖动 |
| 爆燃文字 | `gtext()`：用 `screen` 混合模式，把红色（左偏）和青色（右偏）两层叠在白字下面，形成 RGB 分离；偏移量随拍后时间衰减 |
| 冲击 | 每拍缩放 punch、震屏（按帧号哈希）、放射速度线、冲击波圆环、闪白 |
| 拉片 | `miniScene(k,cx,cy,0.5,lt)`：把 A 段场景函数缩小到 0.5 倍重新绘制成胶片帧（clip + scale）；胶片带和齿孔随位置滚动；分析层用红色角标、三分线、TIME/SPACE 标签 |
| 胶片感 | 预先生成 540×960 的颗粒噪声图，每帧随机偏移后放大绘制；每隔 6px 画一条扫描线 |
| 漩涡 | 每个词有初始角度和半径；角度 += `rot*(1+300/r0)`（越靠内转得越快），半径 × (1 - eIE(p))，中心光晕半径随 p 增长 |
| 涟漪转场 | 黑底上画圆形 clip，半径用 eOC 从 0 到 1300；clip 内绘制 C 段纸面和内容，并画 3 圈同心涟漪线 |

### 4. 音频处理

**信号链**：各乐器 → `master`(0.8) → `DynamicsCompressor`（阈值 −10dB，比率 6，knee 6，attack 3ms，release 120ms）→ `out`(0.9) → 输出。
另有三条总线：`revIn`→卷积混响（3.2 秒，用哈希噪声 × (1−i/n)^3.2 生成冲激响应）、`pump`（B 段超级锯齿专用，做侧链）、`drum`（鼓组；硬底鼓先经过 tanh(2.6x) 的 WaveShaper）。

**乐器合成配方（可直接复用）**：

| 乐器 | 配方 |
|---|---|
| 音乐盒 | 正弦 f（衰减 1.1s）+ 正弦 4f（×0.1，0.12s）+ 三角波 2f（×0.1）；送混响 0.45 |
| 钟琴 | 正弦 f（0.9s）+ 正弦 2.76f（×0.22）+ 正弦 5.4f（×0.06） |
| 拨弦贝斯 | 三角波 + 正弦，低通 900Hz，衰减约 0.25s |
| 软底鼓 / 硬底鼓 | 正弦频率从 125→52Hz（0.12s）/ 170→42Hz（0.09s），硬底鼓经过失真并加 10ms 高通噪声「咔」声 |
| 响指 / 拍手 / 军鼓 | 带通噪声（1.4–2.6kHz），拍手连续 3 个短脉冲再接尾音，另加三角波 190–220Hz 作为鼓身 |
| 沙锤 / 踩镲 / 镲片 | 高通噪声 7k / 8k / 4.2k，衰减分别为 0.045 / 0.035（开镲 0.16）/ 1.7s |
| 超级锯齿（B 段和弦） | 每个音 5 个锯齿波，失谐 ±16/±7/0 音分，低通 3600Hz，接 pump 总线 |
| 侧链 | 每拍 `pump.gain.setValueAtTime(.22,w); linearRampToValueAtTime(1,w+.3)` |
| Sub 贝斯 | 正弦 + 锯齿（×0.4），低通 320Hz，放在反拍 |
| Lead | 方波，低通滤波从 5200 快速降到 900Hz（0.09s），16 分音符琶音 |
| 钢琴（C 段） | 正弦 f/2f/3f，衰减时间依次减半，加三角波起音和一点带通噪声作为击槌声；送混响 0.7 |
| Riser | 循环噪声，带通从 300→9000Hz 指数扫频，增益指数上升；叠加锯齿波 110→880Hz |
| Whoosh | 带通噪声，频率 400↔5000Hz 扫频，时长 0.18–0.8s |
| 冲击音 | 正弦 75→28Hz（1.2s 衰减 1.6s）+ 低通噪声 + 镲片 + 硬底鼓 |
| 磁带停 | 和弦锯齿频率在 0.62s 内指数降到 7%，低通 6000→150Hz，加一个 90→20Hz 的低音 |

**乐谱与卡点对应**：
- A 段：F–F–C–Dm–Bb–F–C–(Bb→C) 每小节一个和弦；16 分音符琶音模式 `[0,1,2,3,2,1,2,3,0,1,2,3,3,2,1,2]`；钟琴主旋律为 8 分音符。
- 场景转场 whoosh：`for x of [4,6,8,10,12,14] whoosh(x-.34,.4,.09)`。
- 盖火漆印 `thump(7.0)`；游园会印章 `thump(10.5/10.75/11.0/11.25)` 以及 `11.5` 更重；21 天计数的 tick 与画面共用 `DAYT`。
- 15–16s：军鼓间隔从 0.125 → 0.0625 → 0.03125 秒加速 + riser 14.5–16。
- B 段：Dm–Bb–F–C–Dm–(Bb→C)；每拍硬底鼓 + 泵感；拍手在第 2/4 拍；开镲和 sub 在反拍；小节首拍镲片；拉片小节每拍 +0.2s 放 whoosh；对撞时刻 21.2/22.0 加底鼓和镲片；最后一小节 riser + 军鼓从 0.1 → 0.05 → 0.025 秒滚奏。
- 25.6 磁带停 → 26.4 钢琴单音 A5 → 放慢的主旋律 → 34.0 终止和弦（F 大调分解和弦 + pad + 音乐盒闪光 + 盖章音）。
- 淡出：`out.gain` 在 36.2→37.0 线性降到 0。

**实测音量（numpy 分段统计）**：A 段 RMS −18dB，B 段 −10.4dB（峰值 0dBFS），骤停段 −16.4dB，C 段 −16.8dB；削波样本比例 6×10⁻⁷，可以忽略。A、B 两段相差 8dB，这是有意制造的爆燃反差。

### 5. 渲染与导出命令

**字体裁剪（build.py 核心）**：

```python
opts = subset.Options(); opts.flavor='woff2'; opts.layout_features=['*']
sub = subset.Subsetter(opts); sub.populate(text=used_chars); sub.subset(font)
# 每个字体取 {pkg}-chinese-simplified-{wgt}-normal.woff2 和 -latin- 两个文件，各自裁剪后 base64 写入 @font-face
# 同时把字符集注入成 JS 常量 CHARS，供 document.fonts.load(font, CHARS) 预加载
```
结果：7 个字重/字体共 786 KB，最终 HTML 为 1.12 MB。

**逐帧渲染 + 合成（render.py 核心）**：

```python
wav = await pg.evaluate('window.__renderAudio()')   # OfflineAudioContext → 16bit WAV → base64
open('audio.wav','wb').write(base64.b64decode(wav))
ff = subprocess.Popen(['ffmpeg','-y','-loglevel','error',
   '-f','image2pipe','-framerate','30','-c:v','mjpeg','-i','-',
   '-i','audio.wav',
   '-c:v','libx264','-preset','medium','-crf','18','-pix_fmt','yuv420p',
   '-c:a','aac','-b:a','192k','-movflags','+faststart','-shortest','out.mp4'], stdin=subprocess.PIPE)
for i in range(int(37.0*30)):                         # 1110 帧
    d = await pg.evaluate(f'window.__frame({i/30})')   # canvas.toDataURL('image/jpeg',.93)
    ff.stdin.write(base64.b64decode(d.split(',')[1]))
```

- 视口设为 1080×1920；帧数据通过管道直接送给 ffmpeg，不落盘。
- 第一版 CRF 18 输出 **36.9 MB**，超过聊天附件 30 MB 的上限，于是重新压缩：
  ```bash
  ffmpeg -i out.mp4 -c:v libx264 -preset slow -crf 22 -pix_fmt yuv420p -c:a copy -movflags +faststart out2.mp4   # → 20.8 MB
  ```
- 检查：`ffprobe -v error -show_entries format=duration:stream=codec_name,width,height -of compact out.mp4` → h264 1080×1920 / aac / 37.000000。

### 2. 踩过的坑

**坑 1：外部字体 CDN 被拦截**
- 现象：`curl https://fonts.googleapis.com/...` 返回 `CONNECT tunnel failed, response 403`，gstatic 也访问不了；容器里只有 Noto Sans CJK，没有书法体、手写体、宋体。
- 原因：沙箱出网走白名单代理，Google Fonts 不在白名单里；而 npm registry 在白名单里。
- 解决：`npm install @fontsource/ma-shan-zheng @fontsource/zcool-kuaile @fontsource/zcool-qingke-huangyou @fontsource/long-cang @fontsource/noto-serif-sc`。每个包里有 90 多个按 unicode-range 切分的小文件，也有一个完整的 `*-chinese-simplified-400-normal.woff2`（1.5–2.7 MB）。取完整文件 + latin 文件，用 fontTools 只保留页面用到的 498 个字符，base64 内嵌。
- 预防：开工前先测 CDN；中文字体一律走「npm 包 + 裁字 + 内嵌」方案，成品 HTML 不依赖任何网络。

**坑 2：裁字后新增文字会变成回退字体**
- 现象（风险）：修改文案时如果出现新汉字，`video.html` 里没有这个字，画布会用系统字体渲染，风格不一致。
- 原因：`build.py` 按源码当时出现的字符集裁字。
- 解决：每次改文案后重新运行 `build.py`（README 里已写明）；字符集从整个源码文件自动收集，不需要手动维护。
- 预防：把「改文案 → 重新构建」写进流程；也可以在构建时额外加入常用 3500 字作为保险（代价是体积变大）。

**坑 3：画布文字在字体加载完成前绘制**
- 现象（风险）：Canvas 不会等字体下载，首帧可能是回退字体。
- 解决：启动时对每个字体族、每个字重调用 `document.fonts.load('40px KL', CHARS)`，然后 `await document.fonts.ready`，最后再设置 `window.__ready=true`；渲染脚本用 `wait_for_function('window.__ready===true')` 等待。
- 预防：固定使用「__ready 握手」模式。

**坑 4：拉片缩略图里的地面线和场景对不上**
- 现象：写 `miniScene` 时，红线用局部坐标 `drawThread(-60,W+60)` 画，而场景里的小人用 `gy(k,x)=threadY(k*W+x)` 取世界坐标下的地面高度，两条线的起伏会错开。
- 原因：主画面用的是世界坐标（场景 i 平移到 i×W），缩略图却忘了做同样的偏移。
- 解决（首次渲染前自查时发现并修复）：`ctx.translate(-k*W,0); drawThread(k*W-60, k*W+W+60)`。
- 预防：一个场景的所有元素都走同一个坐标换算函数；复用场景函数时写一个断言或对比帧。

**坑 5：「万物归一」的小图标太大，挡住了字幕**
- 现象：31.1s 的抽帧中，帐篷屋顶（路径宽 620）、信封等图标在 0.55 倍缩放下有 300 多像素宽，飞过「读前人走过的路」这一行字。
- 原因：不同图标的路径原始尺寸差别很大，却用了同一个缩放系数；运动轨迹的纵向半径（0.9）太大，扫到了字幕区。
- 解决：缩放改为 `lerp(.32,.05,e)`，大图标再乘 0.75、小图标乘 1.2；纵向半径改为 0.55；加上自转。重新抽 31.1/31.4s 两帧确认。
- 预防：图标路径统一归一化到约 100px 的包围盒；飞行元素的轨迹要避开字幕的安全区。

**坑 6：导出的 MP4 超过附件上限**
- 现象：`SendUserFile` 报错 `36.9 MiB exceeds the 30 MiB upload limit`。
- 原因：CRF 18 + 大量颗粒噪声、扫描线（噪声非常吃码率）+ 1080×1920。
- 解决：`-preset slow -crf 22 -c:a copy` 重新压缩到 20.8 MB，肉眼几乎看不出差别。
- 预防：先确认交付上限；直接用 CRF 20–22 + preset slow 导出；或者降低颗粒层透明度，减少高频噪声。

**坑 7：浏览器自动播放限制**
- 现象（设计阶段已规避）：`AudioContext` 在没有用户手势时处于 suspended 状态，打开页面不会有声音。
- 解决：加一层全屏「▶ 播放」遮罩，点击后才创建 AudioContext；画面时钟以 `ac.currentTime` 为准。
- 预防：代码视频的交互版一律用「点击开始」。

**坑 8：音画同步**
- 风险：如果画面用 `requestAnimationFrame` 的时间戳或 `performance.now()` 计时，而声音按 AudioContext 调度，时间一长就会漂移。
- 做法：实时播放时 `t = off + (ac.currentTime - t0)`，画面跟随音频时钟；导出时画面按 `i/30` 逐帧渲染，音频用 OfflineAudioContext 独立渲染，二者都从 t=0 起算，ffmpeg 直接合成，不会漂移。
- 细节：用同一个函数 `dayTimes()` 生成画面的跳数时刻和 tick 音效时刻，做到逐帧对齐。

**坑 9：Web Audio 调度的细节**
- `exponentialRampToValueAtTime` 不能从 0 开始或结束 → 起点和终点都用 `0.0001`。
- 同一个 AudioParam 上的自动化事件必须按时间顺序写入 → 侧链 `pumpAt` 按小节、按拍的顺序循环调用。
- 从中途播放 → `at(t)` 对 `t < offset` 的事件直接返回 null；代价是跨越 offset 的长音会丢失（可以接受）。
- 噪声、混响冲激响应也用 `hash` 生成，保证离线渲染每次结果相同。

**坑 10：网页资料抓取失败**
- 现象：湖北文明网报 `robots.txt fetch failed: SSL WRONG_VERSION_NUMBER`；搜狐报 `URL is disallowed by robots.txt`；思政网只返回 WAF 元数据，没有正文。
- 处理：不绕过限制，改用能打开的华科新闻网页面，并以用户 HTML 为主要内容来源，在交付时说明资料边界。
- 预防：搜索阶段就区分「学生读书会」和「图书馆/院系读书会」；公开资料少时尽早告诉用户，并请用户提供推文或照片。

**坑 11：时长超出预期**
- 现象：用户要求约 30 秒，成片 37 秒。
- 原因：C 段需要留白（26.4–37s 共 10.6 秒）；另外 A 段的 7 个场景各需 2 秒才能看清。
- 处理：在交付说明里解释原因，并给出压缩方案。
- 预防：分镜阶段就把总时长算出来给用户确认；B 段固定 9.6 秒（6 小节 × 1.6 秒），最容易调整的是 C 段。

**坑 12：渲染速度不均匀**
- 现象：普通帧约 90ms，拉片段约 190ms/帧（每 150 帧耗时从 13s 涨到 29s）。
- 原因：拉片段每帧重画 4 个缩小场景 + 残影（最多约 7 次完整场景绘制），每次都叠加 1080×1920 的纸张纹理。
- 预防：缩小场景缓存到离屏 canvas；残影只在甩切的 0.18 秒内绘制（本次已经这样做）。

**坑 13：打包时 sed 命令写错**
- 现象：`sed: -e expression #1, char 40: unknown option to 's'`。
- 原因：替换内容里含 `#`，而 sed 也用 `#` 作分隔符。
- 解决：改用 `|` 作分隔符。
- 预防：批量改路径时优先用 Python 读改写，不用 sed。

**坑 14：构建产物不是逐字节可复现的**
- 现象：在新目录重新构建后，字体总字节数为 786664，原来是 786556，md5 对比不一致。
- 原因：fontTools 生成 woff2 时会写入时间戳等元数据，压缩结果略有差异；功能完全一样（抽帧无报错、画面一致）。
- 预防：验证构建产物时比对「抽帧画面」或「字符覆盖」，不要比对文件 md5。

**坑 15：AI 无法真正「听」**
- 现实限制：无头环境没有声卡，AI 只能用 RMS/峰值/削波这些数字判断音频，无法判断「好不好听」、混音是否浑浊。
- 预防：交付说明中请用户试听；需要调整时让用户描述问题（例如「鼓太吵」「A 段太闷」），对应去改 `score()` 里的 v 参数。

**坑 16：输出目录是符号链接**
- 现象：`/mnt/user-data/outputs` → `/mnt/attach/outputs`；用 `cp` 放进去的文件不会自动出现在聊天里。
- 解决：`cp` 之后调用 `SendUserFile`（只有直接用 Write/Edit 写入的文件才会自动显示）。

### A. 代码视频制作流程模板

```
0. 需求 → 约束表
   - 画幅/分辨率/帧率：1080×1920 @30（竖屏）或 1920×1080 @30
   - 总时长上限、交付大小上限（如 30MB）、交付形式（MP4 / 交互 HTML / 源码）
   - 情绪曲线关键词 → 每段的 BPM、调性、画风

1. 资料
   - 优先使用用户文件（HTML/PDF/推文）→ 提取纯文本
   - 网络搜索补充；外部资料少时明确告知用户
   - 输出「事实清单」，并标出哪些是自行补充、需要核对的

2. 分镜（先定时间常数！）
   - 用小节长度切段：60/BPM × 4 = 每小节秒数（120BPM→2s，150BPM→1.6s）
   - 表格：时间 | 场景 | 画面动作 | 卡点（第几拍）| 音效 | 字幕
   - 设计 1 个视觉主线（本次：红色书签线）+ 1 个音乐主题（快版/慢版同一旋律）
   - 至少设计一个「反差点」（骤停/静音/变色）

3. 环境检查
   fc-list :lang=zh | head; which ffmpeg; python3 -c "import playwright"
   curl -sI https://fonts.googleapis.com   # 不通就走 npm @fontsource
   npm i @fontsource/<字体>; pip install fonttools brotli --break-system-packages

4. 搭引擎（复用本项目 video.src.html 的基础部分）
   - render(t) 纯函数；hash() 替代随机；P()/缓动函数
   - def()/ink()/crayon()/brush()/charsIn()/T()/mw()
   - class Music + score(M)，at(t) 支持 offset
   - window.__frame(t) / window.__renderAudio() / __ready 握手
   - 播放器：点击开始、暂停、进度条、?t= 参数

5. 先写 1 个场景 → build → snap 抽帧 → 确认风格
6. 批量写其余场景 → 每段抽 3–5 帧（含转场中间帧）→ 拼总览图检查
7. 写乐谱：和弦进行、琶音/旋律、鼓组、whoosh/riser/impact 放在分镜的卡点上
8. 全量渲染：render.py（先音频后画面，帧通过管道送 ffmpeg）
9. 质检：ffprobe、音频分段 RMS/峰值/削波、抽帧、文件大小
10. 交付：MP4（超限就 CRF 22 重新压缩）+ 交互 HTML + 源码 zip（附 README）
    说明中列出：时长偏差原因、需要核对的事实、请用户试听
```
