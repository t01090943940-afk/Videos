# 《把日子，慢慢过圆》代码视频 CoExp 复盘

> 最终成片：60 秒 / 1920×1080 / 60 fps / H.264 + AAC / 21 个镜头 / 3600 帧 / 立体声 / 无旁白。
>
> 最终文件：`MidAutumn_Final_60s_1080p60.mp4`，29,332,124 bytes（约 28.0 MiB）。
>
> 这份复盘严格基于本次真实工程：先完成了一个 116 秒、1080p30、20 镜头的版本；收到“节奏太慢、静态和空白太多、电子散步是误识别”反馈后，没有简单倍速，而是重做为 60 秒、1080p60、21 镜头版本，并重编 120 BPM 音乐、重做转场和人物吃月饼动作。

# 一、创作思路

## 1. 如何把需求拆成叙事结构：情感曲线如何落到时间与镜头

这次最重要的不是“介绍中秋知识”，而是把中秋从一个节日名词变成一种观众能够在 60 秒内经历的情绪：**现在太快 → 突然停下 → 记忆被唤醒 → 历史穿越 → 回到今天 → 理解团圆 → 给当下的人祝福 → 回到开场的那轮月。**

最终 60 秒版将叙事压成 21 个镜头。每个镜头不是单纯承载一句话，而是承担一个明确的“状态变化”。

| 时间 | 镜头 | 情绪功能 | 视觉/剪辑任务 |
|---|---|---|---|
| 0–2s | 今夜月圆 | 温情引子 | 窗、月亮、月饼、茶汽；从近景快速建立“今晚” |
| 2–5.5s | 忙碌的现在 | 加速、焦虑 | 城市视差、时间卡片、时钟旋转、速度线，把“快”变成视觉事实 |
| 5.5–7s | 骤停与回望 | 突然抽空 | 音乐在 5.5–6.0s 完全归零；画面不空，月亮与“你还记得中秋吗？”继续运动 |
| 7–9.5s | 分着吃的月饼 | 记忆回暖 | 铅笔庭院、人物、桌面，月饼在人物间移动 |
| 9.5–11s | 时间倒流 | 进入历史 | 月饼匹配变形成时间盘，历史标签绕圆旋转 |
| 11–13.5s | 祭月与谢秋 | 起源感、克制 | 纸张、线描、稻穗、月相进度，强调“习俗脉络”而不是硬造一个发明年份 |
| 13.5–16s | 唐代赏月 | 开阔、诗性 | 金色矢量亭台、灯笼、月亮；快速描边揭示 |
| 16–19s | 宋代佳节 | 抒情高潮之一 | 水墨多层视差、城镇、船、诗句“但愿人长久……” |
| 19–21.5s | 明清团圆 | 象征收束 | 月饼分成四块，圆形结构继续强化“团圆” |
| 21.5–24s | 千年风格汇聚 | 视觉高潮 | 四种历史材质拼成一个整体，月亮从拼贴中心出现 |
| 24–27s | 回到今天 | 从历史回现代 | 古代材质退场，月亮转化为现代城市/窗格结构 |
| 27–30s | 万里同屏 | 温暖而现代 | 两块视频卡片进入，粒子沿贝塞尔曲线连接两端 |
| 30–33.5s | 隔屏吃月饼 | 核心现代团圆动作 | 专门增加近景人物：抬手、咬月饼、咀嚼；彻底取代误识别的“电子散步” |
| 33.5–36s | 同一份牵挂 | 延续余温 | 两端画面继续，桌面与月饼形成共同空间的错觉 |
| 36–39s | 团圆不等于圆满 | 反思 | 未闭合圆环、两个人物、降低音乐能量 |
| 39–42s | 也有人惦念你 | 情感核心 | 粒子汇向圆环缺口，形成“惦念”而不是强行修成完美圆 |
| 42–45s | 祝福学子 | 再加速 | 纸张阶梯、人物向上走、飞页；高考/考研祝愿 |
| 45–48s | 祝福求索者 | 理性与希望 | 轨道、节点、连线，表现科研“提出问题—验证—继续求索” |
| 48–52s | 祝福诗云 | 视觉第二高潮 | 祝福文字墙持续横向运动，中间保留阅读孔径 |
| 52–55.5s | 今晚一起吃月饼 | 回到具体行动 | 两块视频窗口 + 中央月饼；把宏大主题落回“今晚一起吃一块” |
| 55.5–60s | 团团圆圆 | 回环、落地 | 回到开场房间构图；同一轮月完成叙事闭环，最后一帧保持画面而非黑场 |

### 情感曲线

最终不是一路升高，而是“**快 → 静 → 暖 → 快 → 震 → 静 → 暖 → 亮**”：

1. **0–5.5s：快**，用忙碌建立观众的现实处境。
2. **5.5–7s：静**，声音突然归零，把注意力从外部世界拉回内心。
3. **7–11s：暖**，童年与分享月饼让观众产生个人记忆入口。
4. **11–24s：快**，用不同材质高速走完历史，不陷入纪录片式平铺。
5. **24–36s：暖且现代**，把“千里共婵娟”翻译成当代视频通话和一起吃月饼。
6. **36–42s：静与深**，把主题从“团圆=回家”提升到“未圆满时仍有人惦念你”。
7. **42–52s：亮**，祝福学业、科研、生活，让观众把情绪投射到自己。
8. **52–60s：回家**，从宏大祝福落回一个可执行动作和一句中秋快乐。

这条曲线比“中秋历史知识 + 祝福”更有效，因为观众不是被动听知识，而是被安排经历一次“现在—过去—现在”的情绪旅行。

## 2. 每个段落/场景为什么这样设计

### 开场：用“同一扇窗”建立视觉母题

开场不是直接上“中秋节起源”，而是用月亮、月饼、茶杯、窗框、城市远景。原因有两个：

- 中秋是情绪先于知识的节日，先让观众“进入今晚”。
- 这套房间构图在 55.5–60s 再次出现，形成真正的首尾呼应，而不是最后机械地打一个“中秋快乐”。

核心代码中 `room()` 同时服务开场与结尾，`final=False/True` 只调整镜头运动速度和结尾文字，因此空间连续性是代码层面真实复用，而不是两个相似但无关的场景。

### 忙碌的现在：让“快”成为画面而不是台词

初版已有城市和时间卡片，但 116 秒版本的镜头平均太长，导致“忙碌”反而看起来不忙。最终版把 2–5.5s 压到 3.5 秒，并增加：

- 两层城市以不同速度横向视差；
- 65 条速度线；
- 5 张悬浮时间卡片；
- 60 个时钟刻度；
- 两根不同角速度的表针；
- 0.2 秒一次的程序化 click 音效。

这样“现在太快”成为视听同步的事实。

### BGM 骤停：不是黑屏，而是信息密度突然改变

用户明确要求“BGM 骤然而止”。初版设计了约 1.05 秒静音，最终版压到 **5.5–6.0s 共 0.5 秒**。最关键的做法不是单纯把音乐音量拉到 0，而是：

- MIDI 端在 5.5s 对所有通道发 All Sound Off（CC120）；
- 混音数组再次把 5.5–6.0s 直接置零；
- 母带阶段再次强制这段为 0，避免混响尾音或 AAC 编码边缘残留；
- 画面仍有月亮、环形波纹、文字和粒子运动，所以“静音 ≠ 空白”。

声音骤停后才出现“你还记得中秋吗？”，它的作用是制造心理剪辑点。

### 历史段：不是统一滤镜，而是每个时代换一种“材料”

用户要求铅笔/SVG、水墨、现代 2.5D。最终版把“风格变化”写进渲染逻辑：

- 早期：纸纹 + 双线抖动铅笔；
- 唐：深蓝夜景 + 金色矢量线框；
- 宋：浅纸底 + 多层程序化水墨山体视差；
- 明清：雕花月饼 + 扇形分块；
- 汇聚：四块 `history_tile()` 缩放、旋转并合成一轮月。

这避免了“换颜色就叫换风格”。

### 现代段：从“屏幕”转向“动作”

初版有“万里一屏”“隔屏吃月饼”和误识别出来的“电子散步”。收到反馈后，最终版**完全删除** walk 场景，并且不是仅删文案，而是新增 `eat_macro()`：

- 两个 850×658 的近景区域；
- 人物脸部、眼睛、嘴型、手臂重新画；
- 用 `reach` 参数把右手从桌面插值到嘴边；
- 月饼跟随手移动；
- `cycle > .36` 时月饼出现咬痕；
- `chew = reach > .70` 时眼睛/面部状态变化形成“正在吃”的感觉。

也就是说，最终版把“电子团圆”的抽象概念改成了观众一眼能读懂的动作：**你吃一口，我也吃一口。**

### 情感高潮：未闭合圆比“完美圆”更重要

“团圆，不是一切都圆满；是还没圆满时，也有人惦念你。”是整片真正的主题句。

视觉上没有把圆补成一个机械完美图形，而是保留缺口，再让粒子、光点和细线汇向缺口。这样“团圆”不是“现实必须完美”，而是“关系在缺口存在时仍然有效”。这比单纯画一个大圆更符合文本。

### 祝福诗云：让祝福成为环境，而不是 PPT 列表

初版用 112 个词做球面透视投影，并做碰撞过滤；视觉复杂但渲染重，而且文字有“出现/消失”的跳变风险。最终版改为 10 行固定轨道的移动文字墙：

- 奇偶行反向移动；
- 每行速度略有差异；
- 中央 366–654px 区域人为降低文字 alpha，给主句留下阅读孔径；
- 月亮与椭圆环在背后维持统一的圆形母题。

这是一次典型的“少一点算法炫技，换更稳定的阅读体验”。

## 3. 节奏、剪辑、音画配合用了什么技巧

### 3.1 从“平均 5–7 秒一镜”改成“1.5–4 秒一镜”

116 秒初版：20 镜头，绝大多数镜头 5–7 秒。最终版：60 秒，21 镜头，镜头长度大多数在 2–3.5 秒。

关键不是“速度翻倍”，而是**每个镜头只保留一个主要信息任务**。例如：

- “祭月与谢秋”不再同时解释太多历史；
- “唐/宋/明清”各只保留一个最强符号；
- “视频相聚”不再分成屏幕、吃月饼、电子散步三个长段；
- 祝福学子/科研各 3 秒，诗云 4 秒。

### 3.2 文字入场从长淡入改成 0.24 秒级快速入场

最终 `reveal()`：

```python
def reveal(c, s, x, y, size=70, color=CREAM, font='bold', u=1, delay=0, align='left'):
    q = clamp((u - delay + .06) / .24)
    dy = (1 - ease(q)) * 27
    alpha = .30 + .70 * smooth(q)
    return text(c, s, x, y + dy, size, color, font, a=alpha, align=align)
```

60 fps 下 0.24 秒约 14 帧。文字不是“等一秒才慢慢出现”，而是在 8–14 帧内完成主要入场，同时带 27px 位移，观众会觉得画面一直在推进。

### 3.3 转场从长 dissolve 改为 0.22–0.27 秒材质 wipe

最终只对部分镜头使用 `WIPES`，而不是每一刀都加转场：

```python
WIPES = {
    3:'diagonal', 4:'radial', 5:'diagonal', 6:'diagonal', 7:'diagonal',
    8:'radial', 9:'diagonal', 10:'radial', 13:'radial', 16:'diagonal',
    17:'diagonal', 18:'radial', 19:'diagonal', 20:'radial'
}
```

持续时间通常 0.22 秒，关键场景 0.27 秒。斜向 wipe 用多边形 clip，圆形 wipe 用不断扩大的圆形 clip。优势：

- 不会出现两组文字长时间同时可读；
- 比统一淡入淡出更有方向感；
- 与“圆/月亮”母题一致的地方使用 radial wipe，有动机。

### 3.4 Match cut：月亮、月饼、时钟、圆环共享几何母题

整片最重要的剪辑黏合剂其实不是转场特效，而是“圆”：

- 月亮 → 时钟；
- 月饼 → 时间盘；
- 月亮 → 明清月饼；
- 月饼四块 → 历史四材质；
- 圆 → 视频连接核心；
- 未闭合圆 → 团圆/圆满命题；
- 最后回到月亮。

因此即使画风从线稿切到水墨再切到科技感，观众仍然能感觉是一部片，而不是素材拼盘。

### 3.5 音效比“更多转场”更能制造速度

最终音效不是堆爆炸，而是低强度、密集、精确：

- 所有主要切点前约 0.14s 放短 whoosh；
- 2.1–5.48s 忙碌段每约 0.20s 一次 click；
- 11、16、24、36、42、48、55.5s 放低频 thump；
- 6、13.5、19、39、42、55.5s 放 bell；
- 27.06/27.22s 用两次暖色铃声表示视频连接，而不是模仿某个真实 App 的提示音。

音效承担“剪辑的标点符号”，所以视觉无需每一刀都做复杂过渡。

# 二、具体的创作方式

## 1. 技术栈与完整工作流

### 最终技术栈

- **Python**：主控制语言。
- **pycairo / Cairo**：所有矢量图形、路径、clip、渐变、2D/2.5D 绘制。
- **Pillow**：中文文字栅格化、字体测量、缩略图/分镜拼图。
- **NumPy**：程序纹理、噪声、音频数组、数学动画。
- **SciPy**：`gaussian_filter` 做纸纹、水墨噪声；`butter` / `sosfilt` 做程序化音效滤波。
- **SoundFile**：读写 24-bit WAV/FLAC。
- **FluidSynth**：把程序生成的 MIDI 事件渲染为乐器音频。
- **FFmpeg/ffprobe**：H.264 编码、AAC 合成、响度标准化、章节、完整解码 QA、抽帧检查。
- **Noto Serif/Sans CJK**：本地中文排版；字体文件不打包。
- **Motion Library Atlas**：只用于方法参考，主要吸收“固定随机种子、统一时间轴、声音分层、阅读安全、不要把复杂等同于创意”等原则；最终实现没有假称运行 Rough.js/AE/Three.js。

### 从脚本到 MP4 的真实步骤

1. **先写情绪脚本**：确定“现在→骤停→记忆→历史→现代→反思→祝福→回到现在”。
2. **做时间轴 JSON**：每个场景写 `start/end/name/top/sub`，让画面、章节、字幕共用同一份时间数据。
3. **建立程序化资产层**：月亮、城市、纸张、水墨山、月饼、树枝、人物、亭台等都由 `artwork.py` 生成。
4. **按场景函数写动画**：每个镜头函数只接收绝对时间 `t` 和本镜头局部时间 `u`。
5. **生成 stills / storyboard**：先看 21 张关键帧，不先赌完整 3600 帧。
6. **根据静帧与短片局部返工**：例如最终新增 `eat_macro()` 后只渲染 30–33.5s 做检查。
7. **重编 120 BPM 音乐**：不是把 116 秒旧 BGM 倍速；重新生成 MIDI、合成乐器、程序化 Foley。
8. **两遍 loudnorm 母带**：目标 I=-16 LUFS、TP=-1.3 dBTP、LRA=9，并再次强制静音段。
9. **分段并行渲染画面**：0–16、16–30、30–45、45–60 四段。
10. **无损拼接视频段**：concat 后 `-c:v copy`，避免最终合成再损一次画质。
11. **混入 48kHz AAC 256 kbps 音轨 + FFMETADATA 章节**。
12. **完整解码 QA**：检查 3600 帧可完整解码、时长 60.000s、音频、抽样黑帧、重复帧、静音区、SHA256。
13. **打包源工程**：排除字体和 SoundFont，附 README、时间轴、SRT、MIDI、FLAC、QA 报告。

### 2.1 统一时间轴：所有镜头由绝对时间决定

```python
def scene_index(t):
    for i, s in enumerate(SC):
        if s['start'] <= t < s['end']:
            return i
    return len(SC) - 1


def plain(c, t, i=None):
    if i is None:
        i = scene_index(t)
    FUNCS[i](c, t, t - SC[i]['start'])
    rim(c, t, i in BRIGHT)
```

优势：

- 任意时间点都可独立渲染；
- 能做 `--start 30 --end 33.5` 局部预览；
- 不依赖“上一帧状态”，并行渲染不会出状态错乱；
- 更容易对齐音频 cue。

### 2.2 固定随机种子：程序纹理不闪烁

初始工程和最终工程都使用固定随机源，如 `np.random.default_rng(...)`。月面、纸张、水墨山、城市窗格等纹理先生成成 Cairo surface，然后每帧复用。

如果每帧直接 `np.random`，纸纹、水墨、星点会产生高频闪烁；固定 seed + 资产缓存把“随机”变成“稳定材质”。

### 2.3 文本缓存：避免每帧重复字体栅格化

`text_surface()` 使用 `@lru_cache(maxsize=1024)`，同一句同字号文字只栅格化一次。

```python
@lru_cache(maxsize=1024)
def text_surface(txt, size, color=CREAM, font='serif', tracking=0):
    path = {'serif': SERIF, 'sans': SANS, 'bold': BOLD}.get(font, SANS)
    f = ImageFont.truetype(path, int(size), index=2 if path.endswith('.ttc') else 0)
    ...
```

这对祝福诗云尤其重要，否则几十个中文词每帧都重建 PIL 字形会显著拖慢。

### 2.4 2.5D 的本质：图层 + 视差 + 变换，而不是必须上 Three.js

```python
def cam(c, cx, cy, zoom, dx=0, dy=0):
    c.translate(cx + dx, cy + dy)
    c.scale(zoom, zoom)
    c.translate(-cx, -cy)
```

配合：

- 远景城市慢移；
- 前景物体快移；
- `c.transform(cairo.Matrix(...))` 做轻微斜切；
- glow、阴影、clip；
- 不同图层速度差；

就能在 2D 渲染器里制造足够强的 2.5D 摄影感，而且比完整 3D 工程更可控、更易批量渲染。

## 3. 每种视觉风格怎么用代码实现

### 3.1 铅笔线绘 / 纸张

纸底：NumPy 噪声 + Gaussian blur + 暗角，再转为 Cairo surface。

铅笔线：同一条路径画两次，第二次用确定性的微小正弦偏移模拟手绘毛边：

```python
def pencil(ctx, pts, width=2, a=1, c=INK, close=False):
    line(ctx, pts, c, width, a, close)
    pts2 = [
        (x + math.sin(i*2.2 + x*.01)*2.2,
         y + math.cos(i*1.4 + y*.01)*1.7)
        for i, (x, y) in enumerate(pts)
    ]
    line(ctx, pts2, c, max(.7, width*.48), a*.3, close)
```

重点：这里的抖动是位置函数，不是逐帧随机，所以不会“虫子一样抖”。

### 3.2 唐代 SVG/矢量感

虽然没有真的用 SVG runtime，但用 Cairo path 实现了同类矢量语言：

- 深蓝背景；
- 金色细线；
- `pavilion()` 用贝塞尔曲线画屋檐；
- clip 矩形从左向右揭示线框；
- 底下先放一层 28% alpha 的完整亭台，避免揭示前画面过空。

这层“稳定底图 + 快速描边”的补丁，是最终版本比初版更饱满的一个具体改动。

### 3.3 宋代水墨 / 晕染

水墨山体不是贴 PNG，而是在 `make_hill()` 中：

1. 生成多尺度随机曲线；
2. Gaussian filter 形成大、中、小三个频率的山势；
3. 画半透明山体；
4. 用随机 grain 和随深度衰减的 alpha 做纤维感；
5. 4 层山体按不同速度横移形成视差。

最终版把原先较慢的视差速度进一步增大，解决“水墨好看但像静态海报”的问题。

### 3.4 明清月饼 / 雕刻材质

`make_cake()` 用 24 个边缘花瓣、16 个内部纹样、中心圆、文字“团圆”组成雕花月饼。历史段再用 `cake_sectors()` 将它 clip 成四个 90° 扇形并向外分离：

```python
for k in range(4):
    a = k * PI / 2 + rotation
    mid = a + PI / 4
    c.translate(x + cos(mid)*spread, y + sin(mid)*spread)
    c.arc(0, 0, r*1.05, k*PI/2, (k+1)*PI/2)
    c.clip()
    paint(c, A.cake, -r, -r, r*2, r*2)
```

“月饼分块”既是视觉动作，也是“分享”主题的物理化。

### 3.5 现代 2.5D / 视频通话

`video_card()` 使用：

- 圆角矩形机身；
- 屏幕 clip；
- 轻微 rotate + shear；
- 影子和 glow；
- 两端不同环境（暖色家中、冷色城市）；
- 贝塞尔连线粒子；
- 人物吃月饼动作。

连接粒子通过三次贝塞尔公式计算：

```python
xx = (1-a)**3*p0x + 3*(1-a)**2*a*p1x + 3*(1-a)*a*a*p2x + a**3*p3x
yy = (1-a)**3*p0y + 3*(1-a)**2*a*p1y + 3*(1-a)*a*a*p2y + a**3*p3y
```

这种做法比画一根静态线更像“远方正在发生连接”。

### 3.6 祝福墙 / 诗云

最终版不再强求 3D 球体投影，而是固定轨道：10 行文字、8 个槽位、奇偶行反向运动。中央阅读区域降低周边文字 opacity，确保主句不会被挡。

这次经验很重要：**复杂度应该服务阅读，不应该与主标题争夺注意力。**

## 4. 音频：BGM、音效、卡点、淡入淡出、转场

### 4.1 BGM 不是成品音乐素材，而是程序编曲

最终 `music60.py`：

- 原始采样率 44.1kHz；
- 总时长 60s；
- 120 BPM，对应 0.5s 一拍；
- D / G / Bm / A / Em 等和弦；
- 钢琴、弦乐、拨奏/打击等通过 General MIDI program 组合；
- 使用共享三音主题贯穿不同年代；
- wishes 段提高能量，heart/memory 段减少 ostinato 密度；
- 55.5s 后落到 D(add9) 的温暖终止。

最终音乐事件约 1840 个，输出可编辑 `score60.mid`。

### 4.2 Foley 全部程序合成

没有下载 whoosh 包，而是自己生成：

- `whoosh()`：白噪声 → 420–6000Hz bandpass → 正弦包络；
- `click()`：45ms 噪声指数衰减；
- `thump()`：约 70Hz 向下扫的正弦低频脉冲；
- `bell()`：基频 + 2.76 倍频，指数衰减；
- 两路延迟 0.10s/0.22s 做轻微立体声空气感。

优点是每个音效的时间、长度、pan 都能直接用秒控制，和代码画面完全共用时间坐标。

### 4.3 静音和淡入淡出

最终混音：

```python
mix[int(5.5*SR):int(6*SR)] = 0
n = int(.005*SR)
mix[int(5.5*SR)-n:int(5.5*SR)] *= np.linspace(1,0,n)[:,None]
mix[int(6*SR):int(6*SR)+n] *= np.linspace(0,1,n)[:,None]
mix[:int(.07*SR)] *= np.linspace(0,1,int(.07*SR))[:,None]
n = int(.82*SR)
mix[-n:] *= np.linspace(1,0,n)[:,None]**1.3
```

这里 5ms 边缘 fade 的作用是防止波形硬切产生 click，但不会把叙事上的“骤停”软化掉。

### 4.4 两遍响度母带

`master_audio.py` 用 FFmpeg `loudnorm`：

```text
I=-16
TP=-1.3
LRA=9
```

第一遍测量输入响度；第二遍将测得的 `input_i / input_tp / input_lra / input_thresh / target_offset` 回填，线性标准化。之后 resample 到 48kHz、24-bit PCM，最终写 FLAC；再混入 MP4 时编码为 AAC 256k。

### 5.3 单段 H.264 编码参数

实际画面渲染是 Cairo 直接把 BGRA raw frame 写进 FFmpeg stdin：

```bash
ffmpeg \
  -f rawvideo \
  -pixel_format bgra \
  -video_size 1920x1080 \
  -framerate 60 \
  -i - \
  -an \
  -c:v libx264 \
  -preset fast \
  -crf 18 \
  -pix_fmt yuv420p \
  -threads 1 \
  -g 120 \
  -movflags +faststart \

```

参数说明：

- 1920×1080；
- 60 fps；
- H.264 `libx264`；
- CRF 18，质量优先；
- `yuv420p` 保证浏览器/手机兼容；
- GOP 120 = 2 秒；

### 5.4 分段并行

```python
spans = [(0,16), (16,30), (30,45), (45,60)]
```

用 `ThreadPoolExecutor` 启多个独立 Python/FFmpeg 子进程。交付脚本默认 `--workers 3`，并限制最大 4。

开发过程中曾实际四段同时跑；单段日志约为：

- 0–16s：70.7s；
- 16–30s：74.7s；
- 30–45s：91.5s；
- 45–60s：74.6s。

因为并发，墙钟时间接近最慢那段而不是四段相加。30–45s 最慢，因为包含两块视频卡片、人物动作、多个 glow/clip、连接粒子和复杂场景。

关键是 `-c:v copy`：分段时已经 H.264 编好，最终只拼接/复用视频码流，不做第二次 H.264 有损重编码。

## 6. 大致时间分配、最耗时环节和提速方法

从本次工具执行记录看：

- 第一版 116 秒从策划、代码、音频、渲染、QA 到打包，工作阶段约 **20 分钟**；
- 60 秒最终重剪版从重新规划到最终交付，约 **16 分钟**；
- 合计可观察的执行阶段约 36 分钟，不包含用户观看和往返沟通时间。

没有给每个创作动作单独打计时点，所以更细分只能做近似复盘：

| 环节 | 本次耗时特征 | 下次提速方式 |
|---|---|---|
| 叙事/时间轴 | 人工推理成本高，但计算成本低 | 第一轮就限定总时长和“每镜头唯一任务”，避免 116→60 的大重构 |
| 程序资产 | 初始化约 2–3 秒，但一次写好复用价值高 | 把 moon/city/cake/ink/font 全放资产层，不塞进场景函数重复生成 |
| 分镜静帧 | 很快，性价比最高 | 强制先出全片 storyboard 再全渲染 |
| 画面全渲染 | 最耗 CPU；复杂段离线只有 5–15 fps | 按独立时间切分并行；缓存文字/纹理；局部返工只渲对应段 |
| 音乐 | 生成 1840 个 MIDI 事件 + FluidSynth 渲染，成本可控 | 音频与画面分离；先定 cue 再编曲，不要每次画面修改都重做 BGM |
| 母带 | 很快，但脚本格式解析容易出错 | 对 loudnorm 输出用稳健 JSON 提取，第一次就封装成函数 |
| QA | 完整解码必需，但比肉眼整片重看高效 | 自动抽样 + 完整 decode + 关键 cut contact sheet 组合 |
| 打包 | 很快 | 建立固定白名单，避免字体、SoundFont 被意外分发 |

最值得复用的一条：**修改局部时不要重渲整片。** 本次新增 30–33.5s 吃月饼近景后，只重新渲染 3.5 秒，实测约 9.8 秒，再复用 33.5–45s 尾段；这比把最重的 30–45s 全部重跑一次节省明显。

## 2. 本次实际踩过的坑

### 坑 1：第一版 116 秒技术上完整，但观感明显太慢

**现象**：用户反馈“节奏过于缓慢、部分地方空白、静态的地方太多”。

**根本原因**：

- 20 镜头分 116 秒，平均镜头长度接近 5.8 秒；
- 很多动画使用低风险的淡入/停留/淡出；
- “一段话说完才进下一段”的串行思维造成空等；
- 历史画面虽然细致，但 30fps + 长镜头会更像动态海报。

**解决**：

- 重写成 60 秒 21 镜头；
- 不是把成片 ×1.93 倍速；
- 重新编排 120 BPM 音乐；
- 文字入场压到约 0.24s；
- wipe 控制在 0.22–0.27s；
- 60fps；
- 每个镜头增加持续运动元素：视差、粒子、人物、路径、文字墙。

**下次避免**：第一轮脚本就做“时间预算表”，每一秒都必须有信息任务或情绪任务。

### 坑 2：“电子散步”来自语音转文字误识别，却被第一版当成真实需求实现了

**现象**：第一版不仅有文字“电子散步”，还真的写了 `scene_portals(...,'walk')`，包括两块屏幕和步行路径。

**根本原因**：把用户输入中的一个不自然词组当成已确认创意，没有做语义 sanity check。

**解决**：最终版彻底删除 walk 段，重新分配 30–36s，把时间给“隔屏一起吃月饼”的近景和共享桌面。

**下次避免**：当语音稿出现突兀的概念，尤其是核心动作词，先检查它是否符合上下文；如果不能询问，就优先选择上下文中最稳定、重复出现的意图。

### 坑 3：删错内容后不能只改字幕，必须改镜头逻辑

**现象**：如果仅把“电子散步”改成“吃月饼”，原画面仍会是人物走路，语义会穿帮。

**解决**：新增 `avatar()` 的手臂、嘴型、月饼跟随、咬痕状态，再新增 `eat_macro()` 近景。

**下次避免**：文案、动作、音效三层一起改；任何核心动词变化都要检查“画面真的执行了这个动词吗”。

### 坑 4：新音乐脚本第一次出现 `PI` 未定义

**现象**：运行 `music60.py` 报：`NameError: name 'PI' is not defined`。

**根本原因**：从旧 116 秒音乐脚本抽取前缀并重组时，常量定义位置被移到了后面，而前面的弦乐 expression 控制已经使用 `PI`。

**解决**：在事件生成前明确：

```python
PI = math.pi
TAU = 2 * PI
```

**下次避免**：重构脚本时把 constants / imports / IO / timeline / render 分成固定区块；跑 `py_compile` 只能发现语法问题，仍要执行一个最短真实路径测试。

### 坑 5：`numpy.int64` 不能直接被 `json.dumps`

**现象**：生成 `audio_cues.json` 时出现 `TypeError: Object of type int64 is not JSON serializable`。

**根本原因**：`np.arange()` 等产生 NumPy scalar，进入 `bars/cuts` 后被原样塞进 JSON。

**解决**：显式 `float(t)`，并在写 JSON 时加：

```python
default=lambda x: x.item()
```

**下次避免**：所有对外 metadata 在边界层统一转换成 Python `int/float/str`，不要让 NumPy 类型逃出计算层。

### 坑 6：解析 FFmpeg `loudnorm` 输出时 `json.loads` 报 Extra data

**现象**：

```text
json.decoder.JSONDecodeError: Extra data
```

**根本原因**：FFmpeg 的 stderr 中 JSON 块后仍可能有额外文本，`json.loads(r.stderr[r.stderr.rfind('{'):])` 假设“最后一个 `{` 到文件末尾全是 JSON”，不稳健。

**解决**：改为：

```python
report = json.JSONDecoder().raw_decode(
    r.stderr[r.stderr.rfind('{'):]
)[0]
```

只解析第一个合法 JSON 对象。

**下次避免**：任何 CLI 工具的“JSON in stderr/stdout”都不要默认独占输出，使用专门 parser 或 `raw_decode`。

### 坑 7：人物月饼“咬一口”的 clip 路径第一次写法不严谨

**现象**：咬痕遮罩没有按预期形成清晰的 subtract 区域。

**根本原因**：在 even-odd fill rule 下，矩形和圆形路径没有明确开启新的 subpath，clip 语义容易受到当前 path 状态影响。

**解决**：在咬痕圆之前加：

```python
c.new_sub_path()
c.arc(...)
c.clip()
```

**下次避免**：Cairo 做复合遮罩时，每个几何子形状明确 `new_sub_path()`，并对 mask 单独做 0.5 秒测试片。

### 坑 8：唐代矢量描边揭示阶段会显得空

**现象**：如果只做从左到右 clip reveal，早期帧大面积空，虽然“技术上是动画”，观感仍像空白。

**解决**：先画一层 28% alpha 的完整亭台 silhouette，再在上面快速描边揭示。

**下次避免**：任何“逐步绘制”动画都要有低对比底层或环境运动，避免 reveal 尚未到达区域成为死区。

### 坑 9：宋代水墨漂亮但静态感重

**现象**：初版水墨山、城镇、船都在，但运动速度过低，6–7 秒镜头里像展示一张长图。

**解决**：最终版提高不同山层的横移系数，并让城镇、船和细水纹以不同速度移动。

**下次避免**：水墨不是“必须慢”；如果剪辑节奏快，可以用低频、不同层级的视差维持诗性，同时保证画面状态持续变化。

### 坑 10：祝福诗云原始球面方案算法更炫，但会弹字且更重

**现象**：116 秒版采用 112 个文本球面透视投影 + depth sort + 矩形碰撞过滤。词语在碰撞边界附近会突然被过滤/重新出现，视觉可能“pop”。

**解决**：60 秒版改为固定行轨道，保证每条祝福连续移动；中央 aperture 保证主标题稳定可读。

**下次避免**：信息型文字动画优先保证轨迹连续和阅读稳定，再追求 3D 投影复杂度。

### 坑 11：30–45s 是最重渲染段，不能把全片当一个不可拆的大任务

**现象**：该段最初约 5.6 fps，15 秒画面实测约 91.5 秒离线渲染，明显慢于其他段。

**根本原因**：同帧中有多人物、多屏幕、clip、文字、粒子、glow 和复杂几何。

**解决**：

- 全片按四段并行；
- 最后只重渲 30–33.5s 新近景（约 9.8 秒完成）；
- 33.5–45s 继续复用之前的已编码尾段；
- 最终 concat。

**下次避免**：从第一天就把 renderer 设计成无状态、可任意起止；这比微优化某个 for-loop 更值。

### 坑 12：30fps→60fps 不等于渲染量翻倍得不可接受

**现象**：初版 116×30 = 3480 帧；最终 60×60 = 3600 帧。虽然帧率翻倍，但总帧数只增加约 3.4%。

**结论**：对于“时长减半”的重剪，升到 60fps 几乎没有增加总体帧数量，却显著改善快速移动、文字和人物动作的流畅感。

**下次避免**：不要孤立看 fps 成本，要看 `duration × fps = total frames`。

### 坑 13：音画同步不能靠“听起来差不多”

**现象**：骤停、铃声、whoosh 都必须准确对准剪辑点，否则快节奏会显得软。

**解决**：所有 cut 直接存秒数；音效在数组索引 `int(t*SR)` 放置，画面也用相同秒数判断场景。

**下次避免**：不要使用独立手调的“音乐时间”和“视频时间”；至少要共享一个 cue sheet。

### 坑 14：静音区必须在最终 AAC 上再次验证

**现象**：PCM 置零不代表 AAC 解码边缘完全没有 ringing。

**解决**：最终 QA 选 5.54–5.96s 的内部安全区解码为 float32，实测 `silence_peak = 0.0`。

**下次避免**：检查静音时避开 codec frame 边界几毫秒，并以最终交付文件为准。

### 坑 15：中文字体是运行依赖，不应直接跟工程一起分发

**现象**：Cairo 本身不负责复杂字体排版，这套工程实际通过 Pillow + Noto CJK TTC 渲染中文；换机器可能字体路径不存在。

**解决**：默认使用 Linux Noto 路径，并支持：

```text
MOON_SERIF
MOON_SANS
MOON_BOLD
```

环境变量覆盖；源 ZIP 明确排除 `.ttf/.ttc/.otf`。

**下次避免**：开工第一步先渲染一张中文 font test，确认 TTC index、字形、标点和字号。

### 坑 16：最终成片必须检查“编码后”的画面，而不是只检查源 PNG

**现象**：源帧正常不代表 H.264 拼接、YUV 转换、AAC mux 后绝对正常。

**解决**：最终 MP4 做：

- `ffprobe`；
- 完整视频+音频 decode 到 null；
- 4fps 灰度抽样查近黑帧；
- 查 0.25s 连续抽样是否完全相同；
- 关键 cut 从最终 MP4 抽帧做 `encoded_checks.jpg`。

最终报告：没有抽样黑帧，没有连续 0.25 秒完全相同的样本帧，3600 帧完整解码通过。

### 坑 17：文件体积/交付包要提前设计

**现象**：初版源包约 20MB，最终源包约 12MB；若把 WAV、字体、SoundFont、所有中间 part 全部打包，体积会迅速膨胀且引入授权问题。

**解决**：

- 成片只保留 H.264 + AAC；
- 源包只放必要代码、MIDI、最终 FLAC、QA 和文档；
- 不放 raw WAV；
- 不放字体；
- 不放 SoundFont；
- ZIP 使用 deflate level 6。

**下次避免**：源工程白名单打包，而不是“zip 整个工作目录”。

# 四、可复用的模板

## 模板 A：下次可直接套用的代码视频制作流程

### Phase 0：约束

1. 写死：总时长、画幅、fps、目标平台、是否旁白。
2. 把用户需求拆成：必须讲的事实、必须触发的情绪、必须出现的动作、禁止出现的内容。
3. 选一个可贯穿全片的几何/材质母题。

### Phase 1：时间预算

建立表：

```text
时间 | 信息任务 | 情绪 | 主视觉 | 主动作 | 文字 | 音频事件 | 转场方式
```

规则：

- 60 秒片建议 15–24 个镜头；
- 普通镜头 1.5–4 秒；
- 每镜只承担一个主要信息任务；
- 静止超过约 0.5–1 秒必须有明确阅读/情绪理由；
- 不让所有元素串行入场。

### Phase 2：工程骨架

```text
project/
├─ timeline.json
├─ build.py
├─ src/artwork.py
├─ src/film.py
├─ src/music.py
├─ src/master_audio.py
├─ assets/
├─ render/
└─ qa/
```

要求每个 scene 都是：

```python
def scene_x(ctx, t, u):
    ...
```

不依赖前一帧状态。

### Phase 3：先资产、后镜头

先写 reusable primitives：

- `text()` / `reveal()`
- `line()` / `curve()` / `arc()`
- `glow()` / `paint()`
- 人物/设备/建筑组件
- 程序纹理

重资产初始化一次并缓存。

### Phase 4：先静帧 QA

对每个镜头取 40%–60% 处一帧，拼成 storyboard。逐项看：

- 主体是否明确；
- 中文有没有越界；
- 是否有无意义大空白；
- 画风变化是否真的明显；
- 前后镜头是否有颜色/形状/方向关系。

### Phase 5：局部动态 QA

优先渲：

- 最复杂转场；
- 最复杂人物动作；
- 文字最多场景；
- 预计最慢场景；
- 音乐骤停前后 1 秒。

局部通过后再全片。

### Phase 6：声音

把音乐、Foley、旁白（如有）分轨思考：

- BGM 负责情绪和结构；
- Foley 负责切点和动作；
- 静音负责强调；
- 不要用音量跳动逼每个图形都动。

所有 cue 使用绝对秒。

### Phase 7：并行渲染

先估算单帧速度，再决定分段。所有段：

- 同一分辨率；
- 同一 fps；
- 同一编码器/CRF/pix_fmt/GOP；
- 独立可重渲。

### Phase 8：最终 mux

视频段 concat `-c:v copy`，音频最后一次编码 AAC，加入 chapter/meta，`+faststart`。

### Phase 9：自动 QA

至少做：

```text
[ ] duration
[ ] dimensions
[ ] fps
[ ] frame count
[ ] full decode
[ ] audio SR/channels
[ ] black/blank sample scan
[ ] repeated sample scan
[ ] intended silence PCM scan
[ ] near-cut encoded screenshots
[ ] final frame
[ ] hash
```

### Phase 10：打包

只打包可复现所需文件，排除：

- 大量中间视频；
- cache；
- 字体文件；
- SoundFont；
- 不必要 raw WAV。

```text
你现在要制作一个“真正可交付”的代码视频，而不是只给方案、伪代码或分镜。

请设计 15–24 个镜头，普通镜头约 1.5–4 秒；需要停顿时，必须说明这段停顿具体承担什么阅读或情绪任务。

7. {高潮/祝福/结论}
8. 首尾呼应

【视觉原则】
1. 先选一个全片视觉母题，例如圆、光、线、门、窗口、轨道等，用于 match cut 和跨风格连接。

【代码架构】
优先使用 Python + Cairo/Pillow/NumPy/FFmpeg，除非有充分理由使用 Three.js/WebGL。
建立：
- timeline.json：唯一时间真源；
- artwork 模块：程序资产；
- film 模块：场景函数；
- music 模块：BGM/Foley cue；
- master_audio：响度和最终静音处理；
- build：并行渲染和最终 mux。

每个场景必须写成可被任意时间独立求值的函数：

不要依赖上一帧状态，以便任意局部重渲和并行。
所有随机纹理必须固定 seed；文字和重资产要缓存。

【剪辑】
转场优先使用：
- 几何 match cut；
- 材质 wipe；
- motivated camera move；
- 光线/形状延续。
不要给每一刀套同一个 dissolve。
主要转场 0.15–0.35 秒为主，除非剧情需要长停顿。

【声音】

【中文排版】

4. 小样通过后再全片分段并行渲染。
```

# 最后沉淀：这次最值得带走的 10 条经验

1. **先定时间预算，后写动画。** 初版最大的失败不是绘制能力，而是时间分配过松。
2. **快不是全片倍速，而是缩短无任务时长。** 60 秒版重新写了镜头和音乐。
3. **声音骤停必须让画面仍有信息。** 静音不是空白。
4. **跨时代最好的胶水是视觉母题，不是转场插件。** 本片用“圆”贯穿月亮、月饼、时钟、圆环。
5. **现代团圆必须落到动作。** “一起吃月饼”比抽象“线上相聚”更有情感抓力。
6. **文字动画首先是排版问题，其次才是动画问题。** 读不清的炫技等于失败。
7. **程序化随机必须固定 seed。** 否则纸纹、水墨、粒子会产生廉价闪烁。
8. **无状态时间函数是整个工程最重要的架构决策。** 它让分段并行、局部返工、QA 都变简单。
9. **最终 QA 必须检查编码后的 MP4。** 源帧正确不代表交付文件正确。
10. **代码视频真正的上限来自编剧、剪辑、声音、排版、镜头和工程共同工作，不来自“用了多少库”。**
