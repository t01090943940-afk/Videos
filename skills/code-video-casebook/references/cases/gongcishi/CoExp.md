# 《共此时》代码视频复盘

> 项目：用一个高中班级三年的照片和视频，全部用代码做成一支 3 分钟的中秋回忆视频（混燃卡点 + 温情回忆杀）。
> 成品：`mid_autumn_film/output/共此时_三班中秋回忆.mp4`（1920×1080，30 fps，180.000 s，H.264 + AAC，89.4 MB）
> 代码：`mid_autumn_film/src/` 下 14 个 Python 文件，共约 3000 行。BGM 是用代码从零合成的原创曲。
> 实际耗时：约 80 分钟墙钟时间，在 4 核、15 GB 内存的云端容器里完成。
>
> 本文所有数字、参数、报错和修法都来自这次真实的制作过程。

## 一、创作思路

### 1. 需求怎么拆成叙事结构

#### 1.1 先看完全部素材，再定主题

用户的原话是"线索你自己找，主题自己定"。所以第一步没有写任何剪辑代码，而是把素材全部"看"了一遍：

1. **盘点和去重**。仓库里有 290 个文件，按 MD5 去重后剩 217 份不重复素材（37 段视频、180 张照片）。重复文件 68 份，另有 4 张图片损坏打不开。
2. **人工看片**。每 20 张照片拼成一张带编号的联系表（contact sheet），每段视频抽 8 帧拼成一行，逐张看。
3. **机器看片**。每段视频按 0.2 秒一格算运动能量、亮度和清晰度，按 0.1 秒一格算音频响度；每张照片做人脸检测。
4. **重点素材抽密帧**。对 15 段关键视频，每秒抽 1 帧并标上时间码，用来挑具体的入点和出点。

从素材里挖到的"线索"才是真正的剧本来源：

| 线索 | 在素材里的位置 | 最后怎么用的 |
|---|---|---|
| 课表最后一行「晚自习3 21:40–22:30」 | `DATA/…213348.jpg` | 做成纸片飞入，高亮最后一行 |
| 晚自习监控时间戳 2024/03/13 22:25 → 22:30:04，全班起身 | `10.董越偷拍系列/13fb…mp4` 的 284–290 秒 | 快进 ×100 追到 22:30，然后落回实时、定格 |
| 挂钟下面的「高考倒计时 583 天」 | P009 | 第一个匹配剪辑（月亮 → 圆钟），后面又做成翻页倒计时 |
| 联欢会对联「十年寒窗不畏难 / 岁月不忘读书生 / 鲤跃龙门」 | P089 | 竖排书法逐字浮现 |
| 拔河视频文件名「3v10第二场」 | 文件名 | 角标「拔河 · 三班 vs 十班」 |
| 起跑器上印着真实的 3、2 号 | P199 | 倒数 3、2 直接推到真实的起跑器上 |
| 成人礼放气球，镜头正对太阳，太阳是一个过曝的圆盘 | V110 第 15.2 秒 | 太阳慢慢溶成月亮 |
| 三部戏：窦娥冤、雷雨、哈姆雷特 | `8.戏剧活动` 的黑板和 PPT | 一句文案串起来 |
| 2022级、583 天、高二课表 | 多处 | 推算出 2025 年高考，所以 2026 年中秋是"离开九中后的第二个中秋" |

**主题就是从这些线索里长出来的**：挂钟是圆的，太阳是圆的，晚自习下课后教学楼顶上挂着的月亮也是圆的。于是全片用"圆"做视觉母题，主线定为"月亮一直见证着我们"，标题取张九龄的"海上生明月，天涯共此时"，片名《共此时》。

#### 1.2 情绪曲线 → 音乐结构 → 时间段 → 镜头

先定情绪曲线，再把它翻译成音乐结构。关键决定是：**120 BPM，4/4 拍，1 小节 = 2 秒，90 小节正好 180 秒**。所有东西都挂在"第几小节第几拍"上，算时间只需要乘以 2。

```
情绪  ▁▂▃▅█▇█▃▂▃▅▆█▇█▆▃▁
      前奏 主歌 蓄力1 drop1  温情   蓄力2 drop2  尾声
小节   0-8  8-16 16-24 24-40  40-56  56-64 64-80  80-90
秒     0-16 16-32 32-48 48-80 80-112 112-128 128-160 160-180
LUFS  -21  -17  -12.5 -11.0  -16.8  -12.3  -10.6  -19.2
```

最后一行是 BGM 各段的实测响度，情绪曲线在音频上是真实落地的。

| 段落 | 情绪 | 镜头密度 | 视觉基调 | 镜头 |
|---|---|---|---|---|
| intro 0–16 s | 安静、思念 | 1 个长镜头 | 夜空、月亮、孔明灯 | 程序生成的夜空，月亮升起；「海上生明月 / 天涯共此时」竖排；片名 |
| verse 16–32 s | 回忆开启 | 每 2–4 秒一刀 | 冷色监控 → 暖色 | 月亮溶成挂钟；晚自习监控；课表；快进到 22:30 后定格；合照换成夜景 |
| build1 32–48 s | 蓄力 | 每拍 → 每半拍 → 每 1/32 拍 | 暖金、胶片 | 拍立得随拍掉落；分列式；倒计时 583 → 1；快闪；3-2-1 然后静音 |
| drop1 48–80 s | 燃 | 每拍 1–2 刀 | 高对比、高饱和 | 「冲！」；运动会航拍、方阵；拔河；篮球；三联屏；照片墙 |
| break 80–112 s | 温情 | 每 2–4 秒一刀，叠化 | 暖色，加宽银幕黑边 | 联欢会、对联、合唱原声、艺术节、三部戏、胶片条 |
| build2 112–128 s | 郑重 | 每 2 秒 → 每半拍 | 金色阳光 | 成人礼：状元门、旗手、找爸妈、抬头看天、一拍全黑写「放 飞」 |
| drop2 128–160 s | 最燃 | 每拍 1–2 刀 | 金色 | 气球升空、合照风暴、「一起××」、人脸三联屏、照片墙、太阳变月亮 |
| outro 160–180 s | 余韵 | 1 个长镜头 | 夜空 | 约 800 张照片飞来拼成满月，推近看清，再拉远；祝福语；淡出 |

### 2. 每个段落的设计意图

**开场 0–16 s：先建立"月亮"这个母题**
- 开头 2.2 秒从黑场淡入。文字在 0.8 s、3.0 s、4.8 s 依次出现，钟声打在第 2 拍。观众先看到日期"二〇二六年 · 农历八月十五"，马上明白今天是中秋。
- 月亮从画面下方升到 (W×0.64, H×0.40)，缓动用 `ease_out(p, 2.2)`：先快后慢，像真的在升。
- 诗句竖排放在画面左侧，右侧留给月亮，构图左右平衡。
- 两句提问式字幕"离开九中后的，第二个中秋 / 你那边的月亮，圆了吗？"直接对着观众本人说话。
- 14.8–16.25 s 月亮移到画面正中并放大到半径 380 px，为匹配剪辑做准备。

**转场 1：月亮 → 挂钟（匹配剪辑）**
- 挂钟在照片里的位置是 (0.705, 0.375)，半径约是照片宽度的 0.079。算出 `zoom=2.35` 时，挂钟在屏幕上的大小和位置正好与月亮重合，然后用 0.5 秒叠化。
- 意图：一个圆变成另一个圆，一句话都不用说，观众就懂了"那时候的月亮，是教室里的钟"。

**主歌 16–32 s：让观众回到真实的教室**
- 监控画面保留原始时间戳，比任何字幕都真实。
- 课表做成一张纸飞进来，最后一行"晚自习3"用红框标出来，信息准确，也有代入感。
- 快进 ×100 从 22:25 追到 22:30，屏幕角标闪烁"快进 ×100"。落回实时后，大家起身，此时画面定格去色，打出巨大的"22:30"。这一段就是"拉片"。
- 最后把 P032（班级合照，背后是教学楼）自动抠掉蓝天，换成夜空加月亮，人和楼压暗成夜色，接字幕"走出教学楼，一抬头——它就挂在楼顶上"，把主线闭合。

**蓄力 1 32–48 s：越来越密的剪辑是"情绪的加速器"**
- 军训照片原图只有 256×256，太小，不能全屏放大，于是做成拍立得，随每半拍掉落在高分辨率的军训大合照上（合照加模糊、压暗）。低分辨率素材就这样变成了风格。
- 分列式照片一拍一刀，每刀都有缩放冲击。
- 倒计时牌：第 20 小节停在 583，第 21 小节按八分音符跳 500 → 400 → … → 1，每跳一次数字卡片都会弹一下。
- 第 22 小节 16 张体育节照片快闪，每张 0.125 秒（1/32 拍）。
- 第 23 小节：推近到照片里真实的起跑器"3"、"2"，第三拍打上大字"1"，第四拍前半黑白定格加"预备——"，后半拍全黑、全静音。下一拍 drop 砸下来。

**drop 1 48–80 s："燃"是撞击、速度和人脸共同堆出来的**
- 第一拍"冲！"同时叠了 5 种冲击：满白闪光（强度 1.0，0.3 s）、震屏 26 px、RGB 分离 18 px、缩放模糊 0.12、照片从 1.3 倍快速拉到 1.05 倍。
- 内容顺序是先"场面"（航拍、方阵），再"人"（红帽子特写、比耶），再"对抗"（拔河），然后"比赛"（篮球），最后落在"人脸"（赛后采访的笑脸），情绪从燃过渡到暖。
- 72–76 s 三联屏，每个面板错拍更换。76–80 s 照片墙按每拍 3 张多的速度填满，配大字"都还记得"，通鼓过门，最后缩放模糊加闪白切进温情段。

**温情段 80–112 s：慢下来，给出可以回味的细节**
- 视觉手段：宽银幕黑边（letterbox 0.12）、散景光斑、漏光、画面叠化、字幕逐字浮现，全部是"慢"的语言。
- 高潮是 88–96 s：音乐退到只剩一层垫音，全班合唱的原声接管。画面和声音来自同一段视频的同一时刻，是同步的。
- 104–108 s 做了一条"胶片条"，平常日子的照片从右向左滑过，字幕是"原来最好的日子，是那些很平常的日子"。

**蓄力 2 112–128 s：郑重、金色**
- 成人礼素材阳光很好，统一用 `gold` 调色。
- 旗手、状元门、找爸妈的向日葵、抬头看天，镜头越切越快。
- 126–127 s 镜头往天空快速推近（缩放从 1.0 到 1.8，`ease_in(u, 2.5)`），127–128 s 全黑静音，只有"放 飞"两个字。静默一拍是 drop 前最有效的"吸气"。

**drop 2 128–160 s：全片最高点，也是一次"告别"**
- 气球升空配现场人声，大字"我们的十八岁"。
- 每小节头一个词："一起 奔跑 / 大笑 / 唱歌 / 熬夜 / 流汗 / 流泪 / 长大 / 告别"。这 8 个词从燃一路递进到伤感，给最燃的段落埋了一条"泪线"。
- 最后 4 秒（156–160 s）把 V110 里过曝的太阳慢慢溶成月亮：亮的天空像素换成夜空，暗的树影保留并压成夜色，然后在太阳的位置画上月亮。字幕"后来，太阳落下去 / 月亮升起来"，把"青春"交还给"月亮"这条主线。

**结尾 160–180 s：把所有人放进月亮里**
- 约 800 块照片瓦片从屏幕外四散处飞进来（离中心越近的越晚到），拼成一轮满月。每块瓦片按对应位置的月面亮度重新着色，所以远看是月亮，近看是照片。
- 165–169.5 s 推近到 2.1 倍，让观众认出"这是我们的照片"；之后拉远到 0.62 倍，露出星空和孔明灯。
- 最后三行是"三班的各位，中秋快乐 / 月亮替我们，记得每一个人 / 共此时"，最后 1.6 秒淡出到黑。

### 3. 节奏、剪辑、音画配合的技巧

| 技巧 | 这次怎么做的 | 为什么有效 |
|---|---|---|
| 一份总谱驱动一切 | `score.py` 是唯一的时间来源，`T(bar, beat)` 同时给合成器和剪辑用 | 卡点不靠事后对齐，天生精确；改结构只改一处 |
| 剪辑密度递增 | 蓄力段从每拍一刀，到每半拍，到每 1/32 拍 | 观众的心跳会被剪辑速度"带快" |
| drop 前静音 | 第 23 小节最后半拍、第 63 小节最后两拍，音乐和画面同时全黑 | 落差越大，drop 越炸 |
| 撞击叠层 | drop 首拍同时有闪白、震屏、RGB 分离、缩放模糊、镲、太鼓、低频冲击 | 单一效果的冲击力不够，多通道同步叠加才有"砸下来"的感觉 |
| 每个底鼓一次缩放冲击 | drop 段每拍 `add_punch(amt 0.026–0.028, 0.2 s)` | 画面随鼓"呼吸"，也就是抽吸感 |
| 匹配剪辑 | 月亮 → 挂钟；太阳 → 月亮 | 用形状讲故事，情绪不断档 |
| 真实物件做倒数 | 推到照片里的起跑器 3、2 | 比贴大字更有"原来是这样"的惊喜 |
| 速度曲线 | 快进段 `speed=lambda u: 278*ease_in(u/dur, 1.6)`，慢放 0.5–0.8 倍 | 先快后慢或先慢后快，比匀速更有叙事感 |
| 定格加去色 | `freeze=1.25, freeze_fx="bw"`，0.25 秒过渡到黑白 | "拉片"的经典语言：这一刻值得停下 |
| 原声接管 | 合唱段 BGM 编曲本身就撤到只剩垫音，再额外闪避 −12 dB | 真实的声音永远比配乐更催泪 |
| 词语递进 | "奔跑 → … → 流泪 → 长大 → 告别" | 在最燃的段落埋伏笔，燃到最后变成泪点 |
| 情绪先文字后画面 | 字幕先于关键画面 0.1–0.3 秒浮现 | 观众读到字时画面正好到位，像画面在回应文字 |

## 二、具体的创作方式

### 1. 技术栈与整体工作流

**运行环境**：云端 Linux 容器，4 核 CPU、15 GB 内存，没有 GPU。Python 3.11，Node 22（这次没用上）。外网走代理，不少站点被拦截，详见第三部分的坑 4。

**用到的库和工具**

| 类别 | 工具 | 用途 |
|---|---|---|
| 编解码 | ffmpeg 6.1（apt 安装）、ffprobe | 探测、按时间窗解码成 rawvideo、分块编码、拼接、2-pass 压制、抽帧检查、镜头切换检测 |
| 数值计算 | numpy 2.x、scipy（signal.butter / sosfilt / fftconvolve、ndimage） | 合成器、滤波、卷积混响、限幅 |
| 加速 | numba `@njit` | 逐样本状态变量滤波器（笛子气息、riser 扫频） |
| 图像 | opencv-python-headless **< 5**（4.14）、Pillow | warpAffine、模糊、Haar 人脸检测、字形渲染、EXIF 旋转 |
| 音频分析 | librosa 0.11、soundfile、pyloudnorm | RMS、节拍跟踪、起音检测、LUFS 响度测量与归一化 |
| 字体 | fontTools | 读字体 cmap，缺字时回退到其他字体 |
| 作图 | matplotlib | BGM 频谱图和响度曲线（用于"看"音乐） |
| 字体来源 | Google Fonts（OFL 协议） | 马善政（书法）、思源宋体 Regular/Black、思源黑体 Black、龙藏体、志莽行书、站酷庆科黄油体、站酷小薇 |

**完整工作流**（实际执行顺序）

```
0 环境    装 ffmpeg / pip 依赖 / 下载字体
1 盘点    inventory.py        MD5 去重 → ffprobe → build/inventory.json（217 份）
2 看片    contact_sheets.py   人工看 9 张照片联系表 + 10 张视频联系表
3 分析    analyze.py          运动/亮度/清晰度/响度/人脸 → analysis.json + 每段视频的密帧条
4 策划    挖线索 → 定主题 → 定情绪曲线 → 写 score.py（结构、和弦、旋律）
5 配乐    music.py → assets/bgm.wav；verify_audio.py 做客观检查，迭代 3 轮
6 引擎    gfx.py（底层）/ gen.py（程序化画面）/ layers.py（图层）/ media.py（素材缓存）
7 剪辑    timeline.py：逐段写镜头
8 预览    preview.py 抽 5–30 帧拼一张图，看完再改，迭代 6 轮
9 混音    mix.py：BGM + 原声 → soundtrack.wav
10 渲染   render.py：4 进程分块渲染 → 拼接 → 2-pass H.264
11 验收   解码成片抽帧；镜头切换检测对拍子网格；测成片 LUFS；针对性修复并重渲 2 个分块
12 交付   git push（89.4 MB）+ 另压一个 720p 版 28 MB 直接发给用户
```

#### 2.2 图层模型（layers.py）

每一帧的渲染流程是：清空画布 → 按 z 顺序绘制所有活跃图层 → 全局后期。

```python
def render_frame(t, fno):
    cv = np.zeros((H, W, 3), np.float32)          # float32，取值 0..1
    for l in LAYERS:                               # 已按 z 排好序（稳定排序）
        if l.active(t): l.draw(cv, t)
    return POST.apply(cv, t, fno)                  # 冲击/震屏/闪白/颗粒/暗角/黑边
```

`Shot` 是核心图层，一个类覆盖了照片和视频的全部需求：

```python
shot(t0, t1, "V11", src_t=284.2, grade="cctv",
     zoom=(1.0, 1.12), focus=(0.45, 0.5),         # 常量或 (起, 止)
     speed=1.0 或 lambda u: ...,                   # 变速曲线：局部时间 → 素材偏移
     rate=0.5,                                     # 解码帧率（延时快进时省内存）
     freeze=1.25, freeze_fx="bw",                  # 定格并去色
     fit="cover"|"blurfill",                       # 竖屏素材用模糊背景填充
     tin=("whip",0.2,±1)|("dissolve",d)|("zoom",d)|("slide",d,±1)|("iris",d),
     rect=(x,y,w,h),                               # 分屏面板
     overlay=fn, ease=fn, z=...)
```

转场不需要单独的转场对象，而是写在进入的镜头上。为了保证叠化、甩镜下面永远有画面，`shot()` 会自动把上一个镜头延长：

```python
def shot(*a, **k):
    s = Shot(*a, **k)
    if s.tin:        # 进入转场会把"出去的镜头"延长 d 秒垫在下面
        for l in reversed(LAYERS):
            if isinstance(l, Shot) and l.rect == s.rect and abs(l.t1 - s.t0) < 1e-6:
                l.t1 = s.t0 + s.tin[1]; break
    return add(s)
```

#### 2.3 一个函数搞定取景、Ken Burns 和不露边（gfx.place）

```python
def place(img, zoom, focus, offset=(0,0), rot=0, fit="cover", size=(W,H), transparent=False):
    s = cover_scale(sw, sh, w, h) * zoom           # 先铺满，再乘缩放
    fx, fy = focus[0]*sw, focus[1]*sh              # 焦点（人脸重心）落在画面中心
    if fit == "cover" and rot == 0:                # 夹紧焦点，保证不露边
        hw, hh = w/2/s, h/2/s
        fx = min(max(fx, hw), sw-hw); fy = min(max(fy, hh), sh-hh)
    M = affine(s, rot, (fx, fy), (w/2+offset[0], h/2+offset[1]))
    if transparent:  # 转场位移时：画面外透明，而不是镜像
        fr = cv2.warpAffine(img, M, size, borderMode=cv2.BORDER_CONSTANT, borderValue=(-1,-1,-1))
        return np.maximum(fr, 0), (fr[..., :1] >= 0).astype(np.float32)
    return cv2.warpAffine(img, M, size, flags=cv2.INTER_LINEAR, borderMode=cv2.BORDER_REFLECT101)
```

用 `warpAffine` 做浮点仿射，而不是按整数像素裁剪再缩放，这样慢速推拉不会抖。

#### 2.4 视频按"时间窗"解码并缓存（media.py）

```python
cmd = ["ffmpeg","-v","error","-ss",f"{t_in:.3f}","-i",src,"-t",f"{dur+2/rate:.3f}",
       "-vf",f"fps={rate},scale={w}:{h}:flags=bicubic","-f","rawvideo","-pix_fmt","rgb24","-"]
frames = np.frombuffer(raw, np.uint8).reshape(n, h, w, 3)   # 存 uint8，用到时才转 float
```

- 每个镜头只解码它会用到的那一段。`-ss` 放在 `-i` 前面做快速定位，ffmpeg 6 在这种写法下也是帧精确的。
- 竖屏手机视频（旋转 −90°）由 ffmpeg 解码时自动转正。盘点时需要把 w、h 对调。
- LRU 缓存上限 1.4 GB 每进程（4 个进程共约 5.6 GB）。
- 延时快进时，解码帧率取 `FPS / speed`。例如 ×100 的快进用 `rate=0.5`，也就是每 2 秒素材只解 1 帧。

### 4. 音频处理

#### 4.1 原创 BGM：从零合成（music.py，约 614 行）

- **调式与和声**：D 宫调五声音阶（D E F♯ A B），国风感；和弦用卡农进行 D–A–Bm–F♯m–G–D–G–A，这是回忆杀的"标准和声"。蓄力段用 Bm–G–D–A（史诗感），温情段用 G–A–F♯m–Bm–Em–A–D–D。
- **旋律**：抒情主题 THEME（8 小节，前奏、主歌、温情、尾声用）和节奏型 HOOK（8 小节，两个 drop 用，含切分和八分音符）。旋律都写成 `(小节, 拍, 时值, midi)` 元组，和剪辑用同一套坐标。
- **乐器（全部自己合成，没有采样）**

| 乐器 | 做法 |
|---|---|
| 古筝 | 加性合成 15 个泛音，每个泛音乘 `sin(πk·0.18)`（拨弦位置梳状效应），高次泛音衰减更快；起音 50 ms 内音高上扬 1.2%（按弦）；0.35 s 后淡入 5.2 Hz 揉弦；外加 3 ms 拨弦噪声。刮奏按五声音阶每 25–70 ms 一个音 |
| 笛子 | 整条旋律作为一条连奏线生成：音与音之间 45 ms 几何插值滑音；长音 0.25 s 后加 5.6 Hz 颤音；音色是基音 + 0.28×二次 + 0.12×三次谐波；**气息**是白噪声过带通（中心频率跟随音高，numba 写的 SVF 滤波器） |
| 钢琴 | 11 个非谐泛音（`B = 0.00035`）+ 成对微失谐 + 击弦噪声；松键后 0.25 s 阻尼 |
| 弦乐 pad | 带限锯齿（逐谐波加性合成，带平滑低通滚降）× 2 个失谐声部，慢起音 ADSR |
| 贝斯 | 正弦次低音 + 低通锯齿，tanh 饱和；drop 段八度跳的八分音符 |
| 鼓组 | kick（110 → 45 Hz 指数扫频加 click）、snare、clap（3 次 burst 加尾音）、闭 / 开镲、crash（高通噪声加 4 个金属正弦）、tom、**太鼓**（97 → 52 Hz，衰减 0.45 s） |
| 效果 | riser（带通噪声中心从 250 Hz 扫到 10 kHz，外加上行正弦）、impact（70 → 30 Hz 次低音）、反向镲、whoosh、FM 钟声 |

- **编曲上的卡点设计**：蓄力 1 的军鼓从八分 → 十六分 → 约三连十六分滚奏，第 23 小节前三拍打"太鼓 3-2-1"，最后半拍静音；drop 首拍 impact + crash + taiko；每 4 小节一个 crash；过门用 tom；drop 2 前是两拍静音加一次古筝上行刮奏。
- **合唱窗口**：88–96 s 编曲自身撤到只剩 0.05 电平的 pad，不放旋律，给原声让出空间，避免调性冲突。
- **母带处理链**：
  1. sidechain：只在两个 drop 段，按每个 kick 的包络 `1 - 0.65·exp(-t/0.16)` 压 pad 和 bass
  2. 卷积混响：合成冲激响应，大厅 3.2 s、房间 0.8 s
  3. 28 Hz 高通
  4. **前视限幅**：`minimum_filter1d(10 ms)` → `uniform_filter1d(5 ms)` → 60 ms 慢释放，天花板 0.93
  5. pyloudnorm 归一化到 −12.5 LUFS，迭代 3 次（限幅会让响度再掉一点）
- **客观验收**（因为我听不到声音）：整体 −12.9 LUFS，峰值 −1.01 dBFS；分段响度见 1.2 节的表；另外画了频谱图，用来看贝斯是不是过重。

#### 4.2 原声的使用（mix.py）


- **同步原则**：音频的素材入点 = 画面那个镜头的 `src_t`，放置时刻 = 镜头的 `t0`，所以口型和动作天然对得上。
- **响度匹配**：先测片段 RMS，再缩放到目标 dB，不用"猜音量"。
- **淡入淡出**：平方曲线，时长 0.2–1.0 s；闪避（duck）跟随同一条包络。
- **成片实测**：合唱段之前 −19.0 LUFS，合唱段 −15.7 LUFS，说明原声确实"接管"了；drop 2 加人群 −11.7 LUFS；整片 −13.8 LUFS。

#### 4.3 卡点的验证方法

- 画面：用 `ffmpeg -vf "select='gt(scene,0.28)',showinfo"` 检测成片里所有硬切点，和 1/16 拍网格比较。结果是 120 个切点中 85% 在一帧（33 ms）以内，中位偏差 0 ms。剩下的 15% 逐个核对过，都是镜头内部的运动（监控画面切换机位、拔河时手机晃动）或者故意做的 1/32 拍快闪。**所有刻意剪的刀都在网格上。**
- 音频：librosa 节拍跟踪显示 117.5 BPM、偏差 42 ms。这是测量本身的分辨率问题（hop 512 / 22050 Hz ≈ 23 ms，加上速度估计是分档的），不是真的没对上，见坑 9。

```bash
ffmpeg -y -i master.mp4 -c:v libx264 -preset slow -b:v 3700k -maxrate 9M -bufsize 12M \
       -pix_fmt yuv420p -tune film -g 60 -pass 1 -an -f mp4 /dev/null
ffmpeg -y -i master.mp4 -i soundtrack.wav -c:v libx264 -preset slow -b:v 3700k -maxrate 9M \
       -bufsize 12M -pix_fmt yuv420p -tune film -g 60 -pass 2 -c:a aac -b:a 256k \
       -shortest -movflags +faststart -metadata title="共此时 · 三班中秋回忆" out.mp4

# 4) 30 MB 以内的分享版
ffmpeg -i out.mp4 -vf scale=1280:720 -c:v libx264 -preset slow -b:v 1100k -pass 1 -an -f mp4 /dev/null
ffmpeg -i out.mp4 -vf scale=1280:720 -c:v libx264 -preset slow -b:v 1100k -pass 2 \
       -c:a aac -b:a 128k -movflags +faststart share_720p.mp4
```

**码率怎么反推**：`总码率(kbps) = 目标体积(MB) × 8 × 1000 / 时长(s)`，视频码率 = 总码率 − 音频码率。
- 这次目标约 95 MB：95×8000/180 ≈ 4222 kbps，减去音频 256k，视频取 3700k 留余量，实际得到 89.4 MB。
- 30 MB 分享版：28×8000/180 ≈ 1244 kbps，减去 128k，视频取 1100k，实际得到 28.1 MB。

另外，颗粒会显著吃码率，想要更小的文件，可以把颗粒强度降到 0.015 以下。

### 6. 时间分配与提速

| 环节 | 墙钟时间（约） | 说明 |
|---|---|---|
| 环境搭建（ffmpeg、pip、字体、试探网络） | 8 min | apt 第一次失败，需要先 update；GitHub 和 HF 被拦截，要找替代来源 |
| 盘点、联系表、机器分析、看片 | 15 min | 读图最花时间，但这是主题的来源，不能省 |
| 写总谱和合成器，迭代 3 轮母带 | 12 min | 每轮合成加分析约 1 分钟 |
| 引擎：gfx / gen / layers / media，月亮迭代 3 版 | 12 min | |
| timeline 编写和 6 轮预览修复 | 15 min | 每轮预览 20–50 秒 |
| **全片渲染** | **21.5 min** | 帧渲染 856 s（每块 40–82 s × 60 块 / 4 进程）+ 2-pass 压制约 440 s |
| 验收、修 bug、重渲 2 块、重新压制 | 8 min | 其中 2-pass 重新压制又花了约 7 分钟 |
| 720p 分享版、提交推送 | 3 min | |

**最耗时的三件事，以及提速办法**：

1. **2-pass slow 压制**（每次约 7 分钟，修一个小 bug 也要全部重压）
   - 迭代阶段用单遍压制：`-crf 20 -preset medium`；最后交付时再做 2-pass。
   - 或者换成 `-preset medium`，速度大约快一倍，体积相差不大。
2. **全片帧渲染**（0.3–1.8 s/帧）
   - 在内层循环里预合成静态元素，比如落定的拼月、照片墙、文字精灵都要缓存。
   - 夜空这类平滑背景用半分辨率画，再放大。
   - 先用 `--draft` 出半分辨率草稿（render.py 已经支持）。
   - 能用 GPU 的环境可以换 moderngl 或 skia。
3. **看片**：联系表一次看 20 张，比逐张快得多；再配合运动能量和响度曲线，直接定位"最有料的那几秒"。

### 1. 逐项打勾清单

#### 开工前
- [ ] `which ffmpeg ffprobe`：没有就 `apt-get update && apt-get install -y ffmpeg`。**一定要先 update**，这次第一次安装就是因为没 update 而失败的
- [ ] `nproc`、`free -g`、`df -h`：决定并行进程数和每个进程的缓存上限（4 核 15 GB → 4 进程，每个 1.4 GB）
- [ ] 测网络：`curl -sS -o /dev/null -w "%{http_code}"` 逐个测字体、模型、音乐的来源；403 就换来源，不要硬等
- [ ] 中文字体：确认至少有一款书法体和一款宋体 / 黑体能用，**并检查标点（· — ！「」）有没有字形**
- [ ] 素材：MD5 去重；每个文件都 try 打开并 `load()`；ffprobe 读 rotation；列出损坏文件
- [ ] 隐私：找出含姓名、证件照、名单的素材，默认不用
- [ ] 交付约束：Git 单文件上限 100 MB（超过 50 MB 会警告）；聊天发送上限 30 MB。先把目标码率算出来
- [ ] 版权：BGM 自制，或者确认是 CC0；字体要选 OFL 协议的
- [ ] 推断出来的事实（年份、"第几个中秋"、歌名）要列出来，交付时请用户核对

#### 制作中
- [ ] 先写总谱（BPM、小节、段落表），所有镜头时间只能用 `T(bar, beat)` 表达，禁止写死秒数
- [ ] 音乐先做完、先验收（分段 LUFS、峰值、频谱图），再开始剪辑

- [ ] 每次预览图换一个新文件名，避免看到缓存里的旧图
- [ ] 转场的镜头下面必须有画面（自动延长出去的镜头）；位移类转场不能用镜像边界
- [ ] 竖屏素材用 blurfill，或者 cover 时指定焦点

- [ ] 统计每帧耗时，超过 1 s/帧的就做缓存或降分辨率
- [ ] 全局遮罩（黑场、闪白）要注意层级：**应该在文字下面的遮罩就做成图层，不要放到后期**

#### 导出前
- [ ] 总帧数 = 时长 × 帧率；最后一帧时间 < 时长
- [ ] 音频长度等于视频长度，加 `-shortest`；成片 duration 要等于 180.000
- [ ] 混音峰值 ≤ −0.3 dBFS；整体约 −14 LUFS；原声段落的响度是否确实"接管"了
- [ ] 分块渲染可以续跑（已存在的块跳过），修改后只删受影响的块
- [ ] 按目标体积反推码率，然后 2-pass

#### 交付前

- [ ] 镜头切换检测对拍子网格，逐条解释不在网格上的切点
- [ ] ffprobe 核对编码、分辨率、帧率、时长、音频参数
- [ ] 测成片 LUFS 和各关键段落的响度
- [ ] 体积超过聊天上限就另压一个分享版
- [ ] 明确告诉用户：哪些东西是推断的、哪些没能验证（比如"音乐我听不到，只做了客观测量"）

### 2. 踩过的坑

**坑 1. 环境里没有 ffmpeg，apt 第一次安装失败**
- 现象：`which ffmpeg` 为空；`apt-get install -y ffmpeg` 失败。
- 原因：容器里的 apt 索引是空的或者过期了。
- 解决：`apt-get update` 之后再 install，得到 ffmpeg 6.1.1。imageio-ffmpeg 自带的静态版可以临时顶上，但没有 ffprobe。
- 预防：开工第一条命令就是 `apt-get update && apt-get install -y ffmpeg`。

**坑 2. 素材里有损坏的"假 JPG"**
- 现象：`PIL.UnidentifiedImageError`（2 张是未知格式的数据，1 张被 `file` 识别成 Photoshop 色板）；还有 1 张能 open，但 `load()` 时报 `broken data stream`。
- 原因：微信导出的文件损坏或被加密；Pillow 的 `open()` 是懒加载，不会读到像素数据。
- 解决：`try: im = exif_transpose(Image.open(p)); im.load() except: skip`，并记录被跳过的文件。
- 预防：盘点阶段对每张图都 `load()` 一次，损坏清单写进 README。

**坑 3. 大量重复素材**
- 现象：290 个文件里有 68 份字节级完全相同（同一段合唱放在两个文件夹里，同一张照片既有原名又有"微信图片_xxx"的名字）。
- 解决：MD5 去重；重复时优先保留有意义的文件名。
- 预防：去重必须放在第一步，否则联系表和随机抽图都会重复。

**坑 4. 网络被拦截：字体、语音识别模型、CDN**
- 现象：`github.com/google/fonts/raw/...` 返回 403（仓库不在本会话的授权范围内）；`cdn.jsdelivr.net` 返回 403；`huggingface.co` 和 `openaipublic.azureedge.net` 都连不上，所以 Whisper 语音转写做不了。
- 原因：云端容器的出站网络策略。
- 解决：
  - 字体：`fonts.googleapis.com/css2?family=Ma+Shan+Zheng` **不带浏览器 UA 请求时返回的是整包 TTF 的地址**（带浏览器 UA 返回的是切片 woff2），`fonts.gstatic.com` 可以正常下载。
  - npm registry 也能访问，可以作为备选。
  - 语音识别放弃，改用"响度曲线 + 看帧"来选原声片段，而且**不给没听过的对白配字幕**。
- 预防：开工时逐一测试来源；准备好不依赖网络的备选方案，比如自己合成 BGM。

**坑 5. OpenCV 5 里没有 `CascadeClassifier`**
- 现象：`AttributeError: module 'cv2' has no attribute 'CascadeClassifier'`，而且 `cv2.data` 目录下也没有 xml 文件。
- 原因：直接 `pip install opencv-python-headless` 装到了 5.0，Haar 级联在这个版本里被移除了。
- 解决：`pip install "opencv-python-headless<5"`，装 4.14。
- 预防：依赖要写死版本上限。

**坑 6. 竖屏手机视频的旋转**
- 现象：ffprobe 报 1920×1080，但 side_data 里写着 `rotation=-90`，实际画面是竖的。
- 原因：手机录像靠元数据标记旋转，而不是真的转了像素。
- 解决：盘点时读 rotation，是 ±90 就对调 w、h；解码时 ffmpeg 默认会自动转正。
- 预防：盘点表里要记录"显示用宽高"，而不是编码宽高。

**坑 7. 延时快进的内存爆炸风险**
- 现象：计划把 280 秒的监控压成 2.6 秒来快进。按 30 fps 解码需要 9000 帧，约 13 GB。
- 解决：给 Shot 加 `rate` 参数，按需要的采样率解码。×100 快进用 `rate=0.5`，只解 139 帧。
- 预防：解码帧率 = `min(素材帧率, 输出帧率 / 速度)`；每个进程的缓存设上限，按总内存除以进程数来算（从 2.5 GB 改成了 1.4 GB）。

**坑 8. BGM 第一版太响，而且没有起伏**
- 现象：整体 −7.7 LUFS；主歌 −8.4，drop −6.8，几乎一样响；频谱图上 64–128 Hz 一片亮块。
- 原因：
  1. 我自己写的"自动电平"（按 RMS 反向增益）本质上是一个压缩器，把起伏压平了；
  2. 贝斯长音电平 0.3，还过了 tanh，接近方波，能量太大。
- 解决：删掉自动电平；贝斯长音降到 0.13，八分音符改为 0.17–0.19；笛子在 drop 段 +4 dB，镲 −2 dB；最后用前视限幅加 LUFS 归一化。
- 结果：前奏 −21.3、drop −11.0 / −10.6、尾声 −19.2，峰值 −1 dBFS。
- 预防：母带处理不要做"动态压平"；每个总线分段打印电平（`dry / wet / side / fx`），用数字来配平。

**坑 9. librosa 说"节拍没对上"，其实是误报**
- 现象：`beat_track` 给出 117.5 BPM，和网格的中位偏差 42 ms；kick 起音 15 ms 内的检出率只有 50%。
- 原因：hop 512 / 22050 Hz ≈ 23 ms 的时间分辨率，速度估计又是分档的；密集混响和其他乐器会干扰起音检测。所有音符本来就是按采样点精确放置的。
- 解决：以 `cues.json`（合成器实际放置的时间）为准；容差放宽到一个 hop（25 ms）。
- 预防：分析工具的分辨率要先弄清楚；画面卡点用 ffmpeg 场景检测来验证，更直接。

**坑 10. 我听不到声音**
- 现象：模型无法直接听音频，好不好听没法主观判断。
- 解决：只能用客观指标兜底：分段 LUFS、峰值、频谱图、每个总线的电平、节拍检测、原声段落的响度变化。和声上坚持五声音阶加标准进行，降低"难听"的风险。
- 预防：交付时明确告诉用户"请务必戴耳机听一遍"。

**坑 11. 旋律错位了一个乐句**
- 现象：前奏的钢琴本来应该在第 4–7 小节弹主题的后半句，结果被放到了第 0–3 小节，和弦对不上。
- 原因：`THEME_AT(4,7)` 已经把小节号归零了，调用时 `bar0` 还传了 0。
- 解决：`melody(THEME_AT(4, 7), 4, ...)`。
- 预防：旋律片段统一使用"相对小节号"，放置时传绝对小节号；写完对照和弦表逐段检查。

**坑 12. 程序化月亮做了 3 版**
- 第 1 版：陨石坑边缘太锐、太多（260 个），放射纹像一束直线，整体发灰，像卡通。
- 第 2 版：月海成了一个个圆斑，像奶酪。
- 第 3 版：把月海的高斯块**加起来**后，糊成了一整片。
- 最终版：先对坐标做 fbm 域扭曲，让海岸线不规则；多个块之间取 **max** 而不是相加；阈值为 `(m + 0.4(n - 0.5))·1.6 - 0.5`；陨石坑减到 140 个且更柔和；放射纹先模糊再以 0.05 的权重叠加。
- 预防：程序化素材一定要单独渲染一张大图来检查，迭代完成后再接入时间线。

**坑 13. 孔明灯画反了**
- 现象：下宽上窄的平顶梯形，看起来像一个个塑料桶。
- 解决：改成上宽下窄的圆顶；火光在底部，内部亮度从下往上衰减；外发光 18 px。

**坑 14. 夜空渲染太慢**
- 现象：一帧夜空、孔明灯加月亮要 486 ms（第一帧还因为生成纹理花了 8.7 s）。
- 原因：每帧都在全分辨率上算月亮距离场和云层混合。
- 解决：距离场按月亮位置（按 8 px 量化）用 lru_cache 缓存；夜空和云在半分辨率算好再放大；星星在放大之后画，保持锐利。降到约 117 ms。
- 预防：平滑的背景一律用半分辨率；所有与帧无关的东西都缓存。

**坑 15. 同名覆盖导致看到旧图**
- 现象：月亮改完后重新保存为 `test_moon.jpg`，读回来的图和上一版一模一样。
- 原因：读图工具对同一路径有缓存。
- 解决和预防：每次迭代都换文件名（test_moon2/3/4、prev_a…prev_g）。

**坑 16. 常量元组和"起止对"分不清**
- 现象：`focus=(0.5, 0.45)` 本意是一个常量点，却被当成"从 0.5 插值到 0.45"，结果返回了一个标量。
- 解决：拆成 `_scalar(v)` 和 `_vec(v)`：数字就是常量；`v[0]` 是元组才表示起止对。
- 预防：动画参数的约定要写进 docstring，或者干脆用专门的类型，比如 `Anim(a, b)`。

**坑 17. 往 RGBA 画布上贴图时维度广播出错**
- 现象：做拍立得说明文字时报 `operands could not be broadcast together with shapes (81,73,4) (81,73,3)`。
- 解决：`blit` 检测到目标是 4 通道时，走标准的 alpha over 合成（`out_a = a + a0(1 - a)`）。

**坑 18. 书法字体缺标点，显示成方框（豆腐块）**
- 现象："2022 · 夏"里的"·"在马善政字体下显示为方框。
- 原因：很多中文书法体只有汉字，没有部分标点。
- 解决：用 fontTools 读 cmap，缺字时自动回退到思源宋体：`if not has_glyph(name, ch): name = "serif"`。
- 预防：先写一个脚本，对全部文案逐字检查每种字体的 cmap，把缺的字列出来。

**坑 19. 叠化从黑场里浮出来**
- 现象：戏剧段在 101.05 s、103.05 s 两个切点上，新镜头从全黑中淡入。
- 原因：`tin=("dissolve", 0.3)` 只降低了新镜头的透明度，而上一个镜头已经在切点结束，下面没有东西。
- 解决：`shot()` 里自动把"出去的镜头"延长转场时长（见 2.2 节的代码）。
- 预防：抽帧预览要取切点后 0.05 s 的时刻。

**坑 20. 甩镜、滑入时画面出现镜像或"倒置"的人**
- 现象：三联屏滑入时，面板里出现上下颠倒的人。
- 原因：`cv2.BORDER_REFLECT101` 在画面位移后，会用镜像内容去填补露出来的边缘。
- 解决：只要有位移或旋转，就用常量边界值 −1 作为透明标记，生成遮罩再合成；模糊时遮罩也一起模糊。
- 预防：Ken Burns 可以用镜像边界（配合焦点夹紧，本来就不会露边），**转场位移必须用透明边界**。

**坑 21. 分屏的第一拍有两个面板是黑的**
- 现象：三联屏开场，右边两块面板要等第 2、3 拍才出现。
- 解决：前 3 个面板同时在开场时刻出现，之后再错拍轮换。

**坑 22. 拼月尾声渲染极慢**
- 现象：4.8 s/帧，因为每帧要做约 800 次小图 warpAffine。
- 解决：瓦片全部落定之后（`u ≥ max(delay) + 1.6`），把它们一次性预合成成一张 2.1 倍的大精灵，每帧只贴这一张；飞行阶段才逐块画；画面外的瓦片直接跳过。降到约 0.5–0.9 s/帧（按尾声各分块 40–82 s / 90 帧推算）。
- 顺带：瓦片缩略图从 26 px 提高到 64 px，推近时依然清晰。

**坑 23. 静音黑场把文字也盖掉了（到成片验收才发现）**
- 现象：成片 127.6 s 应该显示"放 飞"，实际是全黑；47.85 s 的"预备——"也被盖掉了。
- 原因：黑场放在后期（`POST.black`）里，而后期在所有图层之后执行，于是把文字一起涂黑了。之前的预览没有恰好抽到这两帧。
- 解决：黑场改成一个 z=48 的图层（`cv.fill(0)`），在文字（z=50）下面；"预备——"延长到 drop 前 0.05 s。删掉 c0015 和 c0042 两个分块重渲，其他 58 块直接复用。
- 预防：**图层该在文字下面的，就做成图层**，后期里只放全局效果（颗粒、暗角、冲击等）；验收必须解码成片抽帧，而且要覆盖所有静音和黑场时刻。

**坑 24. 字幕在亮背景、复杂背景上读不清**
- 解决：`cap()` 自动在字幕所在行加一条高斯暗带（±90 px，最多压暗 45%），字形本身再加暗色 glow 和投影。

**坑 25. 尾声大字压在月亮上**
- 现象：拉远还没结束，"三班的各位，中秋快乐"就出现了，和巨大的拼贴月亮重叠。
- 解决：拉远时间从 7.5 s 缩短到 6 s；祝福语推迟 1 小节，副标题推迟 1.5 拍。
- 预防：大字的出现时间要和视觉中心的运动轨迹一起设计。

**坑 26. 文件体积与传输限制**
- 现象：成片 89.4 MB，可以推到 GitHub（有 50 MB 警告，但低于 100 MB 硬上限）；但聊天工具发文件有 30 MB 上限，直接发送失败。
- 解决：另压一个 720p、1100k 的 2-pass 版本，28.1 MB，发送成功。
- 预防：开工时就定好两个目标体积（仓库版和分享版），并按公式算出码率；超过 100 MB 就要考虑 Git LFS 或网盘。

**坑 27. 工具层面的限制**
- `sleep 60 && cat log` 这种等待方式被执行环境拦截了。改成 `until grep -q ... ; do sleep 10; done`，并设 `timeout 590`，或者放到后台运行、等完成通知。
- 渲染要用 `nohup ... &` 放到后台，日志逐块打印，方便随时查看进度。

**坑 28. 原声和 BGM 调性冲突的风险**
- 现象：合唱的调不一定是 D 调，叠在旋律上会打架。
- 解决：编曲层面让出空间，合唱窗口只保留 0.05 电平的 pad，不放旋律；再额外闪避 −12 dB；原声先高通 90 Hz，去掉手机录音的低频轰鸣。

**坑 29. 素材内容不确定，不乱写**
- 文件名"合唱-海底"暗示唱的是《海底》，但我没有核实，所以文案写成"那年的合唱"，不写歌名。
- "第二个中秋"、"2023 秋运动会"都是推断出来的，交付时已经列出来请用户核对。

### 1. 代码视频制作流程模板

```
阶段 0 · 环境（10 min）

  inventory.py      → MD5 去重、try load()、ffprobe（含 rotation）、分配 ID（P### / V##）
  contact_sheets.py → 照片 20 张一页；视频每段 8 帧一行
  analyze.py        → 每 0.2 s 运动 / 亮度 / 清晰度，每 0.1 s RMS，人脸焦点，密帧条

阶段 2 · 策划（10 min）
  a. 列"线索表"：素材里的文字、时间戳、文件名、道具、形状

  d. 写全文文案（字幕、标题、诗句）

阶段 3 · 总谱与音乐（15 min）
  score.py : BPM/BARS/SECTIONS/CHORDS/THEME/HOOK/T(bar,beat)
  music.py : 乐器 → 编曲（按段落函数）→ sidechain → 混响 → 限幅 → LUFS
  verify_audio.py : 分段 LUFS + 频谱图，迭代到各段有明显起伏

阶段 4 · 引擎（复用本项目的 gfx / gen / layers / media）
  需要新效果时：先写成一个函数，单独渲染一张图检查，确认后再接入

阶段 5 · 剪辑（20 min）

阶段 8 · 验收
  解码成片抽 30 帧拼图 → 看静音、转场、字幕
```
