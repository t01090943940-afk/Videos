# 《同一个月亮》中秋代码视频 · 复盘经验总结

> 项目：2 分钟中秋短片，画面逐帧由 Canvas 2D 代码绘制，配乐与音效由 Web Audio 合成，最终导出 1920×1080 / 30fps / H.264 + AAC 的 MP4，并发布一个可在线播放的 HTML 版本。
> 产物：`moon.html`（854 行，87 KB，单文件，含全部画面与配乐代码）、`同一个月亮.mp4`（母版 108 MB）、`同一个月亮_1080p.mp4`（分享版 27.6 MB）。
> 实际耗时：约 53 分钟（从开工到交付分享版）。

---

## 一、踩过的坑

### 1. 本地预览时中文全部变成乱码
- **现象**：第一次用 Playwright 截 29 张样帧，拼成联系表后，所有中文字幕、标签都显示成 `è¿™ä¸ªæ—¶ä»£` 这类乱码，英文正常。
- **根本原因**：`moon.html` 是按 Artifact 页面规范写的，不带 `<!doctype>`、`<html>`、`<meta charset>`（发布时平台会自动包一层带 charset 的骨架）。本地用 `python3 -m http.server` 提供文件时，响应头不带 charset，Chromium 就按 Latin-1 解码了。
- **解决**：在 Playwright 里拦截页面请求，自己补上骨架和字符集：
  ```js
  await p.route('**/moon.html', r => r.fulfill({
    body: '<!doctype html><html><head><meta charset="utf-8"></head><body>' + html + '</body></html>',
    contentType: 'text/html; charset=utf-8'}));
  ```
- **下次避免**：只要是“发布时由平台补骨架”的页面，本地渲染管线里一律用 `route.fulfill` 注入 `charset=utf-8`；截的第一张图必须带中文，先确认字形正常再往下做。

### 2. 修复没经单帧验证就去全量渲染，结果多渲染了一遍
- **现象**：联系表里 78.8 秒（风格汇聚之后）的满月后面有一条竖向的浅色光带。我判断是 `grid(t,.8)` 覆盖了面板透明度，改成 `grid(t,.8*pa)` 后没有重新截图，直接全量渲染。结果 MP4 抽帧时，光带还在。
- **根本原因**：真正的原因是 `techMoon(x,y,r,a=1)` 函数内部写了 `c.save(); c.globalAlpha=a;`，把外面设好的淡出透明度直接覆盖成 1。科技风月亮的光晕被裁在 420 像素宽的面板里，就成了那条光带。
- **解决**：调用时把当前透明度传进去：`techMoon(cx,my,r,c.globalAlpha)`；然后只重渲染后半段（第 1800–3600 帧），和已有的前半段拼接。多花了约 6 分钟。
- **下次避免**：
  1. 所有绘制辅助函数一律**乘**透明度（`c.globalAlpha *= a`），不要**赋值**；
  2. 每次修复后，先用 `shots.mjs` 重新截出问题所在那一帧，确认修好了再全量渲染；
  3. 渲染器写成“纯函数 + 帧区间”的形式（这次是这样写的，所以才能只重渲半段）。

### 3. Bash 工具 2 分钟超时，`sleep 240` 被杀掉
- **现象**：想等渲染进度，执行 `sleep 240; cat render.log`，返回 `Exit code 143 / timed out after 2m`。
- **原因**：工具单次命令默认超时 120 秒。
- **解决**：渲染一律用 `nohup sh -c "..." &` 放到后台跑，把进度写进 `render.log`；每次轮询时 `sleep` ≤ 115 秒。
- **下次避免**：超过 1 分钟的任务（渲染、两遍编码）从一开始就放后台，并且脚本里每 300 帧打一行日志。

### 4. 母版 108 MB，发不出去
- **现象**：`SendUserFile` 报错：`107.9 MiB exceeds the 30 MiB upload limit`。
- **原因**：母版用的是 `crf 17 + preset medium`，120 秒平均码率约 7.5 Mbps；纸张纹理、胶片颗粒和星空会进一步推高码率。
- **解决**：用两遍 x264 定码率 `-b:v 1750k` 加 `aac 160k`，得到 28,970,516 字节（27.6 MiB），分辨率仍是 1080p。两遍编码约 4.5 分钟。
- **下次避免**：开工前就问清楚交付渠道的体积上限（这次是 30 MiB），并按公式预算码率：
  `视频 kbps ≈ 目标MB × 8192 ÷ 时长秒 − 音频 kbps`（28 MB、120 秒 → 约 1911 kbps，扣掉音频 160，视频取 1750）。
  另外，两遍编码会留下 35 MB 的 `ffmpeg2pass-0.log.mbtree`，记得删掉。

### 5. 容器里拿不到 Google Fonts；Canvas 也不会自动加载字体
- **现象/风险**：在线版用 Google Fonts，但渲染容器的网络只放行 npm/pip/GitHub 等白名单。另外，Canvas 的 `fillText` 不会触发字体加载，字体到得晚了也不会重绘，第一帧会直接用回退字体。
- **做法**：
  - 用 `npm i @fontsource/ma-shan-zheng @fontsource/noto-serif-sc @fontsource/long-cang @fontsource/noto-sans-sc @fontsource/jetbrains-mono @fontsource/cormorant-garamond` 从 npm 拿字体；
  - 用 `fonts.mjs` 把各包里的 CSS 拼成 `localfonts.css`（818 KB），把 `url(./files/` 改写成 `http://localhost:8765/node_modules/@fontsource/<包名>/files/`；
  - 在 Playwright 里把 `fonts.googleapis.com` 的请求拦截下来，返回本地 CSS，`fonts.gstatic.com` 直接 abort；
  - 页面里用 `document.fonts.load(字体规格, 全片所有文字)` 预加载。中文字体按 unicode-range 被切成约 100 片，只有传入实际用到的文字，才会拉取对应的分片。设 9 秒超时保底，加载完再 `buildAssets()` 和绘制第一帧。
- **下次避免**：全片文字集中在数据结构里（CAPS、RUSH、WORDS 等）；再写一个 `allText()` 把它们拼起来交给字体预加载，漏一个字就会出现一个回退字形。

### 6. 祝福墙上的祝福句被词球淹没
- **现象**：97 秒、101 秒那两帧，中心的祝福句和后面旋转的祝福词重叠，读不清。
- **原因**：词球半径 440，中心 y 为 470，祝福句 y 为 505，正好压在球心；衬底透明度 0.6 不够。
- **解决**：衬底改为椭圆径向渐变，透明度 0.85，纵向半径 140→170；有祝福句时，把球里靠近中心横带的词压暗：
  `if(active>=0){const dy=Math.abs(p.y-500),dx=Math.abs(p.x-960);a*=dx>720?1:.18+.82*sm(70,190,dy)}`，
  同时把与当前祝福同组的词点亮（`g` 字段分组）。
- **下次避免**：凡是“文字压在文字上”的镜头，设计时就预留一条“阅读带”，背景元素进入阅读带自动变暗。

### 7. 联系表的帧顺序被打乱
- **现象**：样帧文件名是 `String(t).padStart(6,'0')`，得到 `0009.5`、`000101` 这类名字，按字符串排序后顺序错乱，看联系表时要自己对应时间。
- **下次避免**：文件名用整数帧号补零（`f${String(Math.round(t*30)).padStart(5,'0')}.jpg`），并把时间码直接画进缩略图（ffmpeg `drawtext`）。

### 8. 写代码阶段就规避掉的几个坑（没有真正出错，但很容易踩）
- **Canvas 路径在定义时就按当前变换固化**：画完路径后再 `translate` 描第二遍，不会产生偏移。“铅笔双线”效果要把偏移量作为参数，重新构建一遍路径（`strokePts(P,target,dx,dy)`）。
- **月饼咬痕**：用 `rect + arc` 加 `clip('evenodd')` 挖一个缺口，不需要离屏合成。
- **`ctx.letterSpacing` 兼容性**：先 `'letterSpacing' in c` 检测再用，用完重置为 `'0px'`，否则会影响后面所有文字。
- **Artifact 页面里无法下载文件**：页面内的 `<a download>` 或脚本保存都会被拦截，所以不能靠页面里的“录制按钮”（MediaRecorder）导出视频，必须在容器里离线渲染 MP4。
- **声音必须由用户点击触发**：在线版的 AudioContext 在“开始放映”按钮的点击里创建并 `resume()`。

### 9. 本次没有验证的部分（下次要补）
- 在线版没有在真实手机或 Safari 上测过性能和音画同步（只在容器里做了离线渲染）；
- 在线版走的是 Google Fonts，容器里没办法验证实际加载情况；
- 整体响度没有做 LUFS 标准化（平均 −20.8 dB，峰值 −0.7 dB，靠压缩器兜底）。

## 三、创作思路

### 1. 需求如何拆成叙事结构

你的要求可以浓缩成四个关键词：温情 → 追忆 → 震撼 → 回到现在。另外还有三个硬性要求：“BGM 骤停跳转”、“三种风格的历史段”和“祝福墙”。我把它们排成一条 120 秒的时间线：

| 时间 | 段落 | 情绪 | 镜头 |
|---|---|---|---|
| 0–10.6 | 引子：太快了 | 焦躁、窒息 | 消息胶囊横向狂飙、时钟加速、提示音越来越密，10.15 秒冻结并出现故障效果 |
| 10.6–14.5 | 提问 | 安静、失落 | 黑蓝底色，一小轮月亮，“今天，还有人记得中秋吗？” |
| 14.5–22.5 | 城市万家灯火 | 温情开始 | 窗户逐个亮起，月亮升起并变大，妈妈的消息弹出 |
| 22.5–36.0 | 隔屏相望 | 温情高潮 | 双画框视频通话、电子散步、各咬一口月饼、两个半月合成满月 |
| 36.0–41.0 | 骤停 | 屏息 | 纯黑、耳鸣、打字声：“你是否还记得，中秋是从哪里来的？” |
| 41–51.2 | 铅笔线稿：周、汉 | 追忆 | 祭月台、嫦娥奔月的线描动画 |
| 51.2–63 | 水墨：唐、宋、明 | 追忆（诗意） | 烘云托月、竖排诗句、印章、月饼墨线 |
| 63–75 | 2.5D 科技：2006–2024 | 震撼铺垫 | 悬浮档案卡片、月球、嫦娥五号和六号的轨迹 |
| 75–80 | 三种风格汇聚 | 第一个震撼点 | 三联屏合一，“三千年，我们一直在奔向月亮” |
| 80–93 | 反思 | 发人深省 | 月亮远去、38 万公里与“回不去的几百公里”、阴晴圆缺 |
| 93–108.5 | 祝福诗云 | 情感释放 | 祝福词球加古诗环，六句祝福依次出现 |
| 108.5–114.2 | 回到视频通话 | 回到现在 | 通话计时 01:26 仍在继续，两边举起手机拍月亮 |
| 114.2–120 | 片尾 | 升华 | “团团圆圆”四字随鼓点逐字写出，中秋快乐，丙午年八月十五 |

结构上是一个“现在 → 过去 → 现在”的环：视频通话在开头出现一次，结尾再出现一次，计时器从 00:00 一直走到 01:30 左右，暗示这通电话贯穿了整部片子。

### 2. 各段落的设计意图

- **开场引子**：先让观众身体上感到“快”，而不是用字幕说“快”。消息胶囊的位移是 `s(t)=150t+8t³`，速度随时间平方增长；时钟被加速到飞转；提示音间隔按 `0.95·e^(−t/3.1)` 缩短；配一个低频锯齿波，滤波器从 180 Hz 慢慢打开到 2200 Hz。到 10.15 秒，一切冻结：画面切片错位、变黑，同时锯齿波在 0.45 秒内降到原频率的 5%（磁带停转的效果）。“快”到极点，然后突然停住，第一个问题才有分量。
- **万家灯火**：每扇窗都有自己的点亮时间 `on`，随时间越亮越多；字幕“每一扇亮着的窗，都在等一个人”把画面意义说破。妈妈的消息“今年回不来也没事，晚上视频”是整片的情感钩子，同时自然引出下一段的视频通话。
- **隔屏相望**：核心视觉隐喻是“两个画框各有半个月亮，合拢之后是同一个满月”。左框是异乡的高楼和路灯，冷色；右框是老家的矮房、红灯笼和桂花树，暖色，桂花是中秋特有的细节。“电子散步”用视差滚动加人物上下起伏，再加一个“一起走了 1.20 km”的计步标签；“各咬一口月饼”配了咬痕加清脆的咀嚼声。
- **BGM 骤停**：旋律故意安排在 35.75 秒起一个音，没唱完就在 36.00 秒被截断，同时混响尾音也被切掉。画面在同一帧切到纯黑，字幕标了 `cut:true`，不做淡出。之前越温暖，这一刀越痛。
- **历史三段风格**：风格本身就在讲年代。铅笔线稿代表“最早的记载”，像考古手稿，还标注了“r = 1737 km”这样的工程图细节；水墨代表诗词最盛的唐宋明，用了“烘云托月”的技法（月亮留白，周围晕染）；2.5D 科技风代表今天，数据卡片、轨迹线、着陆坐标都有。每一段都用真实史料，而不是泛泛而谈：《礼记》“秋夕月”、《淮南子》“姮娥窃以奔月”、王建《十五夜望月》、苏轼《水调歌头》、田汝成《西湖游览志余》“民间以月饼相遗，取团圆之义”、2006 年首批非遗、2008 年法定假日、嫦娥五号 1731 克、嫦娥六号月背 1935.3 克。
- **风格汇聚**：三联屏同时出现三种月亮，然后三个面板一起向中心收拢，闪白之后合成一轮月亮。合成的月亮身上同时带着铅笔描线环和科技风轨道环。落在字幕“三千年，我们一直在奔向月亮”——神话里的名字真的登上了月亮，这是第一个震撼点。
- **反思段**：用两组数字形成反差。第一组：“月亮每年远离我们约 3.8 厘米”。第二组：地月轨迹线画满，标上“384,400 km ✓”；紧接着“你—家”的连线只画到 72% 就停住，末端闪烁，配两声下行提示音，字幕是“却常常，跨不过回家的那几百公里”。最后月相动画走一遍“阴晴圆缺”，回到满月，落在“所以，团圆才这么珍贵”。
- **祝福诗云**：把“团团圆圆”从家庭延伸成对各类人的祝福：高考、考研、科研、异乡、坚守岗位的人、远方的家人。词球里有“p < 0.05”“模型收敛”“代码零 bug”这类圈内细节，让对应人群会心一笑。外圈是古诗环（“海上生明月，天涯共此时”等），也就是“诗云”。每句祝福出现时，同组的词会一起点亮。
- **结尾升华**：祝福词坍缩成一轮月亮，而这轮月亮的位置正好就是视频通话里满月的位置，于是无缝回到通话画面。两边都举起手机拍月亮，字幕“我们看的，是同一个”。最后“团团圆圆”四个字逐字写出，加上红色印章“同月”。

### 3. 节奏、剪辑与音画配合的技巧

- **“快—停—慢—快—停—释放”的呼吸节奏**：0–10 秒极快 → 冻结 → 14–36 秒 72 BPM 温情 → 骤停静默 → 41–75 秒 120 BPM 快速历史 → 75–80 秒两次重击 → 80–93 秒只剩低音铺底和稀疏钢琴 → 93 秒刮奏加定音鼓进入释放。紧张和松弛交替出现，静默段才有冲击力。
- **匹配剪辑（match cut）**：好几处转场都用月亮的位置保持连续。提问段和城市段的月亮都在 (1450, 250)；祝福词球坍缩的目标点 (960, 400, r=110) 正好是通话画面里满月的位置；片尾月亮从通话位置平滑移到标题位置。
- **用一个画面元素做转场**：铅笔段结束时一滴墨落下，晕开铺满全屏，再“稀释”露出水墨画；水墨段结束时，墨从月亮的位置晕开成深蓝，进入科技段；骤停段结束时，一个光圈扩散，白屏刚好是纸张的颜色，接上铅笔段。
- **音画卡点全部由同一组时间常量驱动**：打字声 `37.0+i*0.11` 对应字幕逐字 `floor((t−37)/0.11)`；咬月饼的音效 31.6 / 32.3 秒对应咬痕出现的 `sm(31.55,31.7)`；水滴声对应水墨三段的开头（51.4 / 55.0 / 59.0）；档案卡片出现时配风声和两声短促电子音；“团团圆圆”每个字都配拨弦、定音鼓和铃声（114.8 + i·0.35）。
- **静默前先抬高**：骤停前 34.9 秒有一串闪亮的高音铃声和上扬的风声，响度从 −25.6 dB 抬到 −21.4 dB；骤停段落到 −34.8 dB，落差约 13 dB。
- **文字节奏**：字幕逐字浮现（每字间隔 ≤ 0.05 秒，带 16 像素上浮和透明度渐入），英文比中文晚 0.3 秒出现；淡出统一 0.45 秒；骤停那一刀不做淡出。
- **双语字幕**：面向“全世界”的观众，每句中文下面配一行英文。英文用 Cormorant Garamond 斜体，字号约为中文的一半，放在中文下方。

### 3. 每种视觉风格的实现

- **现代快节奏（引子）**：11 行消息胶囊，每行的内容在初始化时测好宽度，排成一条长度为 L 的循环带；位移 `((s·k) mod L)`，奇数行和偶数行方向相反；速度超过阈值时画 2–3 个半透明残影，当作运动模糊；冻结时用 `c.drawImage(cv,…)` 把画布自己的条带错位贴回去，做出故障效果。
- **城市夜景**：高楼分远近两层（远层 #121832，近层 #070a14）；约 340 扇窗各自带一个点亮时间，点亮后先画实心窗，再用 `lighter` 混合画一层泛光；整体做 5% 的慢推镜头。
- **视频通话**：两个 740×540 的圆角裁剪区；左框冷色高楼加路灯，右框暖色矮房、红灯笼和桂花树（160 个黄色小点闪烁）；月亮画在各自画框的内侧边缘（x=FW 或 x=0），被裁掉一半，两框间距从 80 缩到 0 时，自然拼成满月；月饼用 72 点花边多边形加内圈和“圆”字，咬痕用 `clip('evenodd')`。
- **铅笔线绘（SVG 描边风格）**：所有图形预先生成成折线点阵，每条带有 `t0/t1`；根据累计长度画出“当前进度”那一段，用 `1-(1-p)²` 缓动；每条线画两遍，第二遍偏移 (1.2, −0.9)，透明度 30%，模拟铅笔重描；阴影排线是很多条 45° 短线，按顺序出现；笔尖处画一个石墨色圆点；背景是 1920×1080 的纸纹（每像素随机亮度加 2600 根纤维加暗角）和一层方格网，镜头平移 1100 像素，从周代的画面移到汉代的画面。
- **水墨晕染**：4 层山体各是一张离屏 canvas：`fbm` 分形噪声生成山脊线，垂直渐变从浓墨过渡到透明，山脊描边加 `blur(1.4px)`，再加皴擦短线和松树；4 层按视差系数 0.25/0.45/0.72/1 平移；中间一层后面叠了三道雾带；“烘云托月”是一个环形径向渐变，月亮内部透明、外圈灰墨，月亮本身直接留出纸色；竖排诗句逐字出现，每字 `blur((1-p)*6px)` 从模糊到清晰，像墨迹洇开；红色印章用微旋转的圆角矩形加白字；墨滴转场是一个主圆加 40 个随机卫星圆，一起扩张。
- **2.5D 超现实科技风**：透视网格地面（49 条汇聚线，16 条横线按 `d^2.3` 分布并随时间向前滚动）；月球用冷色月面贴图，叠一层偏移的径向暗部渐变，再加青色边缘光；卡片用 `setTransform(s,-.12s,0,s,x,y)` 做倾斜，下面叠一层偏移 12 像素的“厚度”，四角画 L 形角标，地面有椭圆阴影；新卡片进场时，旧卡片按 `k` 向左上方后退、缩小、变暗；嫦娥五号和六号的轨迹是三次贝塞尔虚线加一个发光的头部，着陆点有扩散波纹和坐标标签（43.1°N 51.8°W / 41.6°S 154.0°W FAR SIDE）。
- **汇聚**：三个面板裁剪区的中心和宽度随 `pm` 插值收向画面中央，背景透明度 `1−sm(.55,1,pm)`；合成后的月亮 = 暖色月亮 + 两道旋转的铅笔描线环 + 一道青色轨道环；78 秒闪白。
- **反思**：月相用两段弧组成阴影形状（边缘半圆加椭圆明暗交界线），`phaseShadow(x,y,r,ph)` 中 ph 从 0 到 1，对应满月→新月→满月。
- **祝福诗云**：64 个词按斐波那契球面均匀分布，绕 Y 和 X 两个轴旋转，做透视投影，按深度排序；字号、透明度、颜色都随深度插值；外圈 7 句古诗沿倾斜椭圆绕行，背面的画在词球后面、正面的画在前面；110 个孔明灯粒子用 `lighter` 混合向上飘。
- **全局后期**：预先生成的暗角图，加 3 张 960×540 的颗粒图，按 24fps 轮换，用 `overlay` 混合，透明度 5%。

### 4. 音频处理

**信号路由**（骤停的关键）：
```
各声部 → route() → music(增益) ─→ master → 压缩器(-16dB, 3.5:1) → 输出
                  └ mverb(增益) → 卷积混响(3.4s 自生成冲激响应) → wet → master
音效（打字、耳鸣、心跳） → sfx / sverb（不受骤停控制）
```
```js
[music.gain,mverb.gain].forEach(g=>{g.setValueAtTime(1,T(0));g.setValueAtTime(0,T(36));g.setValueAtTime(1,T(40.95))});
wet.gain.setValueAtTime(.5,T(0));wet.gain.setValueAtTime(0,T(36));wet.gain.setValueAtTime(.5,T(39.6)); // 连混响尾音一起切掉
```
要点：只关掉送进混响的输入不够，卷积器内部还有 3.4 秒的尾音会继续输出；所以要把混响的返回通道也关到 39.6 秒（36 + 3.4 秒后尾音已经衰减完）再打开。

**乐器合成**：
- 古筝式拨弦：Karplus-Strong 算法（`ring[j]=decay*.5*(v+ring[j+1])`），同一音高的波形缓存复用；部分音用 `playbackRate` 从 −1 半音滑回原音高，模拟古筝的按音；
- 铺底（pad）：每个音用两个锯齿波，分别失谐 ±7 音分，加低通滤波和包络；
- 笛子：正弦波加三角波泛音，0.5 秒后加入 5.3 Hz 颤音，再叠一点带通噪声作气声；
- 钢琴：三角波加泛音，低通从 4200 Hz 扫到 700 Hz，指数衰减；
- 铃：四个非谐波分音（1 / 2.76 / 5.4 / 8.93），各自衰减；
- 定音鼓：正弦波 130→45 Hz 下滑，加一小段低通噪声；
- 爆发音（boom）：正弦波 72→26 Hz，加噪声低通扫频；上扬音（riser）：带通噪声向上扫频，加锯齿波 110→880 Hz；
- 音效：时钟嘀嗒（高通噪声）、提示音（两个高音正弦）、打字（带通噪声加 150 Hz 低音）、咀嚼（7 个极短的噪声颗粒）、铅笔沙沙声（带通噪声，每 45 毫秒随机调幅）、水滴（正弦波 820→170 Hz）、耳鸣（5400 Hz、增益 0.006）、心跳（两下低频正弦）、磁带停转（锯齿波频率 0.45 秒内降到 5%）。

**配乐结构**（D 大调五声音阶，温情段和祝福段 72 BPM，历史段 120 BPM）：
- 温情段：D–Bm–G–A 循环，古筝八分音符分解和弦加笛子旋律；
- 历史段：Bm–G–D–A；铅笔段是轻拨弦加铅笔沙沙声，水墨段加定音鼓滚奏和笛子，科技段加方波琶音、每拍一下底鼓和贝斯脉冲；
- 反思段：只留低音铺底（D→Bm→G→A）和稀疏钢琴，A 和弦（属和弦）悬着不解决；
- 祝福段：93 秒从 D（主和弦）进入，给出解决感，接刮奏；
- 片尾：落在 D 加九音的和弦上。

**淡入淡出**：总音量在 118.6 秒到 120 秒线性降到 0；每个声部都有自己的起音和释音包络。

**实测响度**（ffmpeg `volumedetect`）：整体平均 −20.8 dB，峰值 −0.7 dB；各段：0–10 秒 −26.9，14.5–21 秒 −25.6，30–35.9 秒 −21.4，**36.05–39.5 秒 −34.8**，41–51 秒 −19.4，63–75 秒 −19.7，93–108 秒 −18.9，114–118 秒 −19.0。

**音画同步原理**：画面和声音都只以同一个 t 为准。离线导出时，音频用 `buildScore(oac,0)` 渲染，画面用第 i 帧 = `i/30` 秒，两者天然对齐，混流时加 `-shortest`。在线播放时，画面时间 = `ac.currentTime − T0`（`T0 = currentTime + 0.6`，给排程留余量）；暂停用 `ac.suspend()`，画面自动跟着停。

### 6. 时间分配（按文件时间戳推算，约 53 分钟）

| 环节 | 用时 | 说明 |
|---|---|---|

| 分镜与写 `moon.html` | ~20 分钟 | 最核心的一步：854 行一次写成 |

| 两遍压缩 | ~4.5 分钟 | 2 核 CPU |

各段每帧耗时（含 JPEG 编码）：骤停段约 55 ms，城市和通话约 100–150 ms，科技约 150–166 ms，词球约 200–309 ms，片尾约 356 ms，**水墨约 395–526 ms（最慢）**。

**提速建议**：
1. 逐字 `ctx.filter='blur()'` 是最大的性能开销，改成预先生成的模糊文字贴图，或者用 `shadowBlur` 近似；
2. 修复后先单帧验证，避免整段重渲（这次就浪费了约 5 分钟）；
3. 按 `nproc` 决定进程数，CPU 多就多开；这次 2 核同时跑 2 个页面和 2 个 ffmpeg，其实是满载的；
4. 最终编码参数提前定好，一次直接出分享版，或者母版和分享版并行编码；
5. 把“快速预览”模式做成参数：720p、每秒 10 帧抽样，先整体过一遍节奏。
