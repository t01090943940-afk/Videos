# PixiJS

> 类型：2D 引擎 · 分类：二维场景 · 研究快照：2026-09-24
> 证据：入口索引。本条不包含跨模型成绩；关联原理演示不视为该库实测。

## 它增加了什么能力

以 GPU 加速的场景图管理精灵、容器和二维效果。

- sprites
- filters
- masks
- 纹理与粒子

## 值得尝试的表达

以下是原创实验建议，不是声称已找到或复刻的官方获奖作品。

- [实验方向 01](./examples/01.md)：让多层照片拼贴在空间中错落推进。
- [实验方向 02](./examples/02.md)：把一张海报拆成数百碎片并按信息层级重新组装。

## 能力边界

不同 renderer 支持有差异；滤镜和高分辨率纹理会增加显存压力。

## 使用建议（本词典编辑性判断）

- 显式更新 ticker 或禁用自动时钟；复用纹理；将高成本滤镜限制到必要区域。
- 分辨率、pixel ratio、滤镜区与资源就绪必须固定。

## 时间线与输出

禁用 ticker 累加或从固定初态重建每个时间。

Canvas 图像序列 / WebCodecs + 封装器。

## 组合候选

[gsap](../gsap/README.md), [canvas2d](../canvas2d/README.md), [ffmpeg](../ffmpeg/README.md)。组合关系仅是研究候选，不代表已验证兼容。

## 常见平庸与失败模式

- 大量图层运动应有主次，不能每一层同时争抢注意。

## 进一步辨别

### 为什么它值得进入视频词典

大量图片层、精灵、滤镜和遮罩，与传统平面合成的对象十分接近。但图层规模、纹理大小和滤镜面积共同决定成本，不是只看对象数量。

建议以 20、100、500 个图层做同一构图实验，逐级增加纹理和滤镜；记录视觉是否真的提升。把性能测试与最终画质测试分开，并报告硬件和渲染后端。

[Pixi 指南](https://pixijs.com/8.x/guides/) 与 [Filters 仓库](https://github.com/pixijs/filters) 是后续阅读入口。本条仅收录定位，未在本环境安装 Pixi。
