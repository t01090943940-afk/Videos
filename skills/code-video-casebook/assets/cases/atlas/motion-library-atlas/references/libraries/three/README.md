# Three.js

> 类型：3D 引擎 · 分类：三维与摄影 · 研究快照：2026-09-24
> 证据：官方资料核对核心定位。本条不包含跨模型成绩；关联原理演示不视为该库实测。

## 它增加了什么能力

以场景、相机、光照和材质组织 Web 3D。

- scene graph
- camera
- materials
- animation mixer

## 值得尝试的表达

以下是原创实验建议，不是声称已找到或复刻的官方获奖作品。

- [实验方向 01](./examples/01.md)：搭建一次可反复拍摄的工地虚拟摄影棚。
- [实验方向 02](./examples/02.md)：围绕同一产品拍建立镜头、结构特写和爆炸视图。

## 能力边界

不自带完整物理、建模与导演；精美场景不保证角色接触和镜头构图正确。

## 使用建议（本词典编辑性判断）

- 先统一米制单位、朝向、镜头与光照；将时间显式传给动画；复用 GLB 资产。
- 分清米制尺寸、坐标朝向、碰撞体和可见网格；检查镜头穿物与近裁剪。

## 时间线与输出

相机、姿态与灯光都受显式 t 驱动；模拟提前烘焙。

WebGL 帧或 DCC 渲染序列 → 合成。

## 常见平庸与失败模式

- 推拉摇移应改变理解；不停绕场不等于电影感。

## 进一步辨别

### 从场景到摄影棚

可复用片场至少需要一致的尺度、对象命名、相机预设与资产路径。场景和每个 shot 的表演参数分开，但不必提前创造通用标准。摄影机高度、视角和遮挡关系比一开始堆更多模型更值得先检查。

### 穿模不是单一问题

可见网格相交、碰撞体不匹配、蒙皮穿透、镜头进入物体和近裁剪，是不同故障。增加物理引擎最多解决其中一部分。让检查报告描述‘哪个对象、哪个时间、什么几何关系’，而不是一句‘没有穿模’。

[Three 示例](https://threejs.org/examples/)、[R3F](https://github.com/pmndrs/react-three-fiber)、[Rapier](https://rapier.rs/docs/user_guides/javascript/getting_started_js/) 分别解决不同层的问题。本地虚拟片场是自写投影渲染，不伪称 Three 实测。
