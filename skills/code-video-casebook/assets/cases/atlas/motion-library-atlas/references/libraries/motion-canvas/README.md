# Motion Canvas

> 类型：框架 · 分类：视频框架 · 研究快照：2026-09-24
> 证据：官方资料核对核心定位。本条不包含跨模型成绩；关联原理演示不视为该库实测。

## 它增加了什么能力

用 TypeScript 生成器组织说明性矢量动画，并通过编辑器调整时机。

- 生成器编排
- 信号与补间
- 矢量场景
- 旁白时间点

## 值得尝试的表达

以下是原创实验建议，不是声称已找到或复刻的官方获奖作品。

- [实验方向 01](./examples/01.md)：一条算法轨迹从伪代码变成可见的节点遍历。
- [实验方向 02](./examples/02.md)：将细胞运输过程拆成进入、结合、释放三个解释节拍。

## 能力边界

不是通用非线性视频剪辑器；生成器历史状态不能随意假设为纯函数。

## 使用建议（本词典编辑性判断）

- 利用框架自己的时间线与播放控制；把讲解步骤拆成有名字的段落。
- 先确定画幅、帧率与音轨；同一镜头不同时间单独检查。

## 时间线与输出

显式帧时间或框架官方渲染时间线。

使用框架输出，或帧序列 → FFmpeg。

## 组合候选

[manim](../manim/README.md), [hyperframes](../hyperframes/README.md), [remotion](../remotion/README.md)。组合关系仅是研究候选，不代表已验证兼容。

## 常见平庸与失败模式

- 不要把模板默认淡入当作唯一导演语言。

## 进一步辨别

### 顺序叙述是一种可用抽象

把‘出现、等待、转移焦点、变化’表达成生成器，可能比直接管理大量独立属性更容易编排解释动画。这是接口特征；是否提升某个模型，仍需同任务对照实验。

建议测试一次中途时间跳转、场景重启和旁白时标更改。不要自行绕开框架的生命周期，然后将错误归为库不能渲染。

[官方说明](https://motioncanvas.io/docs/) 明确其解释动画定位；这不是完整剪辑软件的同义词。
