# Remotion

> 类型：框架 · 分类：视频框架 · 研究快照：2026-09-24
> 证据：官方资料核对核心定位。本条不包含跨模型成绩；关联原理演示不视为该库实测。

## 它增加了什么能力

把 React 组件按视频帧求值，适合参数化片头、字幕和数据视频。

- 帧驱动组件
- 序列与合成
- 音视频编排
- 程序化渲染

## 值得尝试的表达

以下是原创实验建议，不是声称已找到或复刻的官方获奖作品。

- [实验方向 01](./examples/01.md)：把一段旁白拆成可修改的字幕与图表镜头，保留同一视觉身份。
- [实验方向 02](./examples/02.md)：用同一工程生成不同地区的数据版本，而非手工复制时间线。

## 能力边界

普通 React 动画的真实时钟不能自动变成视频时间；商用许可需按团队和用途核查。

## 使用建议（本词典编辑性判断）

- 把视觉状态从 frame 推导；等待字体及媒体就绪；固定分辨率并检查关键帧。
- 先确定画幅、帧率与音轨；同一镜头不同时间单独检查。

## 时间线与输出

显式帧时间或框架官方渲染时间线。

使用框架输出，或帧序列 → FFmpeg。

## 进一步辨别

### 从帧出发，不是从网页播放出发

同一个 composition 的画面应能由帧号与输入数据重建。使用 CSS 自启动动画、系统时间或无种子随机后，预览好看也可能在分段渲染时不一致。DOM 文本适合清晰排版，Canvas 适合自定义绘制，3D 则要把相机和动画时间也接到帧上。

### 先测局部修改能力

保留一个镜头的对象身份、字幕内容和素材，只把强调动作提前。对比修改前后的其他帧。如果无关镜头被重写，问题可能是工程结构和代理策略，而非渲染器上限。

[官方 Skills](https://www.remotion.dev/docs/ai/skills) 包含创作、markup、渲染与多媒体方向。本工作站不宣称运行过 Remotion 引擎；Canvas 演示只用于说明视觉意图。
