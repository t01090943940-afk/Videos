# GL Transitions

> 类型：转场集合 · 分类：着色与后期 · 研究快照：2026-09-24
> 证据：官方资料核对核心定位。本条不包含跨模型成绩；关联原理演示不视为该库实测。

## 它增加了什么能力

以两张纹理和进度参数描述可复用 GLSL 转场。

- texture transition
- progress
- shader 集合

## 值得尝试的表达

以下是原创实验建议，不是声称已找到或复刻的官方获奖作品。

- [实验方向 01](./examples/01.md)：让一道方向明确的位移连接前后两镜的运动。
- [实验方向 02](./examples/02.md)：用图形匹配选择转场，而不是随机轮播特效。

## 能力边界

效果库不等于自动剪辑；授权按单个项目和素材分别检查。

## 使用建议（本词典编辑性判断）

- 核对输入长宽比与颜色空间；用进度显式求帧；不要连续堆强特效。
- 检查编译、长宽比、颜色空间、设备支持、内存和上下文丢失。

## 时间线与输出

显式时间 uniform；反馈效果需保存状态或预计算。

framebuffer/Canvas → 序列或编码。

## 组合候选

[webgl](../webgl/README.md), [pixi-filters](../pixi-filters/README.md), [postprocessing](../postprocessing/README.md)。组合关系仅是研究候选，不代表已验证兼容。

## 常见平庸与失败模式

- 全屏炫光会遮蔽主体；转场必须有方向或形状联系。

## 进一步辨别

### 转场是连接关系，不是效果抽签

开始时明确前后镜头的方向、主形状或焦点联系，再决定是否需要位移、遮罩或几何切分。一个复杂 shader 没有语义联系时，可能比直接硬切更差。

测试 progress=0、0.25、0.5、0.75、1，并检查边界像素、长宽比、透明度与颜色空间。视频纹理还要确保解码到指定时间。

[集合入口](https://github.com/gl-transitions/gl-transitions) 用于发现已有材料。本地 shader-wipe 是原创 WebGL shader，不是从集合中取出某个 shader 后宣称其已通过本地测试。
