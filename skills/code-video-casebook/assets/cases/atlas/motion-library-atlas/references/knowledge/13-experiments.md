# 怎样逐步摸边界，而不先造一个大基准

以一个真实镜头为任务：输入、素材、时长和输出要求明确。先比较两个最有希望的候选，不必一次铺开所有模型和所有库。

## 保持变量可解释

同一任务、素材和时间预算下，改变模型、库或 Skill 中的一项。模型有随机性时需要重复若干次；一次最好结果和平均可用性不是一回事。记录迭代次数、人工介入和错误类型。

如果某个框架不能自然表达任务，先记录适配代价，不通过改题掩盖差异。强抽象可能减少工程决策，但是否让弱模型变好，需要观察而不是假设。

## 两套观察并行

技术：能运行、可定位、可重复、可导出、无明显越界、修改范围稳定。

视觉：信息清楚、构图有主次、动作有意义、节奏合理、风格连贯、存在有效的视觉选择。审美意见注明评价者和参考，不伪装成客观物理量。

## 让失败可检索

记录错误发生的库、版本、时间、对象与原因。区分 API 错误、环境错误、资源缺失、空间关系错误、时间历史错误与审美不匹配。失败记录同样是高价值词典内容。

工作台“实验记录”是本地人工日志，不连接模型 API、不自动执行测试，也不产生虚构评分。每条记录可以导出 JSON，供后续真实研究使用。
