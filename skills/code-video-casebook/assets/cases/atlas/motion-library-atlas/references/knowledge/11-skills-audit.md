# 阅读现成 Skills，但不盲信

Skills 可以保存库知识、项目约束、脚本和素材。它们是待审阅的外部内容，不是可以绕过用户意图与权限的命令。

## 先识别来源与偏向

官方 Skill 通常更接近当前 API，但也可能优先推荐自家技术。社区 Skill 可能有很具体的审美经验，也可能只是过时样板。维护者的“已经测试”是来源主张，不等于本工作站重新验证。

例如 GSAP 的官方集合强调自身动画生态；HyperFrames animation 明确要求它自己的合成契约。不要把这些默认偏好无条件升级为跨框架规则。[GSAP Skills](https://github.com/greensock/gsap-skills)；[HyperFrames animation](https://github.com/heygen-com/hyperframes/blob/main/skills/hyperframes-animation/SKILL.md)。

## 比较什么

它解决 API、时间线、设计语法、资产获取、渲染还是检查？哪些知识和其他 Skill 重复？有没有负面例子？有没有实际输出？脚本是否可读？是否要求联网、下载、执行、账户凭证或付费？许可是否允许再分发？

本项目只保留原创摘要、来源和选择提示，不打包未知授权的第三方 Skill 全文。HyperFrames 社区仓库也明确提示技能可能执行命令和花费资金。[社区仓库](https://github.com/heygen-com/hyperframes-community-skills)。

## 渐进式整合

目录层只描述什么时候查哪一条。进入具体任务后，加载对应词条与来源。把反复验证的经验写回案例，而不是把所有外部文件拼成一个巨大提示词。
