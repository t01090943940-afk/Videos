# 《一畫》代码视频复盘

> 作品：《一畫》，水墨书法主题，60.5 秒，1920×1080，30fps，共 1815 帧，画面和配乐全部由代码生成
> 环境：云端 Linux 容器（2 核 CPU、7GB 内存、没有 GPU），Node 22，Python 3，ffmpeg，预装 Chromium 1194
> 用时：02:18 接到需求，04:10 交付，约 1 小时 52 分钟，其中两次全片渲染合计约 44 分钟

---

## 一、创作思路

### 1. 需求如何拆成叙事结构

用户给了七条要求：惊艳、深刻、衔接自然、像大师之作、炫技、水墨气重、结合古人文章并以泼墨聚合诗云收尾。我把它们压成一句主线：

**一滴墨，化万卷，归一画。**

结构借用手卷本身的形制：镜头从右往左一镜到底，依次经过引首、画心、拖尾，最后落款、钤印。情感曲线是「静 → 生 → 悲 → 冷 → 悟 → 散 → 聚 → 爆 → 静」，对应到时间轴：

| 时间 (s) | 段落 | 情绪 | 镜头高度 h（世界单位，1 单位 = 一个字宽） |
|---|---|---|---|
| 0–2.45 | 黑暗中亮起宣纸纤维 | 静、屏息 | 0.30→0.33（微距） |
| 2.45–3.3 | 一滴墨落下、洇开 | 第一个动作 | 0.33→0.5 |
| 3.35–8.15 | 「永」按笔顺写出，朱批永字八法 | 生，建立规则 | 1.5→1.72 |
| 8.5–21.6 | 《兰亭序》 | 舒展，转向「死生亦大矣」「悲夫」 | 12.2 全景，15.6s 起推到 7.6，悲夫处 6.2 |
| 20.6–28.2 | 《祭侄文稿》 | 悲恸、急促、墨枯 | 12.2，嗚呼哀哉处 8.8 |
| 28.5–36.6 | 《寒食帖》 | 冷、沉 | 12.2，死灰吹不起处 8.0 |
| 35.55–39.4 | 《书谱》「达其情性，形其哀乐」 | 点题 | 10→9.2 |
| 39.3–42.4 | 后拉，整卷铺开 | 顿悟、俯瞰 | 9.4→16.2 |
| 40.6–47.5 | 字化墨烟，汇成诗云星河 | 散，宏大 | 15→14.3 |
| 47.55–49.35 | 星河坍缩成一个点 | 聚，张力推到最大 | 13→10.3 |
| 49.4–50.0 | 静默，只剩一个墨点 | 留白，吸气 | 10.3 |
| 50.0–51.35 | 逆锋压笔、泼墨，一笔横扫 | 爆发，高潮 | 10.3（带震屏） |
| 51.4–54.5 | 推近飞白，笔丝是可读的诗句 | 揭示「压缩诗云」 | 10.3→2.55 |
| 54.5–58.3 | 拉回，题石涛句，钤「无尽藏」 | 收 | 2.5→10.6 |
| 58.3–60.5 | 渐黑，片尾字卡 | 余韵 | — |

首尾呼应：开场那一滴墨，和高潮前坍缩出的那一个墨点，在画面上是同一个意象。

### 2. 各段的设计意图

- **开场（微距宣纸 + 墨滴）**：先让观众看清材料本身，也就是纸的纤维和光。墨滴落下之前，先用一个逐渐收紧的阴影暗示它正从上方落下来。洇开的墨块随后退成淡墨，「永」的第一点正好写在它上面，于是「一滴墨」自然变成「第一笔」。
- **永字八法**：永是《兰亭序》第一个字，又是书法教学的母字。每写到对应的笔画，旁边就出现一个红色小楷批注（侧、勒、努、趯、策、掠、啄、磔），这是专门给懂行的人看的。
- **三大行书的风格区分**，每段都有自己的纸色、笔性、墨色和节奏：
  - 兰亭：浅暖纸色；笔画做了减细（thin=13），字体微微右倾、横画右上扬（rise 0.085）；牵丝比例高；墨色匀润。
  - 祭侄：麻纸色偏黄褐（tint1），暗角加重；笔画加粗（bold=10，嗚呼哀哉用 16）；墨量衰减快（drain 0.00034），所以很快出现飞白；字的大小、旋转和列的摆动都更大；中间有一处涂抹删字；嗚呼哀哉放大到 1.5 倍。
  - 寒食：纸色偏灰冷，饱和度降 25%；字压扁拉宽（sx 1.16、sy 0.9），右肩上扬更明显（rise 0.11），笔画很粗（bold=26）；有少量冷雨点；「死灰吹不起」后面逐字放大、放慢，写完从「灰」字飘出灰烬粒子。
  - 书谱：回到中性纸色，节奏平缓，作为点题。
  - 各段之间是纸缝，不是剪切：着色器按世界坐标 x 切换纸张色调，接缝处画一条细线加一点阴影。上面再放「神龙」半印、「绍兴」骑缝印（左右两半故意错位几像素），模拟历代装裱留下的痕迹。
- **转场（全景 → 墨烟 → 诗云）**：整卷铺开是「上帝视角」。字从右到左依次化成墨烟，原位只留下 11% 浓度的淡痕，墨烟顺着卷轴向左流，汇进一个由上百句古诗组成的旋转星河，星河用 5 种书体混排。这里借用了刘慈欣《诗云》的意象，把所有诗压进一个点。
- **高潮（一画）**：星河坍缩成一个墨点，然后停 0.6 秒，几乎没有声音。接着逆锋压笔、泼墨四溅，1.05 秒内一笔横贯全屏；同一时刻有低频轰鸣、古琴低音和弦，外加 0.05 世界单位的震屏。
- **揭示**：镜头推近飞白处，每一缕笔丝都是一行真实的诗句，比如「床前明月光」「大江东去」「读书破万卷」。这个「近看才发现」的瞬间，才让「压缩诗云」真正成立。
- **结尾**：题石涛《画语录》「一画者，眾有之本，萬象之根」，钤白文印「無盡藏」（出自苏轼《赤壁赋》），然后渐黑，出片尾字卡「Claude Opus 5.5 以代码书写 · 丙午年秋」。

### 3. 节奏、剪辑与音画配合

- **一镜到底**：全片没有一次硬切。所有转场都靠镜头高度 h 的对数插值（缩放速度感觉上恒定）加位置弹簧跟随完成。
- **推拉即强调**：重要句子处推近并放慢书写速度（每字时长 0.34s 提到 0.47–0.8s），其余时间保持全景、快写，形成快慢对比。
- **写字头跟随**：书写段里镜头跟随「正在书写的字」的加权平均位置，再用临界阻尼弹簧平滑，像摄影师跟拍。
- **手持呼吸感**：旋转 ±0.6°，外加低频噪声漂移，幅度为 h 的 1%。
- **静默前置**：高潮前 0.6 秒把声音压到 8%（duck 0.92），爆点才会显得更响。
- **声画同源**：画面时间轴导出 `events.json`（每一笔的开始时间和时长、每列的起止、删字、题款、钤印），音频脚本读同一份数据生成音效，所以对位是帧级的。
- **声像跟随**：大笔从左往右扫，扫笔声的声像也从 -0.85 移到 +0.85。
- **调式叙事**：兰亭、书谱用 F 宫五声音阶（明亮）；祭侄用 D 羽，按音下滑配低持续音（悲）；寒食用稀疏泛音配雨声（冷）；诗云段数千个泛音颗粒的音高最后全部滑向 F4 同音，对应「万诗归一」。

## 二、具体的创作方式

### 1. 技术栈与工作流

| 用途 | 工具 |
|---|---|
| 画面引擎 | 原生 JS + Canvas2D（墨迹层）+ WebGL2 片元着色器（纸、墨、光、调色合成） |
| 笔顺数据 | npm `hanzi-writer-data`（Make Me a Hanzi，9575 字，含繁体，每个字一份 JSON，包含轮廓 `strokes` 和中线 `medians`） |
| 字体 | `@fontsource/zhi-mang-xing`、`liu-jian-mao-cao`、`ma-shan-zheng`、`long-cang`（诗云星河用）；系统自带 Noto Serif CJK SC/TC（印章、微缩诗句、片尾） |
| 纹理 | Python numpy（FFT 滤波噪声，天然可平铺）+ PIL（纤维线） |
| 逐帧渲染 | Playwright + 预装 Chromium（SwiftShader 软件 WebGL），通过 `page.evaluate` 调用 `renderFrame(i)`，再 `toDataURL('image/jpeg',0.95)` |
| 编码 | 帧通过 stdin 以 image2pipe 管道送进 ffmpeg，libx264 编码 |
| 音频 | Python numpy + scipy（加法合成古琴、滤波噪声、FFT 卷积混响），输出 48kHz 16bit WAV |
| 本地服务 | `python3 -m http.server 8123`（用 file:// 打开会被跨域限制卡住） |

工作流：

1. 环境探测：检查 chromium、ffmpeg、node、python、CJK 字体、CPU 和内存，并用 WebGL2 探针确认软件 WebGL 可用。
2. 叙事和分镜：写出上面的时间表，同时确定世界坐标布局，也就是每一列、每一段在卷上的 x 位置。
3. 生成纹理：运行 `gen_tex.py`。
4. 引擎和编排写在同一个文件里（`main.js`，约 1300 行）。
5. 抽帧预览：`preview.js` 渲染指定帧，`sheet.py` 拼成缩略图拼图，看完再改，循环了 8 轮。
6. 性能剖析：`prof.js`，逐阶段计时。
7. 全片渲染：`render.js` 输出无声母版。
8. 合成音频：`audio.py` 读 `events.json`，输出 `score.wav`。
9. 混流并压缩到可发送的体积，然后按 1fps 抽帧复查。

### 2. 项目结构与关键模块

```
shufa/
├─ index.html      # 引入 fontsource 的 CSS、corpus.js、main.js
├─ corpus.js       # 约 110 行古诗断句（诗云和微缩诗句的文本来源）
├─ main.js         # 引擎：图层、镜头、字形、书写、特效、诗云、一画、着色器、主循环
├─ gen_tex.py      # paper.png / paperL.png / streak.png
├─ audio.py        # 配乐与音效
├─ preview.js      # 抽帧预览（中间帧用 stepOnly 只模拟不绘制）
├─ prof.js         # 性能剖析
├─ render.js       # 全片渲染，管道送入 ffmpeg
├─ sheet.py        # 缩略图拼图
└─ tex/            # 纹理
```

**图层设计**：四张离屏 Canvas，每帧上传为纹理，由一个全屏着色器合成。

- `A`（1920×1080）：墨的浓度，只用 alpha 通道。
- `B`（960×540）：湿度，供洇墨光晕用，在着色器里用 mipmap 模糊。
- `C`（1920×1080）：朱色层，放印章和批注，在着色器里用正片叠底合成。
- `D`：片尾字卡。

**世界坐标与镜头**：1 单位 = 1 个字宽，y 轴向下，卷轴向 -x 方向展开。镜头参数是 `{x, y, h, rot}`，h 表示屏幕高度对应多少个世界单位。Canvas 和着色器共用同一套变换：

```js
function camMat(scale){ const s=H/cam.h*scale, c=Math.cos(cam.rot)*s, sn=Math.sin(cam.rot)*s;
  return [c, sn, -sn, c, W*scale/2-(c*cx - sn*cy), H*scale/2-(sn*cx + c*cy)]; } // cx,cy 含震屏偏移
// 着色器里做逆变换：
// vec2 d=(px-0.5*res)/(res.y/cam.z); wp = cam.xy + vec2(cr*d.x+sr*d.y, -sr*d.x+cr*d.y);
```

**镜头时间轴**：`HK` 是 `[t, h]` 关键帧，在对数空间插值；`XK` 是 `[t, x, y, 跟随权重]`，权重为 1 时跟随写字头。位置用临界阻尼弹簧平滑，书写段 ω=2.4，开场和结尾段 ω=5.5：

```js
const ax = om*om*(tg.x-cam.x) - 2*om*cam.vx;  cam.vx += ax*DT; cam.x += cam.vx*DT;
// y 跟随权重随缩放变化：全景时不跟随（整列可见），特写时跟随 70%
const yw = clamp((12.4 - h)/6, 0, 0.7); fy = lerp(5.7, focus.y, yw); fx = focus.x + 0.6;
```

**核心技法：按笔顺「写」出字**。每一笔先在临时画布上填满轮廓，再用中线上的粗线做 `destination-in` 遮罩，只露出已经写到的部分：

```js
sctx.fill(path);                                   // 整笔轮廓
if (bold) sctx.stroke(path);                       // 加粗：描边
sctx.globalCompositeOperation='destination-out';
if (st.er) { sctx.lineWidth=st.er*2; sctx.stroke(path); } // 减细：擦掉描边宽度
drawStreaks(sctx, med, st, s1);                    // 笔毫纹理和飞白：沿中线法向偏移的细线，擦出白痕
if (p<1){ sctx.globalCompositeOperation='destination-in';
  sctx.lineWidth=290; sctx.lineCap='round'; polyPartial(sctx, med, p*med.L); sctx.stroke(); }
ctx.globalAlpha = st.tone; ctx.drawImage(scratch,0,0);    // 墨色浓淡
```

- 进度曲线：`p = 0.55*easeInOut(u) + 0.45*u`，起笔和收笔慢，中段快。
- 飞白判定：沿中线弧长 s 取值噪声 `v`，当 `v < dry*(0.15+1.0*s/L)*(0.55+0.9*边缘度) - 0.08` 时，在这一段擦出白痕，所以笔画末端和两侧先枯。
- 墨量模型：全局 `brush.load` 按每笔长度扣减（`drain × 笔长`），低于 `redip` 阈值就「重新蘸墨」；墨色（tone）和干度（dry）都由当前墨量算出。祭侄段的节律性枯湿就是这样来的。
- 行书化变形：解析 SVG 路径，对每个点做变换，每个字随机取一组参数，并且在重采样中线之前先变形：

```js
x = X + it*(Y-388) + a*512*0.05*sin(v*2.2+p1);   // 右倾 + 正弦扰动
y = Y + rise*(X-512) + b*512*0.05*sin(u*2.4+p2); // 横画右上扬
```

- 牵丝：在前一笔终点到下一笔起点之间画三次贝塞尔曲线（控制点沿两端切线方向外推），线宽随 |cos(πu)| 变化，形成两头粗、中间细，并在两笔之间的空档时间里逐步画出。
- 字间连笔：只在「上一字最后一笔收在下方、下一字第一笔起在上方」时才画，走 S 形曲线，线宽 0.009×字号。
- 缓存：写完的字按 64/128/256/512/1024/2048 分档缓存成位图；正在写的字每帧实时重绘。

### 3. 各种视觉效果的实现

- **宣纸**（`gen_tex.py`，2048² 可平铺）：R 通道是 1/f^3 频谱的 FFT 噪声（云斑）；G 通道用 PIL 画了 26000 根短纤维、1800 根长亮纤维、700 根暗纤维，每根在 3×3 偏移上重复绘制，保证平铺无缝；B 通道是颗粒加杂点；A 通道是吸墨率噪声，决定洇边的毛刺。`paperL.png` 预先烘焙了浮雕光照和大尺度云絮。着色器里同时采样两个尺度（×0.25 和 ×1.9），镜头拉近时自动提高细节层权重（`detail = (2.2-h)/1.6`）。
- **墨**（片元着色器）：
  - 边缘毛刺：`aE = smoothstep(0.5±0.16, aS + (吸墨噪声-0.5)*k)`，其中 aS 是 A 层 mip 模糊后的值。
  - 边缘积墨：`edge = a - textureLod(A,1.5)`，边缘略深，模拟水渍线。
  - 洇墨光晕：`hb = textureLod(B, haloLod)`，haloLod 由「0.045 世界单位 × 每单位像素数」换算。再用吸墨噪声做阈值，得到带纤维毛边的淡墨晕和一圈水线（tide）。
  - 墨色按比尔定律吸收：`col *= exp(-od*vec3(1.03,1.0,0.92))`，淡墨略偏冷灰，接近松烟墨。
- **印章**：512² 画布。白文印先画红色方块，再用 `destination-out` 把字挖空；朱文印是红字加边框。然后随机擦掉 2600 个小点、边缘缺 40 处，模拟印泥不匀和残损。在着色器里，印章正片叠底前再乘一次纸纹理。
- **墨滴**：阴影收紧表示墨滴从上方落下；落纸后用径向渐变画出噪声边缘的墨块，半径按 `1-exp(-9t)` 增长；随后在 0.85–1.5s 内退成淡墨；另有 9 个极小的溅点。
- **删字**：一条多频正弦叠加的涂抹曲线，线宽 0.11×字号，逐段画出。
- **雨与灰烬**：24 个淡墨点（alpha 0.03–0.08），每个配一圈水线；灰烬是 90 个随 curl noise 飘动的小方点。
- **墨烟**：从每个字 128px 的缓存图里按 alpha 采样出点，每字 150×字号²个，全场上限 26000 个粒子。速度由 curl noise、向心吸引和切向旋转三部分组成；坍缩阶段每帧按 `exp(-dt*(0.5+9q))` 收缩半径，同时旋转。每 4 个粒子写一次 B 层，让烟有柔光。
- **诗云星河**：380 条诗句链。每条有半径 r、初始角 θ、厚度 z；角速度 ω=0.55/√r，坍缩时按角动量守恒加速，上限 14 倍。投影时 y 乘 0.5（倾角），深度因子 `f=1+0.32 sinθ` 控制近大远小、远处更淡。字形统一用 64px 的 `fillText`，通过变换矩阵缩放和旋转，避免每个字都重设 font 字符串。
- **一画**（离屏精灵图 6138×1650，330 像素/世界单位）：
  - 头部是超椭圆（e=2.6），旋转 -0.62 弧度，表现逆锋起笔；外加 26 根泼墨尖刺、700 个雾状喷点。
  - 身体由 320 根笔毫线条组成。每根笔毫有自己的枯竭点 `e = 0.98-0.42|o|^1.6-rnd²*0.32`（两侧先枯）；越过枯竭点先出现断续，再逐渐变细到消失。每根还有自己的摆动（wob 0.035），末端向外散开 28%（散锋）。
  - 22 根「诗句笔丝」只在干笔区显示文字：12–13px 的 Noto Serif，沿切线方向排列，字身不旋转 90°。附近 ±6px 内的笔毫在干笔区让开，避免盖住文字。
  - 揭示方式：裁剪区域 = 已写部分的矩形 ∪ 笔锋处的椭圆（圆头笔锋）∪ 压笔时不断扩大的圆。另有 48 个泼溅墨点做抛物线飞行后落纸。
- **调色**：`grade(t)` 按段落平滑混合曝光、暗角、饱和度和色偏（祭侄段偏暖偏暗，寒食段偏冷、饱和度降低，诗云段暗角 +0.35，压笔瞬间曝光 +12% 做闪白），外加每帧不同的胶片颗粒（0.012）。

### 4. 音频处理（`audio.py`）

- **古琴音色**：加法合成 17 个非谐分音，`f_k = k·f0·√(1+0.00012k²)`。振幅按 `|sin(πk·0.13)|/k` 模拟拨弦位置，高次分音衰减更快。先对音高曲线积分得到相位，所以能做按音滑动（glide）和吟猱（5.2Hz 颤音）。叠加 150–2600Hz 带通的琴体共鸣和 6ms 的拨弦噪声。
- **泛音**：基频正弦（衰减 1.9s），加 2 次、3 次弱分音。
- **笔触声**：带通噪声（700–4200Hz，越干越往高频移），乘正弦包络，干笔时再叠加颗粒调制。每一笔都对应一个音效；书写段按每秒 5–8 次的节奏随机铺满。
- **其他音效**：
  - 墨滴：1600Hz 到 500Hz 的快速下滑音，外加 55Hz 低频冲击。
  - 删字：刮擦声。
  - 雨：1.5–9kHz 噪声加 420 个高频水滴声。
  - 大笔：38Hz 下滑的低频轰鸣，F1/C2/F2/C3 古琴和弦，扫笔噪声（低频逐渐减弱、高频逐渐变干，声像从左移到右），末尾 8 个甩墨滴声。
  - 印章：180Hz/410Hz 短衰减加噪声，形成木质的「咚」。
- **混响**：合成一个 4.2 秒的指数衰减噪声脉冲响应（左右声道用不同种子），用 `fftconvolve` 卷积，每个声音按比例送入混响。
- **动态与响度**：以高潮 50–52s 的 RMS 为基准归一到 -15 dBFS，再用 tanh 软限幅；49.33–49.98s 静默；59.6–60.5s 淡出；开头 50ms 淡入防止爆音。
- **校验**：每 2 秒统计一次 RMS 和峰值。发现诗云段 -14dB 反而比高潮（-18.8dB）还响，于是削弱颗粒、加强压笔，最终曲线是正文约 -25dB，诗云升到 -17dB，高潮 -16dB。

### 5. 渲染与导出命令

```bash
# 启动浏览器的关键参数（Playwright）
executablePath: '/opt/pw-browsers/chromium-1194/chrome-linux/chrome'
args: ['--disable-background-networking','--disable-component-update','--no-first-run',
       '--disable-accelerated-2d-canvas','--use-angle=swiftshader','--enable-unsafe-swiftshader','--ignore-gpu-blocklist']

# 帧管道 → 母版（无声，crf16，148MB）
ffmpeg -y -f image2pipe -framerate 30 -c:v mjpeg -i - -c:v libx264 -preset medium -crf 16 -pix_fmt yuv420p video_v2.mp4

# 最终交付：两遍编码，限定码率，轻降噪（28.7MB，低于 30MiB 的发送上限）
ffmpeg -y -i video_v2.mp4 -vf hqdn3d=1.2:1.2:4:4 -c:v libx264 -preset slow -b:v 3500k -pass 1 -an -f null /dev/null
ffmpeg -y -i video_v2.mp4 -i score.wav -vf hqdn3d=1.2:1.2:4:4 -c:v libx264 -preset slow -b:v 3500k -pass 2 \
       -pix_fmt yuv420p -movflags +faststart -c:a aac -b:a 192k -shortest out.mp4
```

体积估算：`视频码率(kbps) ≈ (目标MB×8192 / 时长s) - 音频kbps`，再留 5% 余量。本片：(28×8192/60.5) - 192 ≈ 3600，取 3500k。

### 6. 时间分配（实际）

| 环节 | 用时 | 说明 |
|---|---|---|
| 环境探测、装依赖 | 约 8 min | 含 Playwright 浏览器路径问题 |
| 纹理 | 约 5 min | |
| 引擎首版 | 约 25 min | 一次写完约 1100 行 |
| 预览迭代 8 轮 | 约 35 min | 每轮 1–3 分钟渲染，加上看图和修改 |
| 性能剖析和优化 | 约 8 min | 两处改动让单帧从约 2.5s 降到约 0.6s |
| v1 全片渲染 | 24.6 min | 同时写音频 |
| 复查、修改 | 约 8 min | |
| v2 全片渲染 | 18.8 min | |
| 编码、压缩、复查 | 约 12 min | crf20 编码约 4 分钟，两遍编码约 3 分钟 |

最耗时的是**全片渲染**和**预览迭代**。提速办法：

1. 一开始就加 `--disable-accelerated-2d-canvas`，并控制着色器的纹理采样次数（下面第三部分坑 1、坑 2）。
2. 预览用 960×540 或 15fps。
3. 粒子只从诗云段开始有状态，前 40 秒可以拆成 2–3 个进程并行渲染：每个进程先用 `stepOnly` 预热镜头弹簧，再按帧区间渲染，最后 concat。但本机只有 2 核，收益有限。
4. v1 之前就做一次 1fps 全片低清预览，让 v1 直接成为终版。

- [ ] 从最终压缩版里抽 1–2 帧，确认压缩后的细节，尤其是微缩文字仍然可读
- [ ] 文件名有意义；源代码打包时不带 node_modules
- [ ] 说清楚已知局限（比如这次的「楷书底本、意临行书」）

### 2. 踩过的坑

**坑 1：2D 画布走了 GPU 模拟，冷启动一帧 54 秒**
- 现象：跳到第 700 帧预览时，单帧耗时 54 秒；JS 部分只有几毫秒，时间全耗在纹理上传上。
- 原因：`--use-angle=swiftshader` 让 Chromium 把 Canvas2D 也放到软件 GPU 上加速，每一次合成操作都要经过 SwiftShader。
- 解决：加上 `--disable-accelerated-2d-canvas`，Canvas2D 改用 CPU 版 Skia。同一帧从 54s 降到 2s，热帧的上传时间从 207ms 降到 47ms。
- 预防：无头软件渲染时默认就带上这个参数。

**坑 2：着色器单帧 1.25 秒**
- 现象：用 readPixels 同步计时后发现，一次 drawArrays 就要 1.2 秒。
- 原因：每个像素约 20 次纹理采样（4 次浮雕差分、云、织纹、桌面、B 层 6 次，以及 D 层），在 2 核 SwiftShader 上太重。
- 解决：把浮雕光照和云絮预先烘焙进 `paperL.png`；B 层从 6 次采样减到 2 次；绫边和桌面只在纸外才计算（用 `if(dPaper>-0.01)` 分支）；D 层只在片尾计算。最后约 9 次采样，单帧 0.45s。
- 预防：软件渲染时，每像素纹理采样控制在 10 次左右；能静态预算的都烘焙进贴图。

**坑 3：计时结果误导**
- 现象：`renderFrame` 只要 10ms，`toDataURL` 却要 2–3s；插入 `gl.finish()` 后计时全是 0。
- 原因：Chrome 的命令缓冲是异步的，`finish` 实际上不阻塞。
- 解决：每个阶段后调用 `gl.readPixels(0,0,1,1,…)` 强制同步。
- 预防：剖析 WebGL 一律用 readPixels 做同步点。

**坑 4：Playwright 找不到浏览器**
- 现象：报错 `Executable doesn't exist at …chromium_headless_shell-1243…`。
- 原因：npm 装的是新版 Playwright，而镜像预装的是 chromium-1194；按环境说明也不能运行 `playwright install`。
- 解决：`executablePath:'/opt/pw-browsers/chromium-1194/chrome-linux/chrome'`。

**坑 5：工具命令 2 分钟超时**
- 现象：预览命令运行到一半，报 Exit code 143。
- 原因：Bash 工具默认 2 分钟超时。
- 解决：`(nohup node preview.js … > log 2>&1 &)`，再用 `sleep N; cat log` 轮询；长任务把 timeout 设到 300000 并分段等待。
- 预防：所有渲染任务都放后台运行。

**坑 6：浏览器后台联网被代理拒绝**
- 现象：日志里出现 accounts.google.com 等连接被拒。
- 原因：Chromium 的后台服务在联网，而容器有出网白名单。
- 解决：加 `--disable-background-networking --disable-component-update --no-first-run`。
- 另外：页面报的 404 是 favicon，无害。

**坑 7：宣纸像石膏墙**
- 现象：纸面凹凸感过强，看起来像水彩纸或墙面。
- 原因：浮雕系数 0.5 太大。
- 解决：降到 0.09，后来改成烘焙贴图，系数 0.05；同时把纤维对比提到 0.11，加入大尺度云絮。
- 预防：先单独输出纸张纹理的静态截图检查，再往上叠墨。

**坑 8：墨滴像卡通溅射**
- 现象：26 个大溅点，加上三层同心圆，看起来像漫画里的「啪」。
- 解决：只留 9 个极小的溅点（半径 0.0015–0.005）；主体改用径向渐变，在噪声多边形里填充；落纸后退成淡墨，洇边交给着色器的吸墨阈值去做。
- 预防：真实的墨滴落在宣纸上，主要变化是吸收扩散，不是飞溅。

**坑 9：字像印刷楷体**
- 现象：Arphic 楷体轮廓太规整，看起来像字库。
- 原因：笔顺数据源本身就是楷书字形。
- 解决：
  - 逐字变形：横画上扬（rise）、右倾（it），加正弦扰动。
  - 每一笔随机减细（destination-out 描边）或加粗（描边）。
  - 笔内牵丝、字间连笔。
  - 笔毫纹理和墨量驱动的飞白。
  - 字号、旋转、横向偏移随机抖动，整列轻微摆动。
- 残留局限：本质上仍是「楷书底本的意临」，不是原帖风格。下次如果要求书风逼真，就要找真正的行书字形数据，或者在「写字动画」和「原帖风格」之间提前取舍，并跟用户说明。

**坑 10：字间连笔像乱划的线**
- 现象：细线斜穿过字身。
- 原因：贝塞尔控制点向左偏，而且任意两个字之间都画了连笔。
- 解决：只在上字最后一笔收在下方（Y<250）、下字第一笔起在上方（Y>500）时才画；曲线改成 S 形（控制点沿竖直方向）；线宽降到 0.009×字号。

**坑 11：镜头裁掉列首、露出纸边**
- 现象：
  - h=9.4 时每列的第一个字被裁掉。
  - 开篇全景时右侧露出绫边和桌面。
  - 「悲夫」特写时，镜头对准了别处。
- 原因：
  - 列长约 12 单位，h 太小装不下整列；y 跟随权重也太大。
  - 纸张右边界只到 x=7.8，全景的视野超出了纸面。
  - 写字头位置取平均时，把同时在写的小号款识也算进去了。
- 解决：
  - 全景 h 取 12.2，y 固定在 5.7；跟随权重改为 `clamp((12.4-h)/6,0,0.7)`，只有特写时才跟随。
  - 纸张范围扩到 right=16、left=-64。
  - 计算焦点时排除 size<0.5 的字。
- 预防：先算清楚内容的包围盒和最大视野，再定纸张和镜头；每段都至少抽一帧检查。

**坑 12：雨点像霉斑**
- 现象：170 个灰色圆点，看起来像纸发霉了。
- 解决：减到 24 个，alpha 降到 0.03–0.08，再加一圈水线。
- 预防：氛围元素的第一版就做得很淡，不够再加。

**坑 13：大笔的诗句笔丝变成「条形码」**
- 现象：一画的中段是一块死黑，后面接一片横排的乱码。
- 原因：
  1. 字形旋转写成了 `ang+π/2`，每个字都侧躺着。
  2. 118 根笔丝间距只有 2.8px，而字号 13px，字互相重叠。
  3. 为笔丝预留的让位区是 ±9px × 30 根，加起来超过了整个笔宽，把所有笔毫都挤掉了。
  4. 实心墨芯画到了 s=0.46，然后突然结束。
- 解决：
  - 字形旋转改成 `ang`。
  - 笔丝减到 22 根，只在干笔区（s 大于该笔丝的起点、且笔毫自身已开始干枯）出现，让位区 ±6px。
  - 实心墨芯只保留到 s<0.16；笔毫的枯竭点分布改为两侧先枯；末端逐渐变细，加摆动和散锋。
- 预防：微缩文字要先算清「字号 ≤ 笔丝间距」，并单独输出一张 1:1 局部图检查。

**坑 14：大笔揭示时，前沿是一条直的矩形边**
- 解决：裁剪区域改为矩形截到笔锋前 0.9 倍半宽，再并上一个椭圆笔头。

**坑 15：诗云像树的年轮**
- 现象：一圈圈过于规整；视角转动后，左上角露出桌面。
- 解决：初始角的随机范围扩大到 ±1.2 弧度，厚度 z 随半径增大（0.25+0.14r），诗句链从 560 条减到 380 条；纸张左边界扩到 -64；镜头 h 从 15.8 改为 14.3。

**坑 16：诗云比高潮还响**
- 现象：RMS 统计显示 46–48s 是 -14dB，而压笔的 50s 只有 -18.8dB。
- 原因：2600 个颗粒叠加起来能量很大；原来的归一化以全片峰值为准，由最响的段落决定整体音量。
- 解决：颗粒振幅乘以 0.35 左右，持续低音减半，压笔和弦加大 1.6 倍；改为以高潮窗口的 RMS 为基准归一，再做 tanh 限幅。
- 预防：先画出响度曲线，确认最高点落在叙事高潮上。

**坑 17：成片体积超限**
- 现象：
  - v1 用 `-tune grain -crf 15`，446MB。
  - 混流时用 crf20，66.5MiB，发送时报「exceeds the 30 MiB upload limit」。
- 原因：着色器每帧加的随机颗粒噪声非常消耗码率。
- 解决：胶片颗粒从 0.022 降到 0.012；最终用两遍编码限定 3500k，加 `hqdn3d=1.2:1.2:4:4` 轻降噪，得到 28.7MB，微缩文字仍然可读。
- 预防：开工时就确认交付上限；颗粒噪声要节制；母版和交付版分开输出。

**坑 18：事件表里有重复事件**
- 现象：「永」的事件数组里，有些笔画的 `yong` 事件出现了 2–3 次（按八法批注逐条导出造成的）。
- 影响：音频脚本用字典按笔画序号 `yong[i]` 去重，所以没有产生重复音效。
- 预防：导出事件时就按笔画去重。

**坑 19：跳帧预览，粒子不对**
- 原因：粒子和镜头弹簧都是按帧累积的状态。
- 解决：提供 `window.stepOnly(i)`，只更新状态不绘制；`renderFrame` 遇到不连续帧时打印警告。全片渲染必须从第 0 帧顺序进行。

**坑 20：中文字体**
- fontsource 的中文字体按 unicode-range 拆成了上百个子集（每套 186 个文件），必须用 `document.fonts.load(字体, 实际要用的字)` 触发加载，否则 Canvas 会悄悄用回退字体。
- 部分书法字体可能缺繁体字形，所以诗云和微缩诗句都用简体语料，笔顺数据则全部使用繁体。
- 印章、片尾用系统自带的 Noto Serif CJK TC（字重 300/700/900），同样要先调用 `fonts.load`。

## 四、可复用模板

### A. 代码视频制作流程模板

```
0. 约束确认（10 分钟）
   - 时长 T、帧率 F、分辨率、总帧数 N=T×F
   - 交付体积上限 → 目标码率 = 上限MB×8192/T - 音频kbps，留 5% 余量
   - 环境：浏览器路径、WebGL 探针、ffmpeg、字体、CPU 核数、命令超时

   - 一句话主线 → 情绪曲线 → 时间表（段落 / 起止秒 / 镜头高度 / 声音）

   - 纹理：numpy FFT 噪声（可平铺）；静态光照预先烘焙
   - 文本和数据：语料文件、笔顺或字形数据；逐字检查覆盖情况

3. 引擎骨架（先跑通，再做好看）
   - renderFrame(i)：t=i/F，更新状态 → 清空图层 → 画各图层 → 上传纹理 → 着色器合成
   - stepOnly(i)，固定随机种子，导出事件表 EVENTS
   - 镜头：h 关键帧（对数插值）+ 位置关键帧 + 跟随权重 + 临界阻尼弹簧

   - preview.js：渲染 8–12 个关键帧，拼成缩略图拼图，看完只改最差的那一帧
   - 先做性能剖析（readPixels 同步），单帧要降到 1 秒以内再往下做

5. 全片低清或 1fps 预览（可选，强烈建议）→ 全片母版（后台运行、写日志、定期存最新帧）

7. 混流与压缩：两遍编码，限定码率，轻降噪，faststart，-shortest

8. 复查：ffprobe、1fps 全片拼图、压缩版局部抽帧；说明已知局限后再交付
```
