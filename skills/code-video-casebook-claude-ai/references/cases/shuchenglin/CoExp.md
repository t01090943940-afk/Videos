# 代码驱动的卡点宣传片：方法论、模板经验与踩坑全集

> 基于《树成林 · 60 秒宣传片》的完整复盘（1920×1080 / 30fps / 60.0s，纯代码逐帧渲染，未使用剪辑软件）
> 适用：社群/产品/活动宣传片、混剪、作品集快剪、任何"音乐驱动 + 大量素材 + 强观点"的短片

---

## 0. 一页纸总览

**一句话核心：卡点准，不靠手感，靠坐标。**
先把音乐解剖成一张时间网格，再把音乐按网格"重构"成需要的长度，最后把每一个画面、文字、音效事件都写成网格坐标。

```
第 k 拍的时间 = T0 + BEAT × k        （本片：T0 = 4.0s，BEAT = 0.375s，BAR = 1.5s）
```

**完整产线（10 步）：**

```
① 素材普查 → ② 音乐解剖 → ③ 音乐重构 → ④ 叙事 × 能量映射 → ⑤ 真实素材采集（虚拟时间录屏）
→ ⑥ 合成器（seek(t) 确定性渲染） → ⑦ 声音设计（合成 SFX + 限幅） → ⑧ 分段并行渲染
→ ⑨ 机器质检（联系表 / 黑帧扫描 / 起音对齐） → ⑩ 交付（体积、格式）
```

**决定成败的三件事（按重要性排序）：**

1. **一条连续的节拍网格。** 音乐只在"同一个小节位置"下刀拼接，整条音轨只有一个时钟。
2. **叙事结构 = 能量结构。** 核心观点放在最安静的段落，叙事高潮、音乐高潮、视觉高潮在同一帧重合。
3. **多层卡点 + 多通道确认。** 小节 / 拍 / 十六分 / 镜头内呼吸四层节奏；每个关键点同时用音乐、SFX、闪白、震动、色散、字幕去"确认"。

---

## 1. 核心方法（按产线顺序）

### 1.1 素材普查：先盘点，再构思

在想创意之前，先把手里所有东西机器化地过一遍：

| 动作 | 工具 | 目的 |
|---|---|---|
| 解压并修正中文文件名 | Python `zipfile` + cp437→utf-8/gbk 转码 | 避免乱码路径（见坑 E1） |
| 读所有文档 | 设计基因库、参考拆解、选拔表、作品数据 | 提取**品牌规范、事实数据、原话金句** |
| 图片联系表 | PIL 拼 8 列缩略图 | 一眼看出哪些能用、哪些是"Site not found"/空白占位 |
| 视频联系表 | ffmpeg 抽帧 → PIL 拼 5 帧/行 | 找每段视频里最好看的区间 |
| 真实网页巡检 | Playwright 实时滚动截 8 张 | 判断哪些页面值得逐帧录制 |
| 媒体参数 | `ffprobe` 时长、分辨率 | 提前知道哪些素材放大会糊 |

**本片从素材里挖出的"弹药"：**

- **品牌规范：** 黑白 + 唯一跳色正红 `#E32B16`；Archivo 900 / Space Mono / 思源黑体 Black；缓动统一 `outExpo`；章节卡"0X — 名称"；载入计数 → 红幕 → 巨字。
- **事实数据：** 选拔表中 5 月 8 日–20 日的 264 次网站分享、38 件精选、331 张写真、16 个 SKILL、群聊 78 条 → 38 条、公众号 108 篇 → 9 类。
- **原话金句：** "我不配问"、"重机枪对骑兵"、"AI 时代 60° / IP 时代 15°"、"先做，再想"、"说一句话，拿到成品"。
- **主题曲：** `song.mp3`（169 秒，社群授权）。

> 原则：**观点、数字、金句全部从素材里取，不自己编。** 可信度是"后悔感"成立的前提。

### 1.2 音乐解剖：把听觉变成数据

我全程听不到声音，所以是用数据"看"音乐。这反而更精确。

```python
y, sr = librosa.load('song.mp3', sr=22050)
tempo, beats = librosa.beat.beat_track(y=y, sr=sr)              # → 161.5 BPM（实际 160）
rms = librosa.feature.rms(y=y, hop_length=512)[0]               # 能量曲线（每 4s 平均）
S = librosa.amplitude_to_db(np.abs(librosa.stft(y)), ref=np.max) # 频谱图（看段落边界）
onsets = librosa.onset.onset_detect(y=y, sr=sr, units='time')   # 起音点（毫秒级）
```

**要读出的四样东西：**

1. **BPM → 拍长、小节长。** 160 BPM → 1 拍 0.375s，1 小节 1.5s。
2. **段落结构。** 从频谱图 + 能量曲线看出：主歌 → 渐强（军鼓滚奏越来越密）→ 憋气 → 爆发 → 抽空 → 爆发 → 过渡段 → 最大爆发 → 硬停 → 尾音。
3. **关键起音点（精确到 0.01s）。** 本片：63.05 / 75.05 / 96.05 / 120.07 / 150.05。
4. **网格是否严格。** 爆发间隔都是 12s 或 24s，也就是整 8 或 16 小节 → 这首歌可以放心用数学去剪。

**本片的音乐地图（原曲时间）：**

| 时间 | 能量 | 事件 |
|---|---|---|
| 0–30s | 低 | 主歌，稀疏 |
| 30–60s | 中 | 鼓进，渐强 |
| 58.0–59.9s | 中 | 十六分音符军鼓滚奏（天然上升音） |
| 59.9–63.05s | 低 | 3 秒"憋气"，只剩八分音符脉冲 |
| **63.05s** | 高 | 爆发 A |
| 74.33–75.05s | 骤降 | 抽空 0.72s → 75.05s 重新砸下 |
| 88.6–96.05s | 低 | 过渡段（92–96s 几乎只剩脉冲） |
| **96.05s** | 最高 | 爆发 B（全曲最强，持续 16 小节） |
| **120.07s** | 硬停 | 突然掐断 |
| 150.05s → 160s | 衰减 | 最后一下重音 + 尾音 |

### 1.3 音乐重构：剪短但不断网格

**铁律：只在同一个小节位置下刀。** 所有切点都是 `63.05 + 1.5 × n`，拼接后网格连续。

```python
A = song[59.05 : 81.05]      # 滚奏尾巴 + 3 秒憋气 + 爆发 A（含 74.33 的抽空）
B = song[87.05 : 120.07]     # 爆发 A 的最后一小节 + 过渡段 + 爆发 B + 硬停
S = 0.4s 静音                 # 最响之后的"死寂"
C = song[150.03 : 155.2]     # 真正的尾音，末 3.4s 平方曲线淡出
music = xfade(A, B, 6ms) + S + C    # 接口 6–12ms 交叉淡化防爆音
```

**每一刀为什么这么下：**

- **起点 59.05：** 前 4 秒 = 滚奏尾巴 + 憋气，第 4.0 秒进爆发。开头 4 秒就是钩子。
- **砍掉 81–87：** 那是重复段；砍掉后过渡段刚好落在成片 23.55 秒。
- **保留 74.33 的抽空：** 这是现成的"断拍"戏剧点，价值极高。
- **结尾不用中段收：** 120.07 硬停 → 0.4 秒静音 → 原曲尾音。停顿本身也是一拍。

**重构后的成片时间地图（全片唯一时钟）：**

| 成片时间 | 音乐 | 对应第几拍 |
|---|---|---|
| 0.00–0.85 | 军鼓滚奏尾巴 | — |
| 0.85–4.00 | 憋气（八分音符脉冲，0.1875s） | — |
| **4.00** | 爆发 A | 第 0 拍 |
| 15.28–16.00 | 抽空 | — |
| **16.00** | 重新砸下 | 第 32 拍 |
| 22.00 | 拼接点（听感无缝） | 第 48 拍 |
| 23.55–31.00 | 过渡段 | — |
| **31.00** | 爆发 B | 第 72 拍 |
| **55.02** | 硬停 | — |
| 55.02–55.42 | 静音 | — |
| **55.42** | 尾音重音 | — |
| 60.00 | 结束 | — |

> 验算：`(31.0 − 4.0) / 0.375 = 72`，整数，说明网格贯通。每一个关键时间都要做这种整除验算。

### 1.4 叙事 × 能量映射：结构卡点比单点卡点更重要

**能量曲线 = 情绪曲线。** 把要讲的话按音乐起伏放进去：

| 成片时间 | 音乐 | 叙事功能 | 内容 |
|---|---|---|---|
| 0–4 | 滚奏 + 憋气 | **钩子** | 一个群。12 天。264 个网站。→ 红幕 FIRST EDUCATION |
| 4–15.28 | 爆发 A | **证据** | 网站 / 写真 / 视频 / 智能体，真实作品每拍一切 |
| 15.28–16 | 抽空 | **转折** | 冻结去色："每一件，都从一句话开始。" |
| 16–23.55 | 重新砸下 | **方法** | 输入框打字 → 回车 → 官网真实开场 → "说一句话。拿到成品。" → 作品墙拉远 |
| 23.55–31 | **最安静** | **核心观点** | "拉开差距的，从来不是技术。" → "是一堵墙。" → 我·不·配·问 → 裂缝 → "今天，拆了它。" |
| **31.00** | **最大爆发** | **高潮** | 墙碎成几十片 |
| 32.5–38.5 | 高 | 你能拿到什么 | 官网"使用指南"8 项，每项 2 拍 |
| 38.5–44.5 | 高 | 为什么是现在 | 斜率图 15° vs 60° → 重机枪对骑兵 |
| 44.5–50.5 | 高 | **后悔感** | "你刷短视频的 12 天里" → 作品墙逐格填满，计数 000 → 264 |
| 50.5–55.02 | 高 | **行动号召** | 先做，再想。→ 快闪 → 反白："下一件作品，署你的名字。" |
| 55.02–60 | 静音 + 尾音 | **落版** | 红点 → 树成林 → 二维码 → 未完待续 |

**两条关键决策：**

1. **核心观点放在最安静的地方。** 吵的时候观众只能看画面，读不进字；安静时字才会被读进去。7.45 秒的过渡段是全片最慢的部分，却让 31 秒的爆发加倍。
2. **三重叠合。** 31.00 秒这一帧：叙事高潮（拆墙）+ 音乐高潮（最大爆发）+ 视觉高潮（碎片飞散）。一部片子至少要有一个这样的时刻。

### 1.5 真实素材采集：虚拟时间逐帧录屏

**问题：** 直接录屏会掉帧，而且动画速度取决于机器性能。
**方案：** 接管页面的时钟，每次精确推进 33.3ms，再截一张图。

注入脚本（`vtime.js`，通过 `add_init_script` 在页面脚本之前运行）的要点：

```js
let vt = 0;
performance.now = () => vt;                      // GSAP / 自写 rAF 动画都读这个
Date.now = () => t0 + vt;  window.Date = class extends OD { ... }   // new Date() 也要接管
requestAnimationFrame = cb => { rafQ.set(id, cb); ... }            // 攒起来，手动触发
setTimeout / setInterval → 放进虚拟定时器队列
window.__advance = dt => {
  // 1) 按时间顺序执行到期的定时器
  // 2) vt += dt，执行本帧所有 rAF 回调
  // 3) CSS 动画与过渡：document.getAnimations() 逐个 pause() 并设 currentTime
  // 4) <video>：暂停并手动设 currentTime
};
```

采集循环：

```python
for i in range(n):
    滚动（若有）→ 使用 Lenis 的站点必须调用 FX.lenis.scrollTo(y, {immediate:true, force:true})
    await pg.evaluate('__advance(33.333)')
    r = await cdp.send('Page.captureScreenshot', {'format':'jpeg','quality':88})  # 不用 page.screenshot（见坑 R2）
```

**采集清单（配置驱动）：**

```json
{"name":"site_intro","url":"index.html","dur":6.5}
{"name":"site_full","url":"index.html","dur":35.3,"pre":[["adv",7]],"scroll":"t*1400"}
{"name":"last2","url":"...最后两天.html","dur":6,"pre":[["eval","__go()"],["adv",0.8]]}
```

- `pre`：预推时间 `adv`、点击 `click`、执行脚本 `eval`。
- `scroll`：滚动位置写成时间 t 的表达式。

**本片实际产出：** 官网开场 195 帧（载入计数 → 红幕字符锁定 → 树成林），官网全站滚动 1059 帧，"从 0 到 1" 258 帧（含"先做，再想"真实出场），外加若干作品开场。演示视频用 ffmpeg 抽成 30fps 图片序列。

### 1.6 合成器：`seek(t)` 确定性渲染

**架构：** 一个 1920×1080 的 Canvas 页面，`seek(t)` 只根据时间 t 画出这一帧。

```
seek(t):
  重置本帧特效状态
  相机：拍点冲击 + 撞击点抖动   →  对"底层镜头"做缩放/平移
  底层：SHOTS 中所有覆盖 t 的镜头，按顺序 await 绘制
  叠加：OVER 中所有覆盖 t 的层（文字、UI、会改特效状态的钩子）
  后期：整屏抖动 → 撞击闪白 → 切片故障 → 红绿蓝错位 → 颗粒（overlay）→ 暗角
  HUD：角标、时码、进度条、章节号、作者署名
```

**时间线的写法（核心）：**

```js
const bt = k => 4.0 + 0.375 * k;          // 所有事件都写成拍坐标
full('wjm1', bt(0), bt(1), {z0:1.12, z1:1.02});
seqFull('p918b', bt(1), bt(2), {from:212, speed:1.4});
over(bt(0), bt(0)+.4, lt => stamp('网站', lt));
chapter(4.0, 7.0, '01 — 网站 · WEBSITE');
```

**镜头类型库（全部可复用）：**

| 函数 | 效果 | 用途 |
|---|---|---|
| `full(key)` | 全屏静图 + 推拉镜头 | 暗调、电影感的作品 |
| `win(key)` | 浏览器窗口外框 + 背景同图模糊 + 入场倾斜回正 | 网页截图（掩盖分辨率不足） |
| `seqFull(name)` | 全屏图片序列，可调起点、速度、循环 | 录屏、演示视频 |
| `seqWin(name)` | 窗口化图片序列 | 带界面的演示 |
| `mosaic()` | N×M 作品墙，逐格填充，可聚焦某格缩放 | 量感、"日常"、计数 |
| 盖牌叠层 | 卡片逐拍从上方砸下并叠放 | 竖版图片（写真合辑） |
| 分屏 | 左原素材去色 / 右成片擦入 | 前后对比 |
| 墙 + 裂缝 + 碎片 | 砖墙 → 字 → 随机游走裂缝 → 三角剖分碎片飞散 | 核心隐喻 |
| 斜率图 | 坐标轴 → 15° 灰线 → 60° 红线射出 + 角度计数 | 抽象观点可视化 |
| 信息流 | 6 列竖版卡片高速上滚，去色压暗 | "刷短视频"的具象化 |

**文字引擎（一个函数，7 种进场方式）：**

`text(str, x, y, {size, mode, lt, stagger, dur, out, color, align})`

| mode | 行为 | 用在 |
|---|---|---|
| `rise` | 逐字遮罩升起（`outExpo`） | 标题、观点句 |
| `drop` | 逐字掉落 + 回弹（`outBack`） | 冷开场、"先做，再想" |
| `slam` | 整体从 1.9 倍砸到 1 倍 | "署你的名字"、落版 logo |
| `roll` | 老虎机式纵向滚动 | 编号 01–08 |
| `type` | 打字机 | 输入框 |
| `fade` | 逐字淡入 | 副标题、出处 |
| `none` | 静态 | HUD、计数 |

另有 `scramble()`：英文字符随机跳动后逐个锁定，官网 FIRST EDUCATION 同款。

**后期特效参数表：**

| 特效 | 参数 | 触发 |
|---|---|---|
| 拍点冲击缩放 | 普通拍 +2%，小节首拍 +4.5%，按 `exp(−11t)` 衰减 | 三段爆发内每一拍 |
| 撞击冲击 | +8%×强度，按 `exp(−9t)` 衰减 | 4.0 / 16.0 / 17.5 / 31.0 / 40.0 / 46.75 / 55.42 |
| 相机抖动 | 26px×强度，按 `exp(−10t)` 衰减 | 同上 |
| 撞击闪白 | 55%×强度，0.25s 线性衰减 | 同上 |
| 红绿蓝错位 | 小节首拍约 11px；快闪段 6→20px | 用 multiply 分离三通道，再 lighter 叠加 |
| 切片故障 | 6–16 条横切片随机水平位移 | 快闪、冷开场脉冲 |
| 颗粒 | 3 张 960×540 噪声图轮换，overlay，10% | 全程 |
| 暗角 | 径向渐变，边缘 72% 黑 | 全程 |
| 章节巨字 | 380px，difference 混合，1.25 → 1 倍，0.34s | 每组开头 |

### 1.7 声音设计：用代码合成音效

全部 numpy 合成，零素材库：

| 音效 | 合成方法 | 放置 |
|---|---|---|
| 撞击声 | 正弦下扫 98→38Hz，`exp(−3.2t)` + 高通噪声脆响 + 低通噪声主体，`tanh` 饱和 | 4 次大爆发 |
| 上升音 | 低通噪声（截止频率逐渐打开）+ 200→2000Hz 正弦扫频，包络 x^2.2 | 1.0→4.0、14.08→15.28、28.25→31.0 |
| 风声 | 低通噪声 × sin² 包络，0.35s | **提前 0.2s 起**，峰值落在切点 |
| 打字声 | 高通噪声 + 2400Hz 短促正弦 | 每个字一声，随机左右声道 |
| 碎裂声 | 90 个随机 2.5–7kHz 衰减正弦叮声 + 噪声 | 31.0 |
| 故障声 | 方波 + 高通噪声 | 冷开场每小节 |
| 闷响 | 短撞击 | "我不配问"每个字 |

**混音：** 音乐 ×0.9 + 音效 ×0.28 → 包络限幅器（10ms 峰值跟随，阈值 0.9）→ 削顶保护 0.98。
**不要用 `tanh` 硬压整条混音**（见坑 A2）。

### 1.8 渲染：分段并行 + 管道直编码

```python
d = await pg.evaluate(f'renderFrame({i})')      # canvas.toDataURL('image/jpeg', .93)
ffmpeg.stdin.write(base64.b64decode(d.split(',')[1]))
# ffmpeg -f image2pipe -framerate 30 -c:v mjpeg -i - -c:v libx264 -crf 16 -pix_fmt yuv420p
```

- 按 CPU 核数切段（本机 2 核 → 0–900 帧、900–1800 帧），两路并行，约 3 分钟出片（约 0.25s/帧）。
- `concat` 拼接各段后与 `soundtrack.wav` 混流，AAC 320k。
- **只改了某一段，就只重渲那一段**（本片补镜头时只重渲前半段）。

### 1.9 机器质检

| 检查 | 方法 | 本片发现 |
|---|---|---|
| 全片联系表 | `ffmpeg -vf "fps=2,scale=320:180,tile=10x12"` | 视频段偏弱、斜率段开头太空、输入框太小 |
| 关键帧抽检 | 指定时间点渲染 PNG 拼图 | 背景文字和前景字打架、巨字在作品墙上看不清 |
| **黑帧扫描** | OpenCV 逐帧计算平均亮度，列出亮度 < 4 的连续区间 | **9.63–9.97s 漏了一个镜头** |
| 起音对齐 | 对成品音轨做起音检测，看 4.0 / 16.0 / 31.0 / 55.42 附近的峰 | 峰值都在 +40ms，画面领先 1 帧（可接受） |
| 响度曲线 | 每 2s 算 RMS dB | 冷开场 −26dB，爆发 −12dB，过渡段 −26dB |

### 1.10 交付

- 原画质 75MB（CRF 16）超过 30MB 附件上限 → **两遍编码 3.3Mbps + AAC 192k = 25MB**。
- 同时附上工程源码包（合成器、采集器、音频脚本、配置），方便以后重新渲染。

## 2. 以本片为模板的经验

### 2.1 60 秒高燃宣传片骨架（可直接套用）

```
[0–4s]    钩子    ：3–4 个短词，每 2 拍一个（数字优先）→ 品牌仪式 → 爆发
[4–15s]   证据    ：真实作品，每拍一切，按类别分 3–4 组，组首打巨字
[15–16s]  断拍    ：冻结 + 去色 + 一句转折
[16–23s]  方法    ：演示"怎么做到的"（输入 → 结果），用真实录屏
[23–31s]  观点    ：最安静处，一句话，一个隐喻（墙），逐字砸下
[31s]     高潮    ：隐喻被打破，三重叠合
[31–50s]  展开    ：能拿到什么 → 为什么是现在 → 你 vs 他们
[50–55s]  号召    ：主语交给观众
[55–60s]  落版    ：静音 → 品牌 → 入口（二维码 / 链接）→ 余韵
```

### 2.2 四层节奏

| 层 | 周期 | 负责 |
|---|---|---|
| 小节 | 1.5s | 章节切换、组首巨字、风声、HUD 章节号 |
| 拍 | 0.375s | 常规剪辑点 |
| 八分 / 十六分 | 0.1875 / 0.094s | 快闪、故障脉冲 |
| 镜头内呼吸 | 每拍 | 冲击缩放 + 小节错位（没切画面也在动） |

**变速原则：** 相邻两段不要用同一种密度。本片：网站段每拍切 → 写真段不切画面、在镜头内逐拍落牌 → 视频段每拍切 → 智能体段每 2 拍切 → 十六分快闪 → 冻结。

### 2.3 停留时长与可读性

| 画面内容 | 最短停留 |
|---|---|
| 纯画面（无字） | 1 拍（0.375s） |
| 快闪 | 3 帧（0.094s） |
| 8–10 字字幕 | 2 拍（0.75s） |
| 两行观点句 | 4 拍（1.5s） |
| 核心观点（过渡段） | 约 1.5s 一句，逐字升起 |

### 2.4 让卡点"被感知"的多通道清单

每个**大**卡点至少叠 4 个通道；每个**小**卡点至少 2 个：

- [ ] 音乐本身的重音
- [ ] 合成音效（撞击 / 风声 / 闷响）
- [ ] 画面切换
- [ ] 冲击缩放
- [ ] 闪白
- [ ] 相机抖动
- [ ] 红绿蓝错位 / 故障
- [ ] 文字砸入
- [ ] HUD 变化（章节号）

### 2.5 视觉系统规则

- **颜色：** 黑、白 + 一个跳色。跳色只给最关键的信息（数字、对手、"你"）。
- **字体：** 三款以内，全部沿用品牌。
- **缓动：** 全片统一一条（`outExpo`）；只有回弹效果（`outBack`）例外。
- **常驻 HUD：** 左上品牌、右上标语、左下时码 + 作者署名、右下进度条 + 章节号、四角裁切标记。它既是统一感，也是信息密度。
- **复用品牌已有的仪式：** 载入计数、红幕、字符锁定、使用指南、未完待续红点。观众会觉得"官网活了"。

### 2.6 文案规则

1. **数字优先：** "12 天。264 个网站。"比任何形容词都有力。
2. **每句一个意思，短句优先：** 一屏最多两行。
3. **转化句式"X 进去，Y 出来"：** 关键词进去，选题库出来。
4. **原话 > 自己写：** 金句全部取自社群自己的作品，并在署名位标注出处。
5. **后悔感 = 对比 + 时间：** "你刷短视频的 12 天里，他们……"
6. **最后一句把主语交给观众：** "下一件作品，署你的名字。"
7. **观点要有一个可视化隐喻：** 墙可以被拆，斜率可以被画出来。

### 2.7 素材使用规则

- **有源码的作品一律录真实运行画面**，其次才用截图。
- **低分辨率截图（960×600）不要裸放全屏：** 套浏览器外框，背景用同图模糊铺满，或者只在快闪里用。
- **每个作品标作者：** 真人真作品，才有真实感。
- **背景素材里有字时，必须压暗到 15% 以下并模糊**，否则会和前景字打架。
- **页面自己的动画比你叠加的字更好：** "先做，再想"直接用页面真实出场，不再叠一层。

### 3.1 环境与文件（E）

## 4. 做类似视频最重要的思路

### 4.1 先解剖音乐，再想画面

音乐是整部片的骨架，也是时钟。BPM、段落、起音点、网格是否严格，这四件事确定之前，任何画面创意都是空中楼阁。

### 4.2 剪音乐要像剪乐谱，不像剪声音

只在同一个小节位置下刀，拼完用整除验算。**一条贯通的网格，比一百个手动对齐的点都稳。**

### 4.3 结构卡点大于单点卡点

先让"叙事曲线"贴合"能量曲线"，再谈每一刀。观点放在最安静处；至少要有一个"三重叠合"的时刻。

### 4.4 燃来自反差，不来自一直燃

快和慢、响和静、黑和白、满和空。最响之后接最静，最密之后接冻结。**全片最慢的 7 秒，决定了最快的那 24 秒有多燃。**

### 4.5 节奏要分层，还要变速

小节、拍、十六分、镜头内呼吸，四层各司其职；相邻段落不要用同一种密度。镜头内部必须"活着"。

### 4.6 每个卡点用多个感官去确认

声音预告（风声提前 0.2s）→ 画面兑现（切换 + 冲击 + 闪白）→ 余震（抖动衰减）。**被预告过的卡点，才会让人觉得爽。**

### 4.7 真实 > 精美，可信 > 夸张

真实运行的页面、真实的作者署名、素材自带的数字和原话。后悔感只在"这是真的"时才成立。

### 4.8 一套系统，而不是一堆效果

一个文字引擎、一条缓动、一个跳色、一个常驻 HUD、一套镜头函数。统一感就是高级感。

### 4.9 时间是函数的输入

`seek(t)` 确定性渲染 + 事件全部写成拍坐标。改一个数就能全片重算，零漂移，可以批量试错。

### 4.10 用机器质检兜底，用人耳和人眼做终审

联系表、黑帧扫描、起音对齐、响度曲线能抓住"坏没坏"。**"好不好听、燃不燃"最终要靠人判断**，这是代码流程目前唯一补不上的环节。
