# 《嘟嘟追风筝》代码视频 · 复盘经验总结（CoExp）

> 项目：30 秒原创卡通短片，纯代码逐帧绘制 + 纯代码合成配乐音效，输出 1920×1080 / 30fps / H.264 + AAC 的 MP4（15.4 MB）。
> 原始需求：“用最震撼的代码视频能力做小猪佩奇动画，30s，有故事，节奏快”。
> 本文只记录这次真实发生的过程、参数、问题和解法。凡是“这次没做、只是建议”的内容都会明确标出来。

## 零、先说结论（给赶时间的人）

1. **角色版权要先处理**：小猪佩奇是受保护的角色，这次直接改成原创角色“嘟嘟”（橙围巾、蓝背带裤、正面造型），再加一个会做表情的星星风筝当第二角色。下次遇到知名 IP，开工前就要换成原创角色。
2. **技术路线**：`pycairo` 矢量逐帧绘制（先在 1280×720 逻辑坐标里画，再整体放大 1.5 倍输出 1080p），`numpy + scipy` 合成音频，`multiprocessing.Pool(2)` 并行渲染，帧数据用管道直接喂给 `ffmpeg`，不落地 PNG。
3. **所有动画都写成时间 t 的纯函数**：包括粒子、抖动、尘土、星光拖尾。这样任意一帧都能单独渲染，所以才能多进程并行，也能按时间点抽帧预览。
4. **切场放在节拍网格上**：BPM 150，一拍 0.4 s，全部 7 个切场点都是 0.4 的整数倍（2.8 / 7.6 / 10.0 / 18.0 / 21.2 / 25.2 / 28.4）。
5. **用拼图抽帧 review，别每次都渲染整片**：`still.py` 一次渲染 9～15 个时间点拼成一张图。这次一共 3 轮拼图，发现了 8 处构图/遮挡问题，全部在正式渲染前修掉。
6. **最贵的坑**：`pop_scale` 在动画起点正好返回 0，导致 `cr.scale(0, 0)`，cairo 抛出 “invalid matrix”，整片渲染在约 20.4 s 处崩掉，白跑了 52 秒。凡是 scale 来自缓动函数的地方，一律加 `if s <= 0.01: return`。

## 一、创作思路

### 1. 需求如何拆成叙事结构

需求里的关键词只有三个：**30 秒、有故事、节奏快**。我把它拆成一个“得到 → 失去 → 追逐 → 受挫 → 灵机一动 → 逆转 → 圆满”的经典小起伏结构，每 2.4～8 秒一个情绪转折。

| 时间段 | 场景 | 情绪/能量 | 镜头 | 音乐状态 |
|---|---|---|---|---|
| 0.0–2.8 | S1 片头 | 期待 ↑ | 缓慢推近（zoom 1→1.08） | 琶音 + 上升 riser，1.6 s 起 kick |
| 2.8–7.6 | S2 山坡放风筝 | 快乐 → 紧张 | 缓推，6.2 s 起风时镜头抖动 | 完整 groove，6.1 s 长 whoosh |
| 7.6–10.0 | S3 断线 | 震惊（最低点）→ 决心 | 7.6 特写 2 倍 zoom + 强抖 → 8.3 拉远；集中线 | 7.6 全停，只剩“啪” + 镲；低音 + womp；9.3 管弦 stab + 军鼓滚奏 |
| 10.0–18.0 | S4 追逐 | 最高速度 | 横向视差卷轴，每拍 zoom 脉冲，翻跟头时推近 | 最满的 groove，16 分 hi-hat |
| 18.0–21.2 | S5 大树 | 受挫（安静）→ 灵感 | 从树顶垂直摇到地面，再横摇露出蘑菇 | 去掉鼓，只剩 pad + 钟琴；20.4 叮 + 军鼓滚奏 |
| 21.2–25.2 | S6 蘑菇弹射 | 高潮 | 镜头跟着角色向上冲，竖向速度线 | drop 回满 groove，22.02 boing，23.6 镲 + stab + 星光 |
| 25.2–28.4 | S7 夕阳飞行 | 释放、温暖 | 缓慢拉远（1.18→1.0） | 去军鼓，钟琴旋律高八度，pad |
| 28.4–30.0 | S8 片尾 | 收尾 | 圆形 iris 框住角色，眨眼 | 大和弦 stab + 镲 + 星光琶音，最后 0.3 s 淡出 |

能量曲线是“两个波峰”：S4 追逐是第一个峰，S5 故意压到很低，让 S6 的弹射成为第二个、也是更高的峰。30 秒里如果一直高能，观众反而感觉不到快，所以中间必须留一个“吸气”的低谷（S5 大约 3 秒）。

### 2. 各段设计意图

- **开场 S1（2.8 s）**：片名 5 个字按 0.12 s 间隔依次弹出（`eob` 回弹缓动，带旋转回正），每个字一种颜色、白色描边外圈加深色描边，配 5 个 pop 音。1.25 s 时主角从画面下方弹上来挥手，1.5 s 风筝从右侧飞入。目的是 3 秒内交代标题、主角、道具三件事。
- **转场 S1→S2、S3→S4**：彩色斜条带划过（`band_wipe`，4 条粉/橙/黄/蓝平行四边形错开 0.1 进度，最上层带一颗旋转的白星）。它遮住硬切点，同时带有“卡通节目”的包装感。
- **S2**：主角每拍跳一次（跳跃周期 0.4 s，与 BPM 一致），落地时 squash 压扁。6.2 s 起风后：树弯曲、云加速、白色风线划过、风筝被拽走、主角身体前倾换成“用力”表情，并出现大字“呼——！”。
- **S3（全片情绪最低点）**：7.6 s 白闪 + 2 倍特写 + 强抖 +“啪！”爆炸框，音乐完全停掉 0.6 秒，用“静音”制造冲击。8.3 s 拉回全景，加漫画集中线、头顶两个“！”，气泡台词“我的风筝！！”。9.3 s 换成决心表情，大字“冲！”，红色集中线，接转场。
- **S4 追逐（8 s，全片最长）**：五层视差（远山 0.08、丘陵 0.25、树 0.5、地面 1.0、前景灌木 1.5），11.45 s 滑板从左侧滚入，11.85 s 主角跳上滑板，速度从 520 px/s 加到 1150 px/s。三次跳跃越过石头、木头、小河，最后一次是翻跟头，同时镜头推近，配“哇哦！”。17 s 起风筝飘向右侧大树，iris 圈收在风筝身上。
- **S5**：iris 从风筝处打开（和上一段 iris 收拢的位置是同一个物体，形成视觉连贯）。先看到被卡住、流汗的风筝，然后镜头从树顶垂直下摇 0.9 s 找到树下沮丧的主角（“好……高……”），20.4 s 头顶亮起灯泡，手指向蘑菇，镜头右移露出蘑菇。
- **S6 高潮**：跳上蘑菇 → 蘑菇和角色一起被压扁（squash）→ 释放后蘑菇弹性回弹 → 角色一边旋转两圈一边上升（`eoc` 减速，到终点时刚好转完 4π）→ 23.6 s 抓住风筝，白闪 + 大爆炸框 + 18 颗星光放射 + “抓到啦！”。之后角色吊在风筝下摇摆着飘走。
- **S7**：画面色调从蓝天切到夕阳（紫 → 粉 → 橙渐变），带来情绪上的“释放”。三层紫色山体视差、鸟群、星光拖尾、冒爱心，字幕“一起飞吧～”。最后 0.8 s 把角色位置插值到 (640,457)，让头部正好落在 iris 圆心 (640,320)。
- **结尾 S8**：深蓝星空 + 圆形画框，角色在框内从 0.9 倍放大到 2.0 倍（回弹缓动），头部始终在圆心；眨眼 + 挥手，然后风筝从框边冒出，“完”字弹出，彩带从两个下角喷出，最后 0.25 s 淡出到黑。

### 3. 节奏、剪辑、音画配合技巧

1. **节拍网格剪辑**：切场、跳跃节奏、zoom 脉冲都对齐 0.4 s。S4 的 zoom 脉冲写法是 `0.018*exp(-((t-10)%0.4)/0.07)`，每拍镜头轻轻“顶”一下，观众会下意识觉得画面跟着音乐在动。
2. **静音即重音**：7.6–8.2 s 的 `SILENT` 区间里不排任何鼓和贝斯，只留断线音效和镲。前面一直很满，突然抽空，冲击力远大于再加一层音效。
3. **预备动作 + 爆发**：“冲！”之前先蹲一下再起跳；蘑菇先压缩 0.22 s 再释放；军鼓滚奏（每 0.05 s 一击、力度逐渐增大）配合 riser 引出 drop。
4. **Squash & Stretch**：落地压扁（`sx=1+0.1*sq, sy=1-0.12*sq`），上升拉长（`sy=1+0.25*(1-q)`）。
5. **匹配剪辑**：S4 结尾 iris 收在风筝上，S5 开头 iris 从风筝打开；S7 结尾把角色头部移到 iris 圆心，S8 的圆形画框也在同一圆心。
6. **每段都有一个“字”**：呼——！/ 啪！/ 冲！/ 嗖——！/ 哇哦！/ 嘣！/ 抓到啦！/ 完。弹出时都配一个音效，节奏快的短片靠拟声字来强化卡点。
7. **反差色调**：S1～S6 是蓝天绿地，S7 切到夕阳暖色，S8 切到深蓝星空，色调变化本身就是一种段落标记。

## 二、具体的创作方式

### 1. 技术栈与工作流

**环境**：云端 Linux 容器，2 核 CPU，Python 3.11。
- `pycairo`：一开始没装，用 `pip install pycairo --break-system-packages` 装上，版本 1.29.1。
- `numpy` 2.4.4、`scipy` 1.17.1：已预装。
- `ffmpeg`：已预装，确认过带 `libx264` 和 `aac` 编码器。
- 中文字体：`/usr/share/fonts/opentype/noto/NotoSansCJK-*.ttc` 已存在，用 `fc-list :lang=zh` 检查。

**完整流程（这次实际的顺序）**：
1. 环境检查：一条命令同时查 cairo、numpy、ffmpeg、中文字体、`nproc`。
2. 分镜表：在思考阶段写出 8 段的起止时间、镜头、台词、音效时间点，所有时间都对齐 0.4 s 网格。
3. 写 `lib.py`：数学/缓动、图元、场景元素、角色、特效、转场。
4. 写 `scenes.py`：8 个场景函数 + 合成器 `render_frame(t)`。
5. 写 `still.py`，抽帧拼图 review：第 1 轮 9 帧（0.5～9.5 s），第 2 轮 9 帧（10～18.2 s），第 3 轮 15 帧（19.2～29.5 s），修改后第 4 轮 9 帧复查，外加 1 张局部放大图检查表情。
6. 写 `audio.py`：生成 `audio.wav`，按秒统计 RMS/峰值做响度检查。
7. 写 `render.py`：多进程渲染 900 帧，管道输出到 ffmpeg，同时混入音频。
8. 用 `ffprobe` 检查时长/编码，用 ffmpeg `select + tile` 从成片 MP4 里再抽 9 帧确认。
9. 交付：`SendUserFile` 发送 MP4；源码另外打成 zip。

**核心思想 1：每个场景都是 t 的纯函数，合成器只按时间分发**

```python
def render_frame(t):
    surf = cairo.ImageSurface(cairo.FORMAT_RGB24, W, H)   # 1920x1080
    cr = cairo.Context(surf)
    cr.scale(SC, SC)                                     # SC = 1.5，之后全部用 1280x720 逻辑坐标
    if t < T1: s1(cr, t)
    elif t < T2: s2(cr, t)
    ...
    band_wipe(cr, prog(t, 2.55, 3.05))                   # 转场叠加层，只看时间
    band_wipe(cr, prog(t, 9.72, 10.28))
    vignette(cr)
    surf.flush()
    return surf
```

**核心思想 2：一小套缓动工具，驱动所有动画**

```python
def prog(t, a, b): return clamp((t - a) / (b - a))       # 时间窗 → 0..1
def eob(x, s=1.9): x = clamp(x) - 1; return x*x*((s+1)*x+s) + 1   # 回弹（弹出字、角色登场）
def eoc(x): return 1 - (1 - clamp(x))**3                 # 减速
def eio(x): x = clamp(x); return x*x*(3-2*x)             # smoothstep（镜头移动）
def eel(x): ...                                          # 弹性（蘑菇回弹、摔倒回正）
def pop_scale(t, t0, t1=None, dur=0.35, out=0.2):        # 弹出 + 收回，所有字/气泡共用
    s = eob(prog(t, t0, t0 + dur), 2.6)
    if t1 is not None: s *= 1 - eic(prog(t, t1 - out, t1))
    return s
```

**核心思想 3：带视差系数的镜头**

```python
def apply_cam(cr, cx=640, cy=360, zoom=1.0, rot=0.0, shx=0.0, shy=0.0, par=1.0):
    ecx = 640 + (cx - 640) * par; ecy = 360 + (cy - 360) * par
    cr.translate(640 + shx*par, 360 + shy*par); cr.rotate(rot)
    z = 1 + (zoom - 1) * par; cr.scale(z, z); cr.translate(-ecx, -ecy)
```
同一组镜头参数，远景层传 `par=0.3`、近景层传 `par=1`，垂直摇镜时天空、远山、近景就自动产生不同的移动速度。

抖动也是 t 的确定性函数，用两个不同频率的正弦叠加：

**核心思想 5：角色函数返回关键点的世界坐标**

### 3. 各视觉风格的实现

| 风格/元素 | 实现方式 |
|---|---|
| 统一卡通描边 | 全局描边色 `OL=(0.30,0.12,0.20)`（深紫褐，不用纯黑），`fs()` 统一处理“填充 + 描边 + 圆角连接” |
| 多圆合成的外轮廓（树冠、云、灌木） | 先把所有圆一起用粗线描边（宽 8～10），再把所有圆一起填充，内部重叠线被填充盖住，只剩外轮廓 |
| 平滑山体 | Catmull-Rom 样条转贝塞尔（`smooth_path`）；地形高度是 3 个正弦叠加。**采样点固定在世界坐标网格上**（`xw = k*step`），卷动时只是平移，形状不会抖 |
| 视差卷轴 | 每层偏移 = 总距离 D × 系数；树按世界网格 `k*spacing` 生成，用 `hsh(k)` 决定跳过哪些、大小多少 |
| 速度可变的卷动 | `dist(t)` 写成速度曲线的解析积分（匀速 → 线性加速 → 匀速），障碍物世界坐标 = `dist(跳跃顶点时刻) + PIGX`，所以障碍物一定正好在角色脚下经过 |
| 夕阳 | 4 段线性渐变 + 太阳径向渐变光晕（`RadialGradient`，alpha 0.8→0）+ 3 层紫色山体 |
| 漫画集中线 | 70 个从屏幕外指向中心的细长三角形，随机种子取 `int(t*15)`，所以每秒闪烁 15 次 |
| 速度线 | 20～24 条，位置 = `(t*速度 + hsh 偏移) % 3200`，横向和竖向两个版本 |
| 爆炸框 | 14～16 角星，内外半径比 0.68，外沿带 jitter 抖动，种子随时间变化，所以会“跳动” |
| 文字 | cairo toy API，`select_font_face("Noto Sans CJK SC", BOLD)` → `text_path` → 依次做阴影（偏移、黑色 alpha 0.22）、白色外圈（线宽 ×2.3）、深色描边、彩色填充；用 `text_extents` 算中心点 |
| 转场 | 条带划像 `band_wipe`；iris 圆形遮罩（`FILL_RULE_EVEN_ODD`，大矩形 + 圆，外沿加粉色环）；白闪（全屏白色矩形，alpha 线性衰减 0.12～0.25 s） |
| 暗角 | 径向渐变，半径 380→820，边缘 alpha 0.30 |

### 4. 音频处理

**全部自己合成，不用任何素材**：44.1 kHz 立体声，缓冲区 `L/R = np.zeros(30*SR)`，用 `add(t0, sig, gain, pan)` 按时间把信号叠加进去（等功率声像）。

- **音色**：
  - 方波：奇次谐波加法合成，到 12 kHz 截止，避免混叠；带延迟起振的颤音。
  - 锯齿波：谐波加法，到 10 kHz。
  - 三角波：`arcsin(sin)`。
  - 钟琴：基频 + 2.76 倍 + 5.4 倍非谐泛音，指数衰减。
- **鼓组**：
  - kick：正弦，频率 48+110·e^(−32t) 下滑，e^(−8.5t) 衰减。
  - snare：1.2 kHz 高通噪声 + 190 Hz 音。
  - hi-hat：7 kHz 高通噪声，衰减 e^(−70t)。
  - 镲：4 kHz 高通噪声，2.2 s 长尾。
- **编曲**：
  - 和弦进行 C–G–Am–F，每小节 1.6 s。
  - 贝斯：8 分音符，根音与高八度交替，900 Hz 低通。
  - 琶音：16 分音符三角波。
  - 主旋律：4 小节手写（音高 + 时值），方波，4.5 kHz 低通，外加一路 0.3 s 延迟、增益 0.04 的回声。
  - 分段开关用时间区间控制：`GROOVE=[(2.8,7.6),(10,18),(21.2,25.2)]`、`SOFT=[(25.2,28.4)]`、`SILENT=[(7.6,8.2)]`。
- **音效（全部按画面时间点手工排进时间轴）**：pop（500→1600 Hz 扫频）、whoosh（噪声分 40 段、带通中心频率指数扫动、sin² 包络）、snap（咔嗒声 + 2.2 kHz + 90 Hz）、boing（频率上滑 + 16 Hz 颤音）、jump（方波上滑）、thud、womp（锯齿下滑，“失落长号”）、slide（iris 转场的滑音）、stab（多音锯齿 + 噪声，管弦齐奏打击感）、sparkle_arp（钟琴快速琶音）、riser（正弦指数上升 + 上扫 whoosh）、军鼓滚奏（每 0.05 s 一击，力度线性增大）。
- **卡点原则**：音效时间直接写成与画面相同的常量（例如跳跃开始时刻、落地时刻 `LANDS=[12.2,13.6,15.2,17.0]`、弹出字的 `t0`）。转场音效要提前量：条带划像音效从 2.5 s 开始，画面覆盖中点在 2.8 s。
- **母带处理**：`tanh(mix*1.3)/tanh(1.3)` 软削波 → 峰值归一化到 1/1.12（约 −1 dBFS）→ 最后 0.3 s 线性淡出 → 转成 int16 写 wav。
- **响度检查**：按秒统计 RMS 和峰值。groove 段 RMS 约 0.33～0.41，S5 安静段 0.098～0.145，片头 0.095，峰值 ≤ 0.89，动态起伏和设计一致。

### 5. 渲染与导出命令

```python
subprocess.Popen(["ffmpeg", "-y", "-hide_banner", "-loglevel", "error",
    "-f", "rawvideo", "-pix_fmt", "bgr0", "-s", "1920x1080", "-r", "30", "-i", "-",
    "-i", "audio.wav",
    "-c:v", "libx264", "-preset", "medium", "-crf", "18", "-pix_fmt", "yuv420p",
    "-c:a", "aac", "-b:a", "192k", "-shortest", "-movflags", "+faststart", out], stdin=subprocess.PIPE)
with mp.Pool(2) as pool:
    for fr in pool.imap(job, range(900), chunksize=8):   # imap 保证帧顺序
        p.stdin.write(fr)                                # job 返回 bytes(surface.get_data())
```

- cairo 的 `FORMAT_RGB24` 在小端机器上内存布局是 B,G,R,X，所以 ffmpeg 输入要写 `bgr0`。1920 宽时 stride = 7680 = 4×W，没有行填充，可以直接写入。
- `-pix_fmt yuv420p`：兼容手机和微信播放。`+faststart`：网页和手机可以边下边播。
- 结果：`ffprobe` 显示 duration=30.000000，h264 1920×1080 30/1，aac，文件 15,395,647 字节。
- **压缩到更小体积（这次没做，是建议）**：`-crf 23～26` 通常能降到 1/2～1/3；要发微信/小红书可以同时加 `-vf scale=1280:-2`；如果对体积有硬上限，改用两遍编码 `-b:v` 目标码率 = 目标体积 ×8 / 时长 − 音频码率。

### 6. 时间分配与提速

| 环节 | 实际耗时 | 说明 |
|---|---|---|
| 环境检查 + 安装 pycairo | 约 1 分钟 | 两条命令 |
| 分镜与节拍设计 | 占比较大（思考阶段） | 决定了后面所有常量，值得花时间 |
| 写 lib.py + scenes.py | **最耗时**（约 1500 行代码的生成） | 主要成本在代码量 |
| 抽帧 review 4 轮 | 每轮渲染不到 1 秒（约 0.056～0.063 s/帧）+ 看图修改 | 性价比最高的环节 |
| 写 audio.py + 生成 | 生成 2.7 秒 | |
| 整片渲染 | 第一次 52 秒后崩溃；第二次 **1 分 18 秒**完成（2 进程） | |
| 验证 + 交付 | 约 1 分钟 | |

**提速建议**：
1. 渲染前先用 `still.py` 把每个场景的首帧、中间帧、末帧，以及每个 `pop_scale` 的起点 t0 各跑一遍，能提前暴露类似 scale=0 的崩溃。
2. `render.py` 加 `try/except` 并打印出错的帧号；或者先以 `range(0, NF, 5)` 抽样试跑一遍。
3. 预览可以用 960×540（把 SC 改成 0.75），速度大约快 4 倍。
4. 多核机器上把 Pool 进程数设为 `nproc`。

### 1. 检查清单

**开工前**
- [ ] 需求里有没有知名 IP 角色、商标、Logo？有就先改成原创角色，并在回复里说明一次。
- [ ] `python3 -c "import cairo, numpy, scipy"`，缺什么装什么（`--break-system-packages`）。

- [ ] 定好逻辑分辨率（1280×720）和输出倍率，定好帧率、总帧数（30 fps × 30 s = 900）。

- [ ] 所有随机都用 `hsh(i,k)`，不用 `random`，也不保存帧间状态。
- [ ] 所有来自缓动函数的 `scale` 都要防 0（`if s <= 0.01: return`）。

- [ ] 每写完 2～3 个场景就抽帧拼图看一次，重点看：遮挡（字挡脸、尾巴挡脸）、出画、切场前后位置是否连贯。

**导出前**
- [ ] 每个场景的起点/终点、每个 `pop_scale` 的 t0 都单独渲染一帧，确认不崩。
- [ ] 音频长度 = 视频长度（这次两者都是 30.000 s），音频按秒检查 RMS 和峰值。
- [ ] 音效时间常量和画面常量一致（最好共用同一份常量，这次是手动对齐的）。
- [ ] 输出路径要可写，中文文件名要能正常生成。

**交付前**
- [ ] `ffprobe` 检查时长、分辨率、帧率、编码、有没有音轨。
- [ ] 从成片 MP4 里（不是从渲染函数）抽帧拼图，确认编码后的画面正常。
- [ ] 体积是否符合分享渠道的限制；需要的话再压一版。
- [ ] 如果用脚本或 `cp` 把文件放进输出目录，要额外调用 `SendUserFile` 才能交付。
- [ ] ⚠️ 这次没做：没有在播放器里连续观看，也没有真实试听。下次如果条件允许，至少用 ffmpeg 导出一段 GIF/低清预览看运动节奏，并检查音频频谱。
